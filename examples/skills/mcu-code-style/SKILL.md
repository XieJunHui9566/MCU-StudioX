# MCU C/C++ 代码风格与正确性

适用于固件源码的编写、修改和审查。先确认工程所用语言标准、芯片、框架和现有约定，再提出最小范围的改动。此技能不提供硬件操作授权。

## 先读工程

1. 用 `project_info`、`project_list_files` 和 `project_read_file` 查看工程配置、相邻实现及相关头文件；用 `project_search` 查找同类代码。已有构建诊断可用 `project_build_log` 阅读。
2. 优先遵守工程现有的缩进、命名、头文件组织、错误处理和 HAL/LL/SPL/裸寄存器分层。不要为了统一风格批量改写无关文件。
3. 把厂商 SDK、生成代码和用户维护代码区分开。除非任务明确要求，修改用户维护的适配层，不直接改厂商或生成文件。
4. 芯片型号、时钟、引脚复用、Flash/RAM 容量、寄存器和外设实例必须来自已核验的器件包或数据手册。缺少依据时标出待确认项，不填入猜测值。

## 写法

- 名字表达物理含义和单位，例如 `timeout_ms`、`adc_raw`；相邻代码已有命名规则时保持一致。常量、位掩码和枚举优先于裸数字。
- 缩小变量作用域；清楚区分输入、输出与所有权。公共 API 在头文件说明前置条件、单位、返回值和失败情况。
- 位运算使用合适宽度的无符号类型和显式掩码；检查移位范围、整数提升、溢出及有符号/无符号比较。内存映射寄存器使用芯片 SDK 定义或经核对的地址与位定义。
- 数组、缓冲区和 DMA 长度先检查边界；乘法计算长度时先防溢出。避免无界复制、递归和隐含的大栈对象；遵守工程对动态内存的约束。
- 错误路径保留原始状态和诊断，不静默忽略返回值。清理资源与恢复外设状态应覆盖部分初始化失败。
- 注释解释时序、硬件限制和非直观约束，避免复述代码。修改接口时同步更新调用点及必要文档。

## 中断与并发

- ISR 尽量短且有界；不在中断中阻塞、等待锁、执行无界循环或调用不确定是否可在 ISR 使用的 API。
- 明确哪些数据由 ISR、主循环、DMA 或多核共享。`volatile` 只约束访问优化，不能代替原子操作、临界区或内存顺序保证；按平台和现有框架选择同步方式。
- 共享缓冲区要定义生产者、消费者、容量、读写索引与溢出行为。更新多字段状态时避免读到半更新快照。
- 外设状态机和轮询均设置可观察的超时与错误退出；基于循环计数的延时不能冒充实际时间。使用会回绕的 tick 时采用安全的差值比较，并核对计数位宽。
- 对时钟切换、引脚复用、DMA、缓存一致性和清除中断标志的顺序，依据目标芯片资料及现有驱动约定检查；不要套用其他系列的寄存器值。

## 交付检查

改动前后用 `git_diff` 核对范围，保留用户已有修改。总结实际修改、静态检查结果、尚未验证的硬件假设。编译、连接、下载、擦除、调试和串口发送均依赖当前任务的授权与现有工具权限；此技能本身不触发这些操作，也不放宽权限。
