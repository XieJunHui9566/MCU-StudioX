# StudioX RT51 0.1.0

自研的静态抢占式 8051 RTOS。首个工程模板面向 IAP15F2K61S2 / SDCC 4.5.0 #15242。
内核使用真实的任务执行上下文和独立任务栈；任务可以在普通 C 函数中阻塞后继续执行。
它目前是开发版：基础内核已完成 8052 指令仿真，以及当前 IAP15F2K61S2 / CH340C 板的
抢占、通信、优先级继承、重入算术、tick 回绕和栈水位实机检查。该记录对应 0.1.4
器件包归档及记录中锁定的固件，见 `RT51-HARDWARE-20261012.md`。
0.1.5 模板新增的周期延时、挂起/恢复、软件定时器和统计已随后用新验收固件完成
同一块板的 60 秒运行及断电后 30 秒运行检查，181 帧报告全部通过。
详见仓库 `docs/RT51-EXTENSIONS-HARDWARE-20261012.md`，离线边界另见
`RT51-EXTENSIONS-20261012.md`；结论不扩展到其他型号或任意任务负载。

## 最小接入

工程全部 C 源码必须使用 `-mmcs51 --model-large --stack-auto --int-long-reent --float-reent`。
链接需要 `--iram-size 256 --idata-loc 48 --stack-size 128 --xram-loc 1 --xram-size 1023`，并确认 `.mem` 显示
`Stack starts at: 0x80`。不能混入默认静态局部变量 ABI 的旧目标文件/库。

IAP15/STC15 工程还必须链接 `examples/iap15/stc15_xinit_sdcc.c` 板级启动适配，
它用单 DPTR 复制完整 16 位 XRAM 初值地址。该芯片片内 RAM 的 `MOVX @Ri` 只能
访问低 256 字节，SDCC 默认通过 P2 分页的 XINIT 副本不能用于超过 0x00FF 的初值；
可能同时把初值写到低地址的其他对象。此约束属于 C 启动层，与 RTOS 的任务创建无关。
不要用 main 中逐个重设变量来代替修正启动代码；其他 51 型号须核对自己的 RAM 访问规则。
`tools/Test-Rt51Startup.ps1` 验证空块、单字节、256 字节和跨页初始化。

```c
#include "rt51.h"
#include "stc15.h"

static __xdata uint8_t task_id;
static volatile __xdata uint16_t counter;

static void init_my_timer(void)
{
    /* 用户按实际时钟配置定时器、清中断标志并使能该中断；保持 EA=0。 */
}
static void acknowledge_my_tick(void)
{
    /* 如硬件不会自动清中断标志，在这里清标志/重装。自动清标志时可以传 0。 */
}

/* 由用户选定向量。在 main.c 展开一次；不能由两个 ISR 共同调用抢占入口。 */
RT51_TICK_ISR(my_tick_interrupt, 1)

static void worker(void)
{
    for (;;) {
        ++counter;
        rt51_delay(100);
    }
}
void main(void)
{
    rt51_init();
    if (rt51_task_create(worker, 2, &task_id) == RT51_OK)
        rt51_start(init_my_timer, acknowledge_my_tick);
    /* 裸机 main 没有可返回的调用者；初始化失败时停住并保留状态。 */
    EA=0;
    for (;;) { }
}
```

以上初始化回调是接口示意，不包含可直接运行的定时器配置。可运行 IAP15 示例在
`examples/iap15/main.c`，Timer0 的约 1ms 配置由应用提供，频率来自工程的
`STUDIOX_CLOCK_HZ`。内核只累计 tick：用户提供 1ms 周期时，100 tick 才等于 100ms。
示例取最接近的整数计数，12MHz 时准确为 1ms，其他频率按计数/时钟得到实际周期。
切换定时器时，同时修改应用初始化/清标志回调和 `RT51_TICK_ISR` 的向量。
重复调用/空初始化回调返回 `RT51_INVALID`；成功启动不返回。

## 已实现

- 固定任务槽、静态分配，默认 3 个用户任务和 1 个空闲任务。
- 数值小的优先级先执行；同优先级在 tick 和 yield 时轮转。
- 保留 PC、IE、ACC、B、DPTR、PSW、R0–R7、SDCC `_bp` 与自动 bit 寄存器。
- `rt51_delay()`、16 位 tick 原子读取、任务自然返回和空闲任务。
- 固定周期延时、任务挂起/恢复，取消等待的明确返回状态。
- 静态软件定时器，任务处理回调，积压/溢出可观察，不额外创建服务任务。
- 原子任务/内核快照，可裁剪的 tick 采样和切换计数。
- 任务事件：8 位标志、ANY/ALL、自动消费匹配位、超时和无限等待。
- 计数信号量，按等待者优先级直接移交许可，计数上限可观察。
- 非递归互斥锁、嵌套优先级继承、锁依赖环检测、超时撤销继承。
- 静态按值消息队列、阻塞发送/接收、有限超时；单条最多 16 字节。
- 事件、信号量、队列发送的 FromISR 入口。
- 保存上下文时检查任务栈范围/寄存器 bank，内核工作栈哨兵和水位，错误码保留。

等待超时以剩余 tick 倒计数实现，不受 `rt51_tick_count` 的 16 位回绕影响。
`RT51_FOREVER` 为 65535，有限等待最大 65534；`rt51_delay(65535)` 返回
`RT51_CONTEXT`。`delay(0)` 让出 CPU，运行更高优先级纯计算任务会使低优先级任务饥饿。

## 内存与 ABI 边界

默认每个任务保存栈为 96 字节，包含最少 18 字节的返回地址/寄存器帧以及应用、
库函数、内核 API 的调用帧。96 字节不能全部用作局部变量。建议大缓冲区显式放在 XRAM，
避免递归、深层调用、格式化输出和大的栈局部数组。

IRAM 的 `30..7F` 是内核 80 字节工作栈，`80..FF` 是当前任务使用的硬件栈；
任务暂停时把已用部分复制到各自的 XRAM 保存区。所有调度代码在 EA=0 下有界执行。
不能新增 `__idata` 全局对象或修改链接布局；外设 ISR 必须保留编译器规定的寄存器，
并计入任务栈预算。任务和 tick 入口仅支持 register bank 0。
这是针对具备 256 字节 IRAM 和足够 XRAM 的增强型 8051/8052 的端口，
不宣称兼容只有 128 字节内部 RAM 的原始 8051。

STC 模板保留 XRAM 地址 0 作为 NULL，限制用户对象到 `0001..03FF`（1023 字节），CODE 到 `0000..DBFC`，
为 Mon51 的 `0400..06FF`、`DC00..F3FF` 和 `DBFD..DBFF` 跳板留空间。
内核和示例不写 P3.0/P3.1，不自动修改 MCU 时钟，不使用睡眠/看门狗。
使用仿真芯片时仍须遵守监控程序的引脚、时钟及中断限制。

## 并发规则

1. 任务、信号量、互斥锁和队列在 `rt51_start()` 前创建/初始化，不支持运行中重建对象。
2. 从任务上下文、EA=1 调用阻塞 API。FromISR 入口只做有界操作，不阻塞、不直接调度；
   唤醒任务在下一 tick 执行。普通外设 ISR 只能用 FromISR API，不能调用 yield/阻塞 API。
3. `RT51_TICK_ISR` 是保存上下文的 naked 跳转，不能替换成在普通 C ISR 内调用
   `rt51_port_tick()`；普通 ISR 序言会改变待保存的栈和寄存器。不要在该跳转前写 C 代码。
4. tick 清标志回调在已保存上下文、独立工作栈、EA=0 下运行，应短小，不调用阻塞 API，
   不打开 EA。不能由多个中断源并发提供抢占 tick。
5. 队列对象、存储区、发送/接收缓冲区必须显式位于 XRAM，并在阻塞期间保持有效。
   阻塞发送时其他任务不能改写该消息；用互斥锁或独立缓冲区确保所有权。
6. 共享 16 位/32 位变量不是原子操作。用 `rt51_critical_enter()`/`exit()` 成对保护；
   传给 exit 的是原 EA 状态。临界区内不能 yield/阻塞，不得长时间禁止中断。
7. 互斥锁不递归。任务持锁返回触发 `RT51_FAULT_LOCK_HELD`，避免静默遗留锁。
   传入对象必须先初始化；同优先级对象等待者按任务槽次序选择。

## 调试和故障

可在 IDE 的变量观察中查看 `rt51_tick_count`、`rt51_switch_count`、`rt51_current`、
`rt51_fault`、`rt51_kernel_stack_peak`、`rt51_tasks` 和示例的 producer/consumer 计数。
这是普通 CDB 变量支持；目前没有 RT51 专用的线程窗口，也没有暂停非当前任务的单步入口。
Mon51 暂停会停止用户运行/时间基准，恢复后继续调度，tick 不补偿调试暂停的墙钟时间。

`rt51_fault`：0=无故障，1=上下文栈越界，2=非 bank0，3=内核工作栈/回调约束错误，
4=持锁任务返回，5=软件定时器回调返回时 EA=0。致命错误关中断并停留，保留现场。
水位与检查是有限的检测措施；
8051 没有内存保护，不能保证任意栈越界都在写坏其他内存前被拦截。
`stack_peak` 是保存上下文时观察到的最大栈字节数，包含保存帧；不是任意指令点的完整栈水位。
`rt51_kernel_stack_peak` 由填充值扫描得到，仍可能受碰巧写入相同填充值影响。

## 周期、挂起和静态定时器

`rt51_delay_until(&anchor, period)` 的 anchor 放 XRAM 并由单一任务持有，初值取
`rt51_ticks()`。每次推进一个 period，因此不叠加任务执行耗时。周期限 1..32767 tick；
锚点与当前时间不能脱离半个 16 位周期以上。逾期返回 TIMEOUT，不阻塞，保留推进后的
锚点；应用选择追赶、跳过或重置锚点。参数错误不修改锚点，到期时刻相等返回 OK。

`rt51_task_suspend(id)` 将任务移出调度，取消尚未完成的睡眠、事件、信号量、队列或锁
等待；resume 后原阻塞 API 返回 ABORTED。队列取消不会迟到发送/消费；已经领取资源并
变为 READY 的任务保留成功结果。事件在挂起期间仍可累积，恢复后重新 wait 消费。
挂起锁等待者撤销优先级继承；持锁者返回 OWNER，正在 dispatch 的任务返回 BUSY。
重复挂起/恢复返回 BUSY；空闲/未创建/结束任务返回 INVALID。可挂起自身，suspend 在
被恢复后返回 OK；恢复不重建任务或重启入口，已推进的周期锚点也不回滚。

`rt51_timer_init()` 在启动前注册 XRAM 对象，初始停止；`rt51_timer_start(timer, delay)`
在启动前或任务设置首次到期时间。period/delay 限 1..65534 tick，repeat 为 0/1。
对象与 context 的整个运行期必须有效，不能运行中删除/重建。用户选一个任务调用
`rt51_timer_dispatch()`，每次每对象最多处理一次到期，在调用任务、EA=1 下执行回调。
tick ISR 只递减有限注册表并累计到期；回调时刻还取决于服务任务优先级及调用间隔。
不额外创建服务任务，不保证回调恰好在到期 tick 执行。

重复周期按实际到期 tick 推进，不按回调返回时刻推进。pending 饱和于 255，多出的
到期计入饱和于 65535 的 overruns；派发逐次补处理积压，不无界执行全部回调。
start/stop 清除未派发到期、保留累计 overruns，不能中断已开始的回调。回调可重启/停止
自己或其他定时器；嵌套/并发 dispatch 返回 BUSY。回调的任务等待/控制 API 返回 CONTEXT；
可使用非阻塞 FromISR 发送入口和查询 API，不修改 EA；返回时 EA=0 则保留故障 5 停住。

模板每 100 tick 派发，1000 tick 的周期定时器更新 `timer_heartbeat`；`period_misses`
记录周期逾期。时间基准仍由用户初始化回调决定，内核不选择外设、时钟或引脚。

## 快照和裁剪

`rt51_task_get_info()` 原子查询状态、原始/有效优先级、最近保存栈长度、观测峰值、
剩余等待、持锁数和统计，支持已结束任务；`rt51_kernel_get_info()` 查询 tick、切换数、
当前任务、故障和内核水位；`rt51_timer_get_info()` 查询剩余到期、待处理次数和溢出。
输出都放 XRAM，多字段在短临界区读取。`tick_samples` 只记录 tick 到达时的当前任务，
`dispatch_count` 记录切换进入次数，都是 16 位回绕计数，不是精确 CPU 用时。

`RT51_MAX_TIMERS=0` 裁掉定时器模块及 API；`RT51_ENABLE_STATS=0` 移除任务统计字段，
快照计数返回 0。所有源码须使用同一配置并完整重编，禁止混用不同 TCB 布局的目标文件。
默认 4 个任务槽的统计额外占 16 B XRAM；4 个定时器的指针表/派发状态占 10 B，
每个应用注册对象另占 13 B。当前示例完整配置 9647 B CODE / 532 B XRAM，含一个定时器。
关闭定时器和统计后，同一示例为 7729 B CODE / 493 B XRAM，仍有周期延时和任务控制。

## 验证

运行 `tools/Test-Rt51.ps1`，使用本项目管理的 SDCC 和 s51/uCsim，执行真实编译的
8052 固件。覆盖抢占、ABI 上下文、阻塞、回绕、事件/信号量/队列、嵌套锁与故障路径。
模拟器的标准 12T 8052 外设与 STC15 的 1T 外设分开验证；离线结果不等于实板验收。
`tools/StudioX.Rt51Validation` 检查包导入、模板生成和实际 SDCC 工程构建。

当前不提供动态创建/删除、动态内存、任务优先级修改、流/消息缓冲、低功耗适配、
Keil C51 端口、FreeRTOS API 兼容层或其他系列的预验证端口。
