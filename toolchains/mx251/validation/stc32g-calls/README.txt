MX251 V0.0113：原有多文件调用应用的双 ABI 实板验收

来源与作用
这是 R84 已有的 22 函数应用及原始 128 对输入，不是为新优化另造的语料。
mixed/ 保留普通 reentrant ABI 与两个显式原生接口；native/ 的 OLD 接口也使用
__reentrant __sdcccall(4)。函数体只加 m_/n_ 符号前缀，逻辑、类型、输入和预期不变。
两套模块共处同一固件，共用驱动、启动、时钟和 USB；接口声明在各翻译单元一致。
这验证已存在的显式 ABI 能力，不启用全局默认 ABI，也不代表新分配算法已经实现。

构建
仍使用统一 validation/RunAcceptance.py，profile 为锁定的 STC32G 开发配置。
CMakeLists.txt 管理源码；Ninja 调用 MX251。mx251.json 只选目标/模型/后端/运行库。
main.c 与 usb_poll.c 用旧发射路径，四个应用翻译单元用 ordinary-wide；显式 ABI 开启。
small 的 CALL_MODEL=0，large 的 CALL_MODEL=1；此宏只给 USB 结果标记模型。
仓库入口重建 HEX 必须与已验证镜像相同，不能将模型标记与真正 --model 选项混同。

检查范围
每种模型：128 输入 × 10 个顶层操作 × 两 ABI = 2560 项结果；每操作三组计时。
Timer0 中断调用两 ABI 的全部 10 个顶层操作，检查与前台重叠执行时的保存/恢复。
覆盖有限深度递归（0..3）、混合宽度参数、栈对象取址/别名、volatile 帧、调用链、
寄存器压力和 float 位传递。c_callback 是直接回调链，不是函数指针或间接调用验收。
float 只传递位值，不是浮点算术；保留 NaN 等原始输入，不把通过表述为 IEEE754 认证。
oracle.json 来自原冻结参考；V0.0113 又用独立 Python 公式及 GCC -O0/-O2 核对。

计时口径
STC32G12K128 当前样品保留 IRC 11059200 Hz 配置，WTST/CKCON=0。
Timer0 /12、预分频0，IRQ关闭，每样本64次调用，包含循环、参数装载、调用和返回；
打包结果在停表之后。原计时输入不变，递归计时深度为0，不能据此声称深递归加速。
同镜像比较可隔离模型/时钟差异，但会包含调用方按不同 ABI 装载参数的成本。

USB 回传
65 字节 HID report：第0字节报告ID0，后面64字节以 MXC1 开头。
载荷4..5序号，6..7索引，8..47十个小端u32；48..49中断计数，50中断失败位，
51..52初始化位掩码（期望255），53 USB错误，54协议阶段1，55模型标记，
56..59身份27103213，63为载荷0..62异或校验。
索引0..127普通/混合ABI，128..255原生ABI；256..315计时（两ABI×十操作×三样本）。
计时十值依次：结果、ticks、overflow、重复64、操作号、样本号、ABI号、0、0、0。
采集脚本保留原始报文；完整下载ACK与运行结果分别审核，未做 Flash 回读。

边界
只对指定 STC32G 样品、small/large stack-auto 和这个原有应用取得运行证据。
不覆盖函数指针、可变参数、所有指针空间、全部嵌套中断、任意第三方预编译库。
普通 ABI 库不能只修改头文件就当作原生 ABI 库使用；声明与定义必须一起重编。
不修改 IDE 安装版，不把此项目的体积/速度百分比推广到所有工程。
