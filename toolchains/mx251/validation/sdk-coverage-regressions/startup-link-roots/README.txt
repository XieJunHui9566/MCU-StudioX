永久负例：不能删除编译器用来强制抽取启动库的纯 .globl 声明
================================================================

2026-10-31 的 35f967d3 引擎清理了看似没有代码引用的三个声明：
__mcs51_genRAMCLEAR、__mcs51_genXINIT、__mcs51_genXRAMCLEAR。
这导致 crtclear.rel、crtxinit.rel、crtxclear.rel 不被抽取。
其最终机器字节仍能从 REL 正确重建，但初始化／清零契约已经被破坏。
该 120 B “收益”必须拒绝，不能算性能优化。

edf51664 收敛到仅清理已证明删除的函数定义对应声明；未知外部纯声明
全部保留。这里没有把启动函数名白名单写入生产 GC 算法。

资产包含两个目标配置各 5 份最小镜像：同源父版、35f 拒绝方案、edf
安全方案，以及包含非零 XDATA、DATA/XDATA BSS、CODE 复制源的初始化
夹具 OFF/ON。只有实际输入 ASM/REL/MAP/HEX 和被选择的库成员 REL，
不需要原 compiler、SDK 或 .artifacts 大树。manifest 保存每个资产的
原来源与 SHA-256；original 字段仅作来源记录，重放不读取该绝对路径。

重放方法（无编译、无下载）：
  python -B replay.py --output <新的证据目录>

输出目录必须在此永久包之外。脚本拒绝覆盖旧运行；十份镜像全部做
实际重定位和机器字节重建，再独立检查启动依赖。正确结果是两份 35f
被拒绝，其余八份通过，并且初始化父／候选的 CRT 成员内容、XINIT／
CONST 原值、对象分配地址一致。结果中的 PASS 指回归判据正确，绝不
表示 35f 是可用候选。

relocation.py 来源于本轮冻结的 LinkProofMath.py；仅将 archive reader
导入替换为拒绝桩，因为已按原顺序抽出真正选中的 REL。所有重定位
算术保持原样。未知模式失败，不猜测。编译器／引擎的来源记录保留在
manifest 的 sourceResult 中，但不作为运行时依赖。

这是离线结构和机器字节证据，不证明实际上电值、外设、中断或周期。
真实初始化执行仍需当前完整工程与实板验证；不能以本包替代。
