MCU StudioX {{VERSION}} · 使用与升级说明

1. 安装
运行 MCU-StudioX-{{VERSION}}-win-x64-Setup.exe，按中文向导完成安装。
支持 Windows 10/11 x64，已包含所需 .NET 运行时，不依赖 VS Code。
完整安装包附带全部当前开发工具链。文件名含 Light-Setup 的轻量安装包保留相同器件包、插件和 IDE 功能，不附带工具链。
轻量版创建工程后，从“工具 → 准备工程工具”导入所需版本的 .mcutoolchain；完整包也支持同一导入入口。
烧录器的 USB 驱动使用对应设备厂商提供的驱动。

2. 器件包位置
开始菜单 → MCU StudioX → 器件包。
或进入 IDE 安装目录中的 device-packs 文件夹。
STMicroelectronics 下是按 STM32F100、F103、F407 等子系列分别封装的包；AGM 下是 AG32 临时包。
在 IDE 中点击“导入器件包”，选择 .mcupack。导入后新建工程，依次选择厂商、包、芯片和模板。
CubeMX CMake 工程也可直接从文件菜单导入，无需先安装 STM32 器件包。

3. 编译和下载
F7 编译工程。STM32F1/F4 可在顶部选择 ST-Link、DAP-Link 或 J-Link，齿轮可设置速度和序列号。
点击“下载”将自动保存、编译、烧录、校验并复位运行，下载会替换板上的应用固件。
STM32 调试界面支持断点、条件/日志/临时断点、单步、调用栈、变量、寄存器和反汇编查看。
实板验证范围取决于具体器件、探针和固件组合。软件支持与编译通过不代表所有组合均已完成实板验收；本次发布不连接或烧录硬件，已验证范围与限制见 README 和本版本更新说明。
AG32 临时包附带官方 AGM BLASTER 配置；具体下载与调试流程见 IDE 离线帮助。连接失败时保留工具日志，不自动擦除、解锁或修改选项字节。

4. 升级和修复
保存文件并关闭所有 MCU StudioX 窗口，运行新版安装包，在原目录覆盖安装即可。
安装包识别旧版本并保留个人数据；同版本可以覆盖修复，不支持直接降级。
完整包和轻量包可在原目录互换。已有开发组件整目录保留，不拼接不同来源的同版本文件，不自动迁移工程锁。
程序文件修复与组件修复分开；损坏的组件从 IDE 内“工具校验与修复”恢复。
当前为手动下载安装包升级，不包含联网自动更新服务。
迁移程序安装位置时先卸载再安装到新目录，工程和个人设置仍保留。

5. 个人数据与卸载
个人设置和已导入包：%LOCALAPPDATA%\MCUStudioX
工程文件：你创建或导入时选择的工程目录。
通过 Windows“已安装的应用”或开始菜单卸载，只删除安装器管理的程序文件，不删除上述数据。
runtime/toolsets 下的独立开发组件及旧辅助开发工具也会保留；需要清理时先在 IDE 工具管理中核对工程依赖。
自定义插件、主题和工程请放在用户目录，不要覆盖程序自带文件。

6. 第三方组件
组件版权、许可证和来源信息随附在 runtime、licenses 和各器件包中，归各自权利人所有。
安装包未进行代码签名，发布者字段不能代替有效数字签名。

7. Git 与工程终端
新建工程会在工程目录自动初始化 Git（main 分支），构建产物默认忽略。
从“工具 → 工程终端”或 Ctrl+反引号打开；默认目录是当前工程，Git 已内置，无需单独安装。
首次提交前设置自己的 user.name 和 user.email，再执行 git add、git commit；配置远程仓库后可执行 git pull、git push。
终端采用 CMD 命令语法，支持持续会话、上下键历史、Ctrl+C 中断、滚轮浏览和 Ctrl+滚轮字号。
提交前请先保存编辑器文件。磁盘上的文件修改会同步到编辑区；已有未保存内容时保留缓冲区并提示处理冲突。
完整示例与说明见 docs/GIT-TERMINAL.md。

8. 串口工具
串口终端支持 HEX、UTF-8、GB2312、ANSI 彩色显示、可配置串口参数和流控、收发与日志导出。
协议解析支持 Modbus RTU 和用户脚本，示例位于 examples/protocols。
串口绘图使用独立入口，支持自定义数据分隔符、多通道曲线、时间和值坐标缩放。
具体操作见 docs/SERIAL_TERMINAL.md、docs/SERIAL-PROTOCOLS.md 和 docs/SERIAL-PLOT.md。

9. AI 助手与 MCP
在工具菜单配置 API，密钥保存在当前用户凭据中。
内置 Agent 和外部 StudioX.Cli mcp 共用工程、编译、Git、下载、调试、串口、网络和 PDF 工具；变更及硬件连接需要相应授权。
支持项目历史会话、运行中追加提示、实时工具活动、API 实际缓存用量和按需加载 MCU Skill。

10. FreeRTOS 调试
暂停目标后在调试窗口的 RTOS 页读取任务、调度器、可用堆统计与队列/同步对象；反汇编页查看机器指令和当前 PC。
读取使用 ELF 调试信息及目标内存，不调用目标端内核函数；缺失字段显示不可用，不伪造任务或 CPU 百分比。
内置 Agent 可通过 debug_rtos_snapshot 和 debug_disassemble 读取同一会话，调试本身不会隐式下载固件。
STM32F407 / ST-Link 与 CH32V307VCT6 / WCH-LinkE 的已验证范围见 docs；其他内核版本、型号及同步对象争用仍需单独验证。

11. 第一个工程完整引导
从欢迎页“第一个工程引导”或“帮助 → 第一个工程完整引导”打开七步引导。
明确选择器件和模板后，依次创建工程、检查健康、编辑保存、首次编译、查看产物和准备运行调试。
步骤依据当前工程的真实结果；源码修改、编译失败或关闭工程会撤销相关成功标记。
按 F1 打开离线帮助，37 篇主题支持正文搜索、分类、快捷键速查和错误关键词查找。

12. 调试、故障与构建比较
调试连接向导显示实际阶段，普通附加不下载固件；复位连接需明确选择且满足接线和配置要求。
“调试 → 固件故障分析”可读取已暂停现场，分析 ESP Panic/Backtrace，并导入明确文件的 ESP Core Dump。
“工具 → 构建历史与对比”保留最近 20 次成功构建，比较静态存储占用、符号、文件和 Ninja 步骤耗时。
源码或 ELF 已改变时拒绝沿用旧结果；运行期堆栈峰值和实板匹配仍需对应证据。

13. 软件、插件与工程组件
从“工具 → 软件与组件分发”读取本地或 HTTPS 目录，核对来源、许可证、精确版本、哈希和磁盘预估。
runtime/distribution/catalog.json 提供离线示例；读取目录不会自动安装或信任插件。
安装新工具版本不改已有工程锁定；插件更新或回退后需重新审阅能力并启用。
源码组件写入工程独立版本目录和锁定文件，支持明确更新与回退。ESP-IDF 最小构建还需核对生成组件的 REQUIRES。
程序员助手插件单独提供 .studioxplugin 文件，从插件管理导入并明确启用；安装包不自动安装用户插件。
