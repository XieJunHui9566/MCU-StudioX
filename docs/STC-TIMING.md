# 51 延时与波特率生成

入口：**工具 → 工程与构建 → 51 延时与波特率…**。源码右键菜单和命令面板提供同一入口。当前适配 `stc.stc8` 包内明确核对的 24 个 STC89 / STC12 / STC15 / STC8G / STC8H 型号，使用工程锁定的 SDCC 头文件；不把规则套用到未登记的 8051 或 C251 型号。

## 工程参数

读取工程 Manifest、包内准确器件/模板身份、寄存器声明及地址、已保存的 `.studiox/stc-isp.json` 时钟和 `.studiox/build.json` Mon51 预设。工程有频率时优先采用并禁止在窗口覆盖；未指定时要求明确填写系统时钟。频率必须是运行时系统分频后的值，生成函数不切换系统时钟。如果工程填写的是 RC/晶振原始频率且用户源码还配置了系统分频，须先使工程的编译时钟与实际计时系统时钟一致，或保留 ISP 时钟并使用明确的生成参考值。

“保存生成参数”只保存 `.studiox/stc-timing.json`，包括手动参考 Hz、定时器分频、固定延时 µs、延时定时器、用户波特率、发生器和引脚选择；不改变 ISP、构建参数或硬件。函数名现场填写，以 `sx_` 开头，避免与 C 关键字和 SFR 冲突。窗口不会把 ISP 传输波特率当作用户 UART 波特率。

支持现代 STC 的定时器 1T / 12T，以及 STC89C52RC 的 6T / 12T；STC89 的选择必须与实际 ISP 硬件选项一致，生成代码不修改 CPU 模式。6T 参考频率限制为 ≤24 MHz。未指定频率不猜测 12 MHz。

## 固定延时

选择 Timer 0 / Timer 1 和 1–10,000,000 µs 固定延时，生成返回状态的函数。采用 16 位模式 1，按最接近的整数计数计算，超出一个周期时拆成 65,536 计数的整周期和余数。窗口显示名义计数时间、量化误差和重装值相关信息。

函数只可由主循环调用且不可重入。定时器运行中、其中断/时钟输出已开启或模式 3 共享控制位时返回 `0`；成功返回 `1`。只修改自己的 TMOD/AUXR 位，在短临界区保存/恢复原 EA、模式、TH/TL、标志和时钟位；等待期间保留原全局中断状态。其它代码/ISR 不得在函数等待中重配该资源。必须检查返回值，否则资源冲突时没有执行延时。

这是定时器轮询的阻塞延时，不是经过编译器校准的空循环。实际耗时还包括函数调用、寄存器访问、轮询、分段重装及中断耗时；不保证精确短脉冲，也不生成软件循环后宣称不受优化影响。调度器或 UART 已占用的定时器需选择其它资源。

## UART1 初始化

生成 8N1 UART1 初始化函数，不发送数据，不开启全局/串口中断。Timer 1 使用 8 位自动重装（模式 2），同时比较 SMOD=0/1 的候选；STC15 / STC8G / STC8H 还可选 Timer 2 的 16 位自动重装。两个相邻计数候选按真实速率误差比较，不只对理想除数四舍五入。

显示目标/实际波特率、百分比误差、发生器、计时分频、重装值及引脚；名义误差超过 2% 时保留计算预览并阻止复制/插入。该预算不包含 RC/晶振误差，不保证链路一定可用。STC89/STC12 的低分辨率 Timer 1 无法实现某些高波特率时，调整时钟、分频或目标速率，而不是生成错误常数。

STC15 / STC8G / STC8H 可选择 P3.0/P3.1、P3.6/P3.7 或 P1.6/P1.7，保留 P_SW1 其它位，并只配置所选 RX 为输入、TX 为推挽。可用引脚还取决于封装、板级接线及其它外设；型号名称不证明板上已引出。旧型号只生成默认引脚。初始化前应结束原 UART1 传输，发生器运行中或中断/时钟输出已启用时返回 `0`，不能用本函数抢占正在使用的资源。

Mon51 工程禁止生成可插入的默认 P3.0/P3.1 UART 代码，需切换用户串口。普通预设的默认引脚代码也附带 `STUDIOX_MON51_DEBUG` 编译门禁，后续改为调试构建时会报错。

## 插入与配置变化

预览核对后可复制，或插入当前可编辑 C 文件顶部。插入只修改未保存缓冲区，保留换行并支持整段 Ctrl+Z/重做，不改 main、不自动调用函数。重复函数/辅助函数名拒绝插入。插入和保存前重新核对工程、头文件、时钟、监控和生成参数；过期窗口、只读文件、后续编辑或调试会话阻止修改。

生成代码附带准确器件/系列宏门禁；定义了 `STUDIOX_CLOCK_HZ` 时必须与生成频率一致，否则编译报错并要求重新生成。手动参考频率的普通工程未定义时钟宏时，已有源码仍是当时生成的固定频率，需要主动更新；保存生成参数不会重写此前插入的源码。原始计算、读取和编辑异常保留到 IDE 日志。

## 资料与验证

计时模式、UART 时钟和引脚切换依据厂商资料及包内寄存器事实：[STC89](https://www.stcmicro.com/datasheet/STC89C51RC-en.pdf)、[STC12C5A60S2](https://stcmicro.com/datasheet/STC12C5A32S2-en.pdf)、[STC15](https://www.stcmicro.com/datasheet/STC15F2K60S2-en.pdf)、[STC8G](https://www.stcmicro.com/datasheet/STC8G-cn.pdf)、[STC8H](https://www.stcmicro.com/datasheet/STC8H-en.pdf)。厂商原示例没有复制进产品，生成代码由 C# 应用服务构造。

基础构建使用 `tools/Build.ps1`。`StudioX.StcTimingValidation <新输出目录> <STC8.mcupack> <已有 tool-runtime>` 检查计算边界、型号/配置变化、资源冲突门禁和 24 个准确型号的实际 SDCC 编译。Desktop `--preview-stc-timing <新输出目录> <隔离 IAP15 工程>` 检查两套主题、Mon51/误差/输入提示、插入撤销及过期/只读保护。均不连接、烧录或运行 MCU；计算与编译检查不能代替实板时序测量。
