# GitHub 协作

从窗口右上角的 GitHub 账号入口或 **工具 → GitHub 协作** 打开图形界面。左侧保留一个 Git 图谱按钮。此功能使用 IDE 随包 Git 与 Git Credential Manager，面向 GitHub.com。账号密码和 OAuth 令牌不会填入工程文件或远端 URL。

## 开始使用

1. 点击 **登录 GitHub**，在系统浏览器完成授权。IDE 显示本机可用账号；有多个账号时，在顶部选择本次 GitHub HTTPS 同步和 PR 操作使用的账号。SSH 远端仍使用本机 SSH 密钥。
   未登录时，窗口右上角显示“未登录 GitHub”；点击即可进入协作页登录。授权后，这里会显示所选账号的头像和用户名。退出最后一个账号后恢复未登录提示。
2. 输入不含账号密码的 HTTPS 仓库地址，选择新目录并克隆。目录中若有 `.studiox/project.json`，IDE 会打开工程；普通 Git 仓库也可在协作页与 Git 图谱中管理，但不能当作 MCU StudioX 工程构建。已在本机的普通仓库可用 **选择本地仓库** 打开；图谱只会切换到已验证的独立仓库根目录。
3. 对现有工程，可初始化 Git，在“远端仓库”填入 `origin` 及仓库 URL 后保存。抓取地址与推送地址可以分别设置；两者都不能包含账号密码或令牌。先获取远端更新，再检出同事的分支或将当前分支发布到远端。
4. 当前分支设置上游后，可快进拉取和推送；按钮显示具体上游分支。远端与当前上游不一致时，先切换远端或重新设置上游。分支分叉时 IDE 不自动覆盖或强推，可在 Git 图谱中检查提交并手动合并。

## Pull Request

选择 GitHub 远端后，打开 **Pull Requests** 标签。可以按开放/关闭状态查看 PR、文件补丁、检查状态、审阅意见和讨论。点击 **创建 PR** 填标题、源分支、目标分支和说明；fork 的源分支可写成 `owner:branch`。创建前应先将源分支推送到 GitHub。

在 PR 详情中可以发表评论、批准或请求修改。合并前 IDE 显示来源提交 SHA、检查状态和合并方式，并要求确认；GitHub 会再次检查该 SHA、仓库权限及分支保护规则。多人同时更新分支时，刷新详情后再操作。

本机 **退出账号** 只移除 Git Credential Manager 保存的凭据；若要撤销 GitHub 网站上的授权，需要到 GitHub 的授权应用设置中操作。组织仓库可能需要组织 SSO 或管理员批准。账号与安全机制见 [GitHub 账号接入](GITHUB_AUTH.md)。
