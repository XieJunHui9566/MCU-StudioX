# StudioX RT51

51 专用自研 RTOS 的首版为 0.1.0，源码和 API 使用说明见
[firmware/StudioX.Rt51/README.md](../firmware/StudioX.Rt51/README.md)。

时间源由用户提供：`rt51_start(timer_init, tick_ack)` 调用用户的初始化回调，
`RT51_TICK_ISR(name, vector)` 绑定用户所选中断向量；可选的 `tick_ack` 清中断标志/重装。
内核不选择定时器，不猜测 MCU 时钟。普通 C ISR 不能直接调用抢占入口。

当前源码生成的模板是 IAP15F2K61S2 + SDCC：`stc.stc8 / 0.1.5` 中的 `rt51`，
显示为“StudioX RT51 · 静态抢占式 RTOS”，原来的 `bare` 模板保留。
配方为 `tools/New-StcRt51Pack.py`，只从已验证的 0.1.2 包生成新版本，不覆盖旧包。
该包需要含本轮 SDCC 模板参数叠加/内存校验修正的 IDE 构建。
0.1.4 添加单 DPTR 的 STC15 XINIT 启动适配，修复高于 00FF 的 XRAM 初值；
旧 0.1.3 是修复前的离线首版，归档保留，不覆盖。
制作器件包不会自动更新安装版、升级产品版本或发布 GitHub Release。

默认提供 3 个用户任务和空闲任务、抢占/同优先级轮转、延时、事件、信号量、
优先级继承互斥锁及静态消息队列；新增周期延时、挂起/恢复、静态软件定时器和任务快照。
无动态内存。示例由生产者发送消息、消费者接收，
纯计算后台任务用于观察 tick 抢占；变量可通过现有 CDB 观察功能查看。

完整配置示例使用 9,647 字节 Flash、532 字节 XRAM，包含一个软件定时器。
相较归档 0.1.4 示例的 6,456 / 487 字节，增加 3,191 字节 CODE、45 字节 XRAM。
定时器/统计可裁剪，接口语义及约束见源码 README。
关闭定时器/统计的示例为 7,729 字节 Flash、493 字节 XRAM。
硬件任务栈 128 字节、内核工作栈 80 字节，各任务在 XRAM 中保存最多 96 字节上下文。
XRAM 地址 0 保留为 NULL，用户对象限于 0001..03FF；CODE 限于 0000..DBFC，
兼容当前 Mon51 监控区与跳板保留要求。核对实际 `.mem` 和 HEX 才能宣称构建通过。

验证入口：

- `tools/Test-Rt51.ps1`：SDCC 编译 + uCsim 标准 8052 指令仿真，保留固件、映射、
  编译日志、仿真命令与日志。31 组测试覆盖不主动让出的任务、嵌套栈与寄存器、
  32 位重入算术库、tick 回绕、阻塞/超时、事件/信号量/队列、锁继承/依赖环、
  ISR 唤醒、任务返回/空闲回退、周期回绕/逾期、等待取消、定时器积压/回调控制、
  统计快照、错误回调及故障检测。`-Compact` 检查关闭定时器和统计后的配置。
  模拟器填充 0400..06FF 哨兵，逐字节检查完整 768 字节保护区并核对 P3 未变。
- `tools/StudioX.Rt51Validation`：包导入、用户源码复制、构建选项边界、普通与 Mon51
  的实际 SDCC 工程构建；不连接串口。
- `tools/Build.ps1`：完整 IDE 基础编译。

基础版已在当前 IAP15F2K61S2 / CH340C 板完成普通 ISP 写入、连续运行和
断电重启检查，详见 [实板记录](RT51-HARDWARE-20261012.md)，只对应记录中锁定的旧固件。
新增功能随后也在同一块板完成普通 ISP 写入、60 秒运行和断电后 30 秒运行检查，
见 [扩展实板记录](RT51-EXTENSIONS-HARDWARE-20261012.md)：181 个有效报告、16 个应用
检查位全部通过、错误为 0，验收固件为 15,174 B CODE / 713 B XRAM。
离线覆盖范围另见 [扩展记录](RT51-EXTENSIONS-20261012.md)。
Mon51 下运行 RT51 本轮只做构建检查。不宣称其他 51 型号、Keil C51、
任意 128 字节 IRAM 器件或 RT51 专用线程调试窗口已经受支持。
