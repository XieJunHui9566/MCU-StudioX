# STC 串口 ISP 下载

STC 8 位与 32 位工程的下载入口统一迁入下载按钮旁设置打开的独立页面；串口硬件选项、保存语义、各系列覆盖及尚未接入的高级功能见 [STC 下载配置页](STC-DOWNLOAD-SETTINGS.md)。Mon51 未配置端口时也导航到此页，不重载已有编译或串口草稿。

下载串口使用可编辑选择框：选中列表中的 COM 口或手动输入端口，文字应立即显示；刷新串口列表后保留已填端口。通用模板提供 `PART_EditableTextBox`，深浅主题均适用。`MCU StudioX.exe --preview-editable-combos <新输出目录>` 在隔离用户目录检查已保存 COM14、列表选择、手输 COM27、刷新保留和普通波特率框，输出 JSON 和截图；此入口不打开串口、不启动下载。

STC 8 位工程的编译与下载设置分开保存：代码容量/优化档位属于 `.studiox/build.json`，串口、波特率和时钟选择属于 `.studiox/stc-isp.json`。时钟频率以整数 Hz 保存，例如 11.0592 MHz 为 `11059200`，避免小数 kHz 丢失精度。显式时钟频率会在下次编译时定义 `STUDIOX_CLOCK_HZ`；修改时钟后需重新编译。选择外部晶振只写时钟来源配置并把实装晶振频率告知编译器，ISP 不会改变晶振器件的物理频率。

启用准确匹配的图形配置器时，改由工程 `device.mcuconfig` [托管时钟](GRAPHICAL_CONFIGURATION_CLOCK.md)：本页时钟只读，端口与传输波特率仍可调整。ISP 使用分频前源频率，编译与计时计算使用派生系统频率；下载设置不另存一份频率。未保存、校验失败或配置变更后固件过期均会阻止下载准备；停用插件后需显式解除才恢复手动时钟。

下载使用 `stcgal 1.10`（MIT 许可），依赖 Python、pyserial 和 tqdm。发行版的 `runtime/stc-isp` 内置隔离 Python 3.14.7、stcgal 及依赖；来源、版本与逐文件 SHA-256 记录在该目录的 `provenance.json`，许可证保留在 `licenses/`。IDE 先查找用户级配置、发行目录 `runtime/stc-isp/Scripts/stcgal.exe`、再查找 PATH；用户选择外部 `stcgal.exe` 的路径只保存在用户数据目录 `stc-isp-tool.json`，不进入工程或器件包。用户配置失效时会回退到内置或 PATH 中的可用运行时。

下载前 IDE 验证当前开发环境组件、构建凭据、源码快照、Intel HEX 校验和、代码地址上限，然后复制固件快照，在输出栏显示型号、COM 口、SHA-256 和时钟设置。点击下载后直接进入流程，不再弹出下载前确认。`stcgal` 启动后等待芯片上电，用户此时按开发板的电源/下载键；提示保留在输出栏。受控脚本在同一次 ISP 会话中识别芯片完整型号及代码容量，只有匹配才进入擦除与写入；型号不符时不擦写。IAP15F2K61S2 的校验为 `0xF449`/62464 字节代码空间。STC8G1K08/17 的封装后缀和 STC89C52RC/LE52RC 共用识别名采用经过核对的允许列表，其他相近型号不会自动代用。

**写入会覆盖芯片现有程序。** STC 串口 ISP 不提供旧固件读回备份；`stcgal` 会执行擦除、写代码和写选项。工具的写入应答不等于 Flash 读回校验，IDE 只报告工具写入完成，实际运行需在板上观察。下载中断后程序可能不完整。串口监视器必须先释放同一 COM 口。

下载输出使用终端风格的字符进度条，同一写入阶段在原行刷新。已写字节数在每块写入应答核对后更新，分母为实际传输镜像大小（包含协议要求的填充）；等待上电、校准、擦除和结束应答阶段使用活动字符。逐块原始记录仍保存在 `stcgal.log`，警告和错误不被进度刷新覆盖。

Mon51 仿真监控制作复用同一输出路径和配色，不再直接追加原始输出块或显示另一种 tqdm 进度条。F/L 专用监控均在每个 64 字节块应答通过后报告进度，总量为实际编码镜像的 61,440 字节；最后结束应答或选项保存失败时，即使已到 100% 也显示失败。两次重新上电提示的用途与制作后退出规则不变。

工具成功退出并确认完整写入后，输出栏以绿色显示“STC ISP 下载成功”和耗时，不弹出成功提示；状态栏、芯片、串口、固件和下载日志位置仍保留，成功正文注明未执行 Flash 读回校验。写入条达到 100% 不代表整个下载成功；后续应答或选项保存失败时仍显示失败，取消和超时也不会显示成功。

外部晶振模式必须先确认板上确有与设置一致的晶振；赛点资源包的 IAP15F2K61S2 开发板 P1.6/P1.7 未接外部晶振，不能用它验证该模式。`stcgal 1.10` 在芯片当前处于外部时钟时，会把内部 RC 校准初值设为 24 MHz，因此 IDE 拒绝单次从外部时钟切回指定 RC 频率的下载，避免误报成功。需要先用独立的安全恢复流程并冷启动，再重新校准。

2026-10-10 对官方 ISP 成功下载的串口通信进行记录，并在同一块 IAP15F2K61S2 / BSL 7.2.5S / 状态 0x70 / CH340C 上作校准对照。受控脚本现对该精确目标的内部 RC 路径使用官方的首轮 11 点校准请求及 `0x66` 脉冲；普通下载与包内 Mon51 制作共用该适配。其他型号、BSL 和外部时钟路径保持原实现。修正版先通过仅校准测试，再经用户授权完成同一份 271 字节 LED 程序的普通 ISP 下载：擦除、写入、结束及选项保存成功，退出码 0。此项使用实际内嵌脚本，尚未验证安装版界面或重新制作监控，也没有 Flash 读回或运行验收。请求字节、对照结果和原始记录位置见 [校准可靠性验证](STC-ISP-RELIABILITY-20261010.md)。

## 全系列串口下载配置审计（2026-11-01）

本节按用户“串口也要查、范围不限于 STC8、现在先研究”的要求，审查配置解码、写入、容量、时钟和型号覆盖。本轮没有打开串口或 HID、启动监听、擦写芯片、修改生产下载逻辑或替换安装版。以下“复现”均指离线源码或假传输复现，不能作为其他型号的实板资格。

### 已离线复现的缺陷

这里优先级用于后续修复排序，不表示本轮已修复或实板出现相同故障。

| 编号 | 问题及复现 | 影响与修复要求 |
| --- | --- | --- |
| S01 / 高 | `Stc15Option.set_uart_pin_mode("normal")` 实际读回 `push-pull`。`options.py:610` 对非空字符串直接判断真值 | 后期 STC15 UART2 默认管脚模式会设反；应按枚举值编码，覆盖初始位为 0/1 的两种情况。当前 IDE 未暴露该高级字段 |
| S02 / 高 | STC15、STC8 的 `rstout_por_state` getter 返回 `high/low`，setter 使用布尔转换，`high` 被转成 false，结果为 `low` | 读取后原样保存也可能改变配置；须统一字段类型与严格枚举解析。传 `true` 可得到 high，不能因此称显示值往返正确。当前 IDE 未暴露该高级字段 |
| S03 / 高 | `Stc8dProtocol.set_option` 缺少按实际容量检查。以型号库 STC8H1K08 的 12,288 B 总容量输入 split=65,024，得到 EEPROM=-52,736 B；非 IAP 型号前端还会忽略这个 split 计算结果 | 属于底层输入/规划缺陷，不是证明该芯片支持可调分区。应先判断器件能力，再验证各区域、镜像及对齐；不支持的型号拒绝该选项 |
| S04 / 高 | MCS-251 路径把 `split_code` 固定为 65,536 B。STC32G12K128 型号库为 131,072 B、STC32F12K59 为 60,416 B，两者均被套同一规划；split=0 又被上游 setter 拒绝，内部默认分支永远到不了 | 配置值语义、地址区和镜像处理不一致，不能开放为通用 STC32 下载分区支持。当前 StudioX AI8051U 独立后端不使用该路径 |

| S07 / 中 | 底层前端在 MCS-251 HEX 缺 type 04 时打印错误，但 `program_mcu` 正常返回，`run()` 最终退出码为 0；假传输记录只有 connect/disconnect，没有任何写入 | 独立工具或只看退出码的调用方会误判成功，应抛出输入错误。StudioX 当前 MCS-251 下载使用独立后端；普通 mcs51 入口不应借此扩展支持 |

### 需要补证据的协议与产品能力问题

1. **系列名称不足以授权写配置。** `StcIspCapabilities.For` 对 `STC12*`、`STC15*` 直接继承旧系列时钟能力；底层选择也按名称正则。当前型号库没有 STC12H/STC15H，合成名称命中旧路径只是风险复现。导入未来器件包时应按明确的协议代际、ROM/BSL、选项布局和容量声明决定能力，未知组合不能自动取得旧型号写入资格。
2. **不能把 `stc89a` 视作已自动支持。** 代码实现存在，但自动路线中只有 `stc89`；两者状态位置、校验/串口设置及命令不同。需要准确器件/ROM 识别证据，不能仅按“大版本较新”切换。
3. **不能静默补全缺失状态。** 后期 STC15 `initialize_options` 只要求 14 字节，长度 23 或 37 仍生成四字节 MSR，随后 `build_options` 会把缺失的核心电压字段填 FF。四字节可能对应真实旧 ROM，故不能统一强制所有 STC15 都是 38 字节；应由已核对协议配置规定必需字段和写入掩码，区分合法旧布局与截断。
4. **STC10/11/12 的额外写入位置仍有未知。** `Stc12OptionsMixIn` 在注释中承认最后一个选项字节位置不确定，故把同一值写到两个位置。12A/12B 又有 BSL≥66 时的额外 50/10 交互。离线生成符合现有源码，不证明所有芯片接受这些位置而不影响其他选项；需按变体核对。
5. **保留时钟不等于保留校准原字节。** STC15/8 的 trim=0 路径仍可能依据当前频率重新校准。STC8G 前端按请求频率 27.36 MHz 切换 8d/8g 实现，preserve=0 与芯片现有频率没有直接对应。保持现有 UI“RC 可能重新校准”的说明，下一步按器件及 BSL 核对自动选择与响应，不以是否下载成功替代频率和原始配置核对。
6. **原生 USB、USB 转串口、USB 下载桥分开。** 新 USB 的 S[8:17] 九字节原始配置保留规则，不能套串口 `Stc8Option` 的五字节拼接；USB 转串口仍是 UART 协议；AI8051U 现有桥后端具有独立的精确状态门禁，不能据它宣布 STC32/AI 全系列或直连串口已通过。

### 各代配置语义与边界

下表是内置串口参考实现的 MSR 布局，零基 M 表示该类内部拼接后的数组，不是芯片 SFR 地址。它证明不能共用一张原始位表，不构成全部型号逐位硬件确认。

| 参考类 | 原始状态 S 中的选项来源（零基） | 明显区别 |
| --- | --- | --- |
| `Stc89Option` | 89：S19；89A：S1 | 单字节；6T/12T、ALE、XRAM 等与后续 1T 系列不同 |
| `Stc12AOption` | S23、24、25、29 | clock_source：M0 bit1=1 为 external；低压字段是高/低档位；擦 EEPROM 为 M2 bit1 的反逻辑 |
| `Stc12Option` | S23、24、25、27 | reset=M0 bit0 正逻辑；POR 等待 M1 bit7=0 为 long；擦 EEPROM 为 M3 bit1 反逻辑 |
| `Stc15AOption` | S23..35，共 13 字节 | reset=M0 bit4 正逻辑；低压启用 M1 bit6 正逻辑；EEPROM 擦除在 M12 bit1 反逻辑 |
| `Stc15Option` | S5、6、7、12，部分版本再加 S37 | reset=M2 bit4 反逻辑；低压启用 M1 bit6 反逻辑；时钟 M2 bit0=1 为 internal；擦 EEPROM 为 M3 bit1 正逻辑；POR long 的极性与 STC12 相反 |
| `Stc8Option` | S9、10、11、15、16 | WDT 移到 M3；低压档位为 3−(M2 & 3)；擦 EEPROM 移到 M0 bit1 正逻辑；M4 分区字段不能代表全部容量与 CPU 模式 |

同样名为 `low_voltage_reset` 的字段，可能表示复位启用、也可能表示门槛高低；同一档位编号在不同 F/L/H 型号上的电压不能共用。WDT 是否上电启动、IDLE 是否停止、分频、运行后能否关闭也要分开。引脚检测条件的实际引脚、复位管脚与启动输出管脚同样按具体型号列出，不能把运行时串口重映射误当下载接口重映射。

EEPROM 至少有四个独立维度：物理容量与可用区域、IAP 逻辑地址、MOVC 地址、本次擦写策略。厂商 [STC15 手册](https://stcmicro.com/datasheet/STC15F2K60S2-en.pdf) PDF/纸面第 633 页表明：STC15F/L2K08S2 的 53 KiB EEPROM 在 IAP 下为 0000–D3FF，MOVC 下为 2000–F3FF；IAP15F/L2K61S2 则允许用户程序区作为 EEPROM，没有同样的专用数据区。不能统一使用 `65536 - 固件大小` 估计可保留容量。该页已渲染核对，元数据、SHA-256 和完整选页提取在审计目录。

[STC12C5A60S2 手册](https://stcmicro.com/datasheet/STC12C5A60S2-cn.pdf) PDF/纸面第 35 页说明内/外时钟设置于后续冷启动生效，且重新选内部 RC 前仍需提供当前外部时钟完成下载。该页旧版官方界面还把“下次下载擦除数据区”和程序/EEPROM 文件的未用区填充分别设置；主机填 FF/00 不等于芯片保留或擦除 EEPROM。本轮只读取手册，未以固件中的 IAP 自擦写示例代替厂商 ROM ISP 命令。

串口前端会先设置选项对象，然后执行 handshake→erase→program→program_options。故“下一次下载擦 EEPROM”的持久字段、这次 erase 命令作用范围、要发送的 EEPROM 镜像必须分别建模：在擦除后写一个保护位不能保护刚才已经被擦掉的数据。底层原始命令行还会警告后截断过长镜像；当前 IDE 的 HEX 地址上限预检已挡住常规 8 位工程的这种输入，不应把原工具行为直接等同 IDE 行为。

### 已有实板证据如何复用

IAP15F2K61S2 的官方普通下载原始记录位于 `.artifacts/stc-isp-reliability-20261010/official-com15-run1.ndjson`。它支持精确目标 7.2.5S/状态70 的首轮 11 点与 66 脉冲修正，受控脚本仍只对 F 型号启用。[IAP15L2K61S2 验收](STC-IAP15L2K61S2-ACCEPTANCE-20261021.md)明确使用 L 专用镜像，L 的原校准流程已实测；不能因为 F/L 名称相近就扩大 F 修正。Mon51 的专用 62/42 写入也不能混成普通程序下载格式。

本次没有把过去的原生 USB 或 AI8051U 桥抓包改称串口证据，也没有把同一段 MSR 在不同通道的显示结果当作位定义真值。既有成功判定仍要求进程成功、准确型号标记和完整下载结束标记，程序进度达到 100% 或工具打印 `done` 均不足以宣布整体成功。
