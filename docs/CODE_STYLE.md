# 源码与注释约定

本约定覆盖仓库维护的 `src`、`tools`、`examples`。厂商 SDK、许可证、自动生成文件、运行时和构建产物不参与批量整理。器件包生成脚本中内嵌的厂商源码或生成模板，应由模板维护者单独核对，不能当作普通字符串自动重新排版。

## 先确定职责

每个类只有一个明确的所有者职责。界面呈现、会话状态、协议编码、路径权限、设备连接和文件事务分别管理。`partial` 只适用于同一职责的分段实现及 WPF 生成类；新增文件不能代替独立职责的提取。

- Desktop 调用应用服务，处理控件、输入和界面线程，不持有设备连接或编译参数。
- Application 协调用例与服务生命周期，不依赖 WPF。
- Engine、Devices、Packages 和 Foundation 分别实现工程工具、设备、器件包和公共基础能力。
- 一个公开类型对应一个源码文件。既有主类型文件中的首个 DTO 可以保留原文件名；新增类型使用类型名称。内部帮助类可以和其唯一调用者放在一起。
- 组合根负责创建服务和清理顺序。MCP 注册入口只组合工具组；业务实现放在对应工具组与服务中。

## C#

以 `.editorconfig` 为排版来源，使用 UTF-8、LF、四空格、文件作用域命名空间。命名空间内依次放 `System` 和其他 `using`；不保留无用导入。类型、方法、属性使用 PascalCase，局部变量和私有字段使用 camelCase；WPF 已绑定的事件处理器名称和外部协议字段保持兼容。

控制语句使用花括号，块独占一行。同一行不堆叠多个语句；只有简单、可直接读懂的返回表达式使用表达式体。枚举值、参数和初始化器较长时逐行写，避免为了缩短文件行数把逻辑压成一行。方法之间保留空行，连续相关字段和简单属性可成组排列。

异步方法使用 `Async` 后缀；需要取消的操作显式传递 `CancellationToken`。UI 回调在 Dispatcher 中执行，业务服务不得捕获界面同步上下文。清理方法先使旧回调失效，再等待在途操作结束，最后释放其拥有的资源。

读取脏编辑缓冲区、审批后的文件哈希、工程代次和设备所有者时，保留既有校验。格式整理不能改写公开方法签名、序列化值、MCP 工具描述、消息次序或权限边界。

## XAML 与项目 XML

使用两空格缩进，一行一个元素，属性分行。保留命名空间、资源键、绑定、事件名称、可见文本和 `xml:space`。属性内的换行用字符引用保存，避免 XML 解析时变成空格。格式工具会在写入前比较 XML 数据是否等价。

## 注释

说明使用中文，API 名称、器件料号、协议字段、单位和引用保持原样。

- 类型的 XML `<summary>` 说明职责、所有权或输入输出；复杂公开方法补充前置条件、单位和失败语义。
- `//` 说明约束、原因和容易踩错的边界。较长说明分行，不把多段注释挤在一行。
- 字段名已经表达事实时，不写“给变量赋值”“循环所有项”等复述。
- 说明已实现的行为，避免“以后再用”“新版本”“本次修改”等很快失效的时间措辞。
- `null` 或未知统计不能写成零；离线模拟不能写成实机结果；计数不能没有依据地换算为时间或百分比。
- 捕获异常后保留原始诊断。正常取消、已经展示过的失败或继续清理资源时，注释解释为何不重新抛出。
- 未完成项须写具体条件及影响，不能只留 `TODO`。厂商版权、许可证和协议定义不翻译、不删改。

示例：

```csharp
// 审批期间磁盘文件可能变化；实际写入前再次核对哈希，保护外部修改。
await files.SaveAsync(project, document, token);
```

## 整理与检查

在仓库根目录执行：

```powershell
./tools/Format-Source.ps1          # C#、公开类型与 XAML/构建 XML
./tools/Format-Source.ps1 -Check   # 只检查，不改产品源码
./tools/Build.ps1                 # 常规解决方案构建
```

结构工具复用本机 .NET SDK 的 Roslyn，校验 token 和注释，补花括号并拆分同文件公开类型；再由 SDK 排版。格式检查不会构建厂商工程、烧录、升级版本或发布。

第一方 Python、PowerShell 和 C/H 的排版入口、固定格式器及检查方式见 `tools/Format-FirstPartySources.ps1`。Python 比较 AST，C/H 核对 token，PowerShell 校验语法；字符串中的生成内容保留原值。嵌入式 C/C++ 还要遵循 MCU 技能中的并发、超时、容量和准确料号约束。

职责调整必须运行相关离线行为验证，不能只看到编译成功。当前重点门禁包括 AI 协议与缓存、MCP 完整契约、审批卡移除、工程隔离、实时编辑同步、设备释放和 LVGL 自定义 UI。测试须使用隔离夹具，保留真实工程的未提交改动。
