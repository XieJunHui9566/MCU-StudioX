## 冷启动问题与修正

用户再断电上电后，首次连接与代码/CDB 核对成功，但初始寄存器 PC=0000。直接 GO 未命中断点，随后暂停与结束握手无应答。原始超时及未恢复的 A5 断点记录保留，没有把该次检查计为成功。

原厂 SET_PC(0) 会将执行入口映射到 DBFD 的用户复位跳板；直接 GO 从物理 0000 执行监控入口，两条路径不同。应用会话现于连接后发现 PC=0 时显式执行该映射并回读，保持暂停；非零 PC 不受此初始化影响，不擦写 Flash，也不声称复位外设。

用户再次断电上电后，先核对上次日志、目标 CODE 及原程序身份：唯一差异为 00A8 的 A5，原字节 90；仅恢复这一字节，再完整回读 188 字节。恢复日志改存为已核对记录，未绕过未恢复记录或重新下载整份程序，执行上下文仍保持冷启动暂停状态。

修正版随后 7 项检查通过：V2.5 连接及 CDB 自动加载；初始 PC 映射 DBFD；源码断点绑定及命中；源码单步计数 0→1；完整用户代码保持一致；结束恢复运行并释放 COM18。此次没有用户区擦除、监控制作或配置写入。
