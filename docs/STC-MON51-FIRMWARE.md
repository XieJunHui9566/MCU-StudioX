# IAP15F2K61S2 原厂仿真监控与制作通道

2026-10-09：在用户提供的 AiCube 提取资料中找到并解码了原厂 **Mon51 V2.5 MCU 固件**。现有固件满足当前用户程序更新及调试功能，当前不需要重写 MCU 监控。专用制作通道已在本次明确授权的 COM18 / IAP15F2K61S2 / CH340C 上完成写入应答、制作后重新上电握手、188 字节用户程序恢复及 14 项基础调试检查；此前 STC-ISP 制作的验收与本次原生制作证据分别保留。范围仅为 ISP 7.2.5S、状态标记 70 及当前已核对镜像。

## 固件来源与复核

原始来源是用户本机 AiCube-ISP-v6.96V-plus.exe（10,395,648 字节），SHA-256：`DC8B06F1FD951D2CBCCDAC9A6BA120233E82C83E53C56761BD8C794E86E2050E`。`E:\手册PDF\AiCube` 的提取资料包含同一 EXE 的反汇编和 ZIP 资源。依用户 2026-10-09 的明确要求，已核对的专用制作 BIN 随 **stc.stc8 / 0.1.2 `.mcupack`** 提供；包内保留来源、原厂资源散列及权利声明。IDE 运行时不需要厂商 EXE、不加载 Keil DLL，直接由应用服务校验器件包并交给 IDE 内置下载引擎写入。此本机交付不声明厂商固件为开源或获得公开再分发许可。

包中 `IAP15F2K61S2.monitorFirmware` 指向 `debug/mon51/iap15f2k61s2-7.2.5S.bin` 和 `provenance.json`；其他型号没有这项制作能力。窗口显示准确包版本与固件版本，制作前完整校验包索引、镜像大小与固定 SHA-256，再生成专用制作快照和 `monitor-source.json`。旧工程可以明确选择这一监控资源包，其原来的 SDK、器件包和编译工具锁定不变。多个候选资源不自动猜测最新版本。

开发重建使用 `tools/New-StcMon51Pack.py --base-pack <已核对的 0.1.0 包> --monitor-image <已核对 BIN> --output <新的源目录>`，再用 CLI `pack` 生成格式 1 包及完整哈希索引。生成器不修改旧包，也不要求最终用户提供 AiCube。以前的 EXE 静态导入器仅保留为开发调查工具，不是 IDE 制作入口。

## 为什么普通 ISP 下载不等价于制作

原厂制作模式 7 在 `0x44DA45` 起解码镜像，按准确型号修改最后一字节，再重新编码并用 `0x42` 写入模式（`0x44DB4A`）。首包设位 20，因此实际命令为 62；后续为 42。普通 ISP 使用 22 / 02。两条流程的载荷编码与命令不同。

F449 将型号标记加 02；当 ISP 版本至少 7.2 且状态尾字节的高半字节为 50 时，初值为 00，否则初值为 10。此前 COM18 只读检测保留了 7.2.5S、状态尾字节 70，因此当前制作镜像末字节为 **12**。原生入口只接受这一组合；不向其他版本或尾字节发送擦除命令。

制作镜像使用确定的 FF 用户区填充（原厂生成随机填充），复位块放 0000，监控放 E000，尾字节 EFFF 为 12，再对连续 61,440 字节编码。最终 BIN SHA-256：`ABC080915DDDCA9589F184E9BE76FBCC757EDF001BE02AF7A70ECB57451106F9`。该镜像已在当前实板完成制作并进入 Mon51 V2.5；没有把确定填充与随机填充的等价性扩展到其他型号或 ISP 版本。

制作入口走现有受控 stcgal 运行时的专用适配：准确型号/物理容量/ISP 版本/尾字节门禁 → ISP 握手 → Flash 擦除 → 62/42 编码写入并逐包核对应答 → 07 完成 → 写回已读取的选项及校准参数 → 退出并提示重新上电。它会替换用户程序、监控及 ISP 参数，不能沿用“只写用户区”的授权。RC 可能重新校准，不代表原始参数逐字节不变。完整 ACK 仅证明工具写入流程完成；重新上电后能否握手和调试必须另行验证。

## 功能边界

| 项目 | 已实现/已知边界 |
| --- | --- |
| 用户程序热更新 | 原生 Mon51 用户区擦除、正文写入、最后提交 LJMP 复位向量、完整回读；188 字节实际工程曾实板通过，不要求每次断电 |
| 调试 | 运行、暂停、指令/源码单步、逐过程、跳出、运行到光标、寄存器、内存及变量编辑、源码/地址/条件/日志断点；具体变量布局须能从 CDB 核实 |
| 源码与工具链 | 当前 SDCC 标准 CDB；源码、构建回执、HEX/CDB 与目标 CODE 必须匹配。Keil OMF 尚未解析，不会自动套用 CDB |
| Flash | 厂商要求保留 DC00–F3FF 共 6 KB；即使恢复固件只有 4 KB，也不缩减保留范围。IDE 另保留 DBFD–DBFF 跳板，用户最多 56317 字节 |
| RAM | 用户 XDATA 0000–03FF；监控占 0400–06FF 的 768 字节；厂商声明不占用户 data/idata 资源 |
| 引脚与功能 | P3.0/P3.1 专用；用户不可写这两个引脚或使用相关 INT4、定时器 2 时钟输出/外部计数。资料称不占 UART1；用户 UART1 改脚并行运行尚未实板验证 |
| 断点 | 改写 CODE 为 A5；IDE 同时最多 16 个地址（包含内部临时断点）。这是主机限制，不代表芯片有 16 个硬件比较器；反复改写会消耗 Flash 寿命 |
| 观察点与时序 | 条件断点是停止后计算条件；没有已验证的数据访问硬件观察点、完整实时轨迹或外围时序仿真。定时器/中断在暂停和单步时的行为尚未验收 |
| 复位与电源 | IDE 逻辑复位设置 PC/上下文，不等于芯片断电或完整外设复位。制作后需 MCU 断电再上电；CH340C 本身不能保证板上电源控制 |
| 波特率 | 静态监控代码通过同步字节测定通信时序；IDE 的波特率用于串口通信，不是修改芯片配置。当前实板验证值为 115200 |
| 型号与版本 | 调试仅 IAP15F2K61S2 / Mon51 V2.5；制作进一步限定 ISP 7.2.5S、状态尾字节 70。其它 STC15/8/32、USB/SWD 不作为已适配实板 |

Flash/RAM/引脚限制的一级来源为 [STC15F2K60S2 系列官方手册](https://www.stcmicro.com/datasheet/STC15F2K60S2-en.pdf) 中 IAP15 仿真说明，以及用户提供的 STC-ISP 仿真页。具体命令与资源放置来自本机原厂 EXE 静态证据；未公开 SFR 9C 在监控中用于执行/停止恢复，完整硬件含义尚未核实。

## 是否另写监控

若以后确实需要替换监控，可以自定义协议、RAM 布局和 IAP 更新策略；这仍需保留通信引脚、RAM、Flash，并验证复位进入、异常恢复、中断/定时器影响和 Flash 擦写寿命。重写软件不能让该芯片获得已验证的 SWD、零资源占用调试或真实硬件访问观察点。现有原厂监控与专用制作通道已经满足本次流程要求；复杂中断和外设时序场景仍需各自验收。
