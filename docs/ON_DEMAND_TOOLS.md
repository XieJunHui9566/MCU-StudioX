# 准备工程开发环境组件

轻量版保留与完整版相同的自包含 IDE、器件包、内置插件、clangd、Git 和独立宿主；不携带 MCU、HDL、PC 开发环境组件或独立下载运行环境。从新建工程页选择器件包、完整型号和模板创建工程，或选择已有 StudioX 工程，再进入“工具 → 开发环境组件 → 准备工程开发环境组件…”。第一个工程引导、工程健康检查、开发环境组件和分发页均提供入口。两种版本都能导入 `.mcutoolchain`，无需安装全局工具。

## 使用流程

1. 页面读取工程配置和内容锁，列出明确的 ID、版本、编译器与用途。快速检查只检查清单身份和必要入口，不递归枚举 SDK、不自动联网。
2. 默认选择“自动从 GitHub 获取”，点击“获取并安装工程缺少的组件”。IDE 使用内置来源和可信公钥读取签名目录，按工程的 ID/版本精确匹配，不需要输入网址或下载公钥。全部缺失版本有目录条目才开始获取，尚未发布的版本明确列出；不会替换为最新版。
3. 自动模式依次下载、核对长度与完整 SHA-256、绑定归档身份和工程内容锁，再完整校验并安装。页面“取消操作”或顶部停止按钮可取消；已保存片段留在独立用户目录 `distribution-cache`，下次同一归档可续传，重新启动 IDE 也可继续。
4. 选择“手动导入本地组件”，点击“选择 .mcutoolchain 并导入…”，可多选工程所需归档。此模式不访问网络，先检查整批身份并展示来源、大小和摘要，再确认导入。支持真实 7z/LZMA2 和已有 ZIP 格式 1 组件，也兼容 `.studioxtools`。本地归档不继承当前目录的发布者验证状态。
5. 每个组件独立暂存并原子发布。取消或失败保留已经安装的组件，刷新后可以只准备剩余组件。工程配置在获取或预览期间改变会拒绝安装。已有组件被禁用时先启用，目录损坏时使用“工具校验与修复”。通用“工具 → 开发环境组件 → 导入开发环境组件…”入口可管理预装和后来导入的组件，相同身份与内容完整校验后跳过重复安装，同版本不同内容拒绝覆盖。
6. 安装完成后重新运行健康检查或编译。工程配置、工具内容锁、源码和 sdkconfig 保持不变；不修改全局 PATH，不安装全局 Python，也不启动硬件会话。

MicroPython 脚本不要求原生 GCC/CMake；Zephyr 实验工程显示范围说明。已配置的引脚映射、逻辑构建和 RTL 仿真需求单独列出，不把所有工程绑定到单一 MCU 系列。预览后工程配置或工具状态发生变化时拒绝安装，必须刷新。

## 下载和信任

归档缓存以 SHA-256 命名。中断、取消和早于文件尾的断流保留落盘字节；服务器正确返回 206 时检查 Content-Range，强 ETag 可用于 If-Range。服务器返回 200 时重写完整文件。错误范围、大小、编码或最终哈希会丢弃无效片段，不发布安装缓存。已有完整缓存使用前仍重新校验；缓存损坏可重新获取。

归档允许最多 5 次 HTTPS 跳转，适用于发布站点转到 CDN；拒绝降级到 HTTP。目录读取仍不自动跳转。每次网络等待最多 90 秒，超时保留进度；没有把大归档总下载时间限制为 30 分钟。同一归档使用 OS 文件锁，多个 IDE 实例不能同时改写进度。

“工具 → 开发环境组件 → 从 GitHub 获取开发环境组件…”和页面“浏览 GitHub 组件库 / 其它版本”可浏览所有公开条目，读取时始终核对 IDE 内置公钥。当前公开目录提供 `stc.sdcc/1.0.1`，原有 11 个组件和新增 IDF 5.5.5、6.0.3、6.1.0 仍在补齐发布材料，登记不代表可下载。已有 `stc.sdcc/1.0.0` 工程不会自动使用 `1.0.1`。

自定义 HTTPS / 本地目录、发布者公钥和逐个下载预览位于折叠的“高级”区域。来源和公钥变更后旧目录选择失效；没有公钥时发布者仍是目录自述，SHA-256 不证明发布者身份。自动模式不沿用自定义目录或公钥。组件发布和材料要求见 [开发环境组件](DEVELOPMENT_COMPONENTS.md)。

续传语义参考 [RFC 9110 Range Requests](https://www.rfc-editor.org/rfc/rfc9110.html#section-14)。

## 实现与验证

Application 的 `ProjectToolPreparationService` 负责需求、配置快照、归档身份与安装绑定；`DistributionService` 负责下载、缓存和空间预算。Desktop 只调用这些应用服务。快速入口不承诺 SDK 完整性；构建和工具完整校验仍走现有目录校验服务。

基础构建使用 `tools/Build.ps1`。`StudioX.ProductWorkflowValidation` 覆盖跨服务实例续传、取消、错误范围、200 回退、缓存损坏、并发、CDN 跳转、精确版本、编译器、内容锁、预览后配置变化与离线安装。可选参数使用本机工具和独立 F407 工程编译；ESP-IDF 参数只进行现有工程的只读入口检查。

`StudioX.ComponentCatalogValidation --acquisition <新输出目录> <已签名目录文件> [--online]` 覆盖 7z/ZIP 批量导入、精确版本、取消后继续、配置/锁保留、禁用/修复分流、缺失签名、目录读取期间工程变更。`--online` 明确从公开 GitHub 下载 SDCC 组件到隔离目录并完成安装，不执行工具或连接硬件。

`--preview-project-tools <隔离输出目录> <工程目录> <目录文件>` 检查真实引导入口、菜单、缺失状态、目录加载、忙碌状态、深浅主题、小窗口、标签重开及来源失效，不访问硬件。

`tools/Publish-Light.ps1 -OutputDirectory <新目录>` 生成轻量 Payload，也可使用 `Publish.ps1 -DistributionProfile light`。旧 `Publish-Base.ps1` 和 `-DistributionProfile base` 明确转到 light，共用发布流程。两种配置保留相同器件包和内置插件，`-ExcludePlugins` 仍可用于明确的无内置插件发布。可用轻量 Payload 运行相同 UI 预览，确认不依赖开发机的固件开发环境组件。

开发环境组件格式、当前落地范围及完整/轻量互相覆盖的保留规则见 [开发环境组件](DEVELOPMENT_COMPONENTS.md) 和 [安装说明](INSTALLER.md)。验证使用本地 Payload 和唯一测试身份的安装器，不构成正式发布。
