# IAP15L2K61S2 Mon51 软件适配

2026-10-21：新增 IAP15L2K61S2 的 Mon51 V2.5 支持。已核验准确型号目录、原厂程序静态资源，完成 SDCC 实际编译及离线协议/WPF 检查；用户随后接入实机并允许覆盖废弃程序，本型号已完成制作、断电激活及 16 项实板检查，见 [实板验收](STC-IAP15L2K61S2-ACCEPTANCE-20261021.md)。

## 型号与流程

[STC 官方系列资料](https://stcmicro.com/cn/stc/stc15f2k60s2.html) 将 IAP15L2K61S2 列为可作仿真器的型号，参数为 61 KiB Flash、2 KiB SRAM、2.4–3.6 V。工程与确认框使用完整 ID，不以 STC15L2K60S2 等相近型号代替。

1. 使用包含本次适配的 IDE，导入 `stc.stc8/0.1.6` 器件包。新包保留 0.1.5 的既有器件、模板及资源，不修改旧包或工程版本锁。
2. 打开准确型号为 IAP15L2K61S2 的 STC SDCC 工程，点击“调试”，明确确认型号与实际串口。
3. 尚未制作监控时，选择同型号固件并点击“设置为仿真芯片”。制作会覆盖用户程序及监控区并写回 ISP 参数，程序先核对目标、容量、镜像、ISP 版本及状态。已有生效的 Mon51 V2.5 可跳过制作。
4. 制作后给 MCU 断电再上电并勾选确认；“开始调试”保存、编译最新源码，通过 Mon51 更新用户区，完整回读并加载 CDB 后保持暂停。

支持现有 Mon51 运行、暂停、指令/源码单步、逐过程、跳出、断点、寄存器和内存观察/编辑；符号及变量操作要求当前 CDB、构建回执和目标代码一致。Mon51 握手只能核对监控版本，不能自动读取芯片完整料号。

用户 CODE 上限 56317 字节（至 DBFC），DBFD–DBFF 为复位跳板，DC00–F3FF 保留监控；用户 XDATA 为 0000–03FF，监控占用 0400–06FF。P3.0/P3.1 供监控使用，其他限制见 [固件说明](STC-MON51-FIRMWARE.md)。

## 固件与制作边界

F/L 镜像不能互换。制作严格限定 ISP 7.2.5S / 状态 70 / 115200 / 保留当前时钟来源；未知版本或状态拒绝，不猜测兼容。F 型号专用的实测 RC 校准修正未扩大到 L 型号。离线 ACK 本身不证明实板成功；本次另完成了真实制作、断电激活、程序回读和调试验收。

`tools/New-StcMon51LowVoltagePack.py` 校验原 0.1.5 包及 L 镜像散列，生成新的 0.1.6 源目录，再由 CLI `pack` 制作格式 1 归档。包内保留来源和原厂权利声明；不包含或执行厂商 EXE、Keil DLL，不声明公开再分发许可。

## IDE 本体改动

本功能涉及 Engine、Application 和 Desktop：集中管理准确型号与镜像身份；构建预设、回执、制作和连接接入 L 型号；恢复记录保存准确型号，并阻止通过 F/L 切换绕过同串口未完成恢复；连接窗口按工程过滤型号及固件，显示 L 的软件验证状态。产品版本未升级，没有自动连接或烧录硬件。
