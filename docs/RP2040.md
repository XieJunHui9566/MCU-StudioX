# RP2040 C SDK 工程

本文记录原 0.1.0 C SDK 包。0.2.0 保留这些 C 模板并增加独立 MicroPython 工程模式，见 [MicroPython 适配](MICROPYTHON.md)。

独立 StudioX 格式 1 包 `raspberrypi.rp2040/0.1.0`，基于官方 Pico SDK **2.2.0**，与 RP2350 分包。新建工程选择「树莓派 · Raspberry Pi」→「RP2040 · Pico SDK C 工程」→「RP2040 · Pico / Pico H（2 MB Flash，离线）」。

## 板级配置与模板

准确工程目标为 `RP2040-PICO`，对应官方 Raspberry Pi Pico / Pico H：双核 Cortex-M0+、12 MHz 外部晶振、SDK 默认 **125 MHz** 系统时钟、**2 MiB 外部 QSPI Flash**、**264 KiB SRAM**（256 KiB 主区、两个 4 KiB scratch 区）。芯片标称最高 133 MHz 不等于模板默认频率；外部 Flash 容量和 boot2 设置取自官方 `boards/pico.h`，不推断任意第三方 RP2040 板卡的配置。

| 模板 | 行为 |
| --- | --- |
| 最小 C 工程 | 内存计数和 100 ms 延时，不初始化外部 GPIO |
| GPIO 闪灯（C） | 使用 Pico 的 GP25，每 500 ms 翻转；兼容板须核对 LED 接线 |
| 双核队列（C） | 两颗 Cortex-M0+ 通过 SDK 队列交换数据，记录响应超时，不操作外部 GPIO |

入口均为 `src/main.c`，默认 C17、`-Og -g3`；可在 IDE 编译设置中覆盖优化与调试信息。SDK 内部保留少量 C++ 运行支持源码，不提供 C++ 用户模板。没有 MicroPython 工程、解释器或固件。

## SDK 与工具

包制作时使用上游 CMake File API 与 Ninja 编译依赖收集实际 C SDK 源码、启动代码、私有汇编片段、配置头和预生成的 256 字节 boot2 校验汇编。最终包保留 SDK 许可证、原始文件 SHA-256、版本、提交及必要改动说明。

用户工程使用 IDE 内置的 `arm.gnu/1.0.0`（GCC 15.2.Rel1）、CMake 和 Ninja，不依赖包作者机器的 Pico SDK、Python、picotool 或网络。生成 `.build/firmware.elf/bin/hex/map` 和 `compile_commands.json`。工程可放在包含中文和空格的目录中。

收录 pico_stdlib、multicore、queue/sync、rand/unique_id 和 GPIO、UART、定时器、时钟、ADC、DMA、Flash、I2C、SPI、PIO、PWM、interp、RTC 等 API 的依赖。未使用的函数通过链接回收删除。根 CMake 用于添加用户源码、头文件目录和宏，不执行 `pico_sdk_init()`。

这是固定板型的已解析 SDK 源码包；USB/TinyUSB、Pico W 无线、FreeRTOS、PIO 汇编生成、UF2 生成和任意上游 Pico CMake 工程导入尚未接入。官方 boot2 和生成器作为来源材料保留，用户编译不运行 Python。

## 制作与验证

```powershell
python tools/New-Rp2040Pack.py --sdk '<本机 Pico SDK 2.2.0>' --toolset artifacts/tool-runtime/toolsets/arm.gnu/1.0.0 --python '<Python 可执行文件>' --cli src/StudioX.Cli/bin/Debug/net10.0/StudioX.Cli.dll --output '<新输出目录>'
dotnet run --project tools/StudioX.Rp2040Validation -- '<包.mcupack>' '<包含 toolsets 和 languages 的 runtime 目录>' '<新验证目录>'
```

SDK 固定提交为 `a1438dff1d38bd9c65dbd693f0e5db4b9ae91779`；不同提交或已跟踪 SDK 源码被修改时拒绝打包。维护配方见 `examples/packs/raspberrypi.rp2040/`，生成器不自动下载 SDK。

交付目录为 `artifacts/packs/RP2040-0.1.0/`，其中 `index.json` 记录归档 SHA-256。归档大小为 768,483 字节，SHA-256 为 `c05b06e251d6766c9a1400054c14346d5e0c6f307408a378fbe0dc0c50ccd60a`。开发目录 `artifacts/device-packs-development/Raspberry-Pi/` 随开发版构建复制；后续 `tools/Publish.ps1` 将 RP2040 与 RP2350 两个包分别加入发行目录，不合并包身份。

2026-09-28 离线验证通过：

- 三个模板经真实包导入、工程创建和 BuildService 编译，BIN 分别为 **17,536 / 17,632 / 23,148 字节**。
- 检查每个 BIN 的 boot2 CRC、向量表位置、初始栈顶、Thumb 复位入口，以及实际 ELF 的 Cortex-M0+ ABI。
- 从 ELF/MAP 确认 2 MiB Flash 与 256 + 4 + 4 KiB SRAM，保留原始构建日志和内存报告。
- 用 C 静态断言核对板型、12/125 MHz 时钟、Flash 和 GP25；实际链接外设 API，验证 O2 覆盖与恢复。
- clangd GPIO 补全、SDK 声明跳转与悬停通过；工程路径包含中文及空格。
- `--preview-rp2040` 通过真实 WPF 深浅主题、树莓派图标、三模板选择、新建工程、编辑/编译入口及下载/调试禁用检查；截图和结果位于 `artifacts/validation/rp2040-ui-20260928/`。
- `tools/Build.ps1 -Configuration Debug` 全量构建为 0 警告、0 错误；隔离执行发行脚本的树莓派包收集步骤，确认两个独立包均保留且哈希一致，没有制作安装包或修改产品版本。

记录位于 `artifacts/validation/rp2040-c-sdk-20260928/`。上述均为软件验证，未连接或烧录 RP2040；器件包不声明 OpenOCD 配置，IDE 下载与调试入口保持禁用。RP2350 已有的实板证据不适用于本包。
