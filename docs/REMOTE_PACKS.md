# 在线器件包同步

MCU StudioX 使用公开的 [MCU-StudioX-MCUPacks 仓库](https://github.com/XieJunHui9566/MCU-StudioX-MCUPacks)作为在线器件包来源。该仓库按厂商品牌存放 `.mcupack`，根目录的 `index.json` 列出每个包的相对路径、ID、版本、压缩文件大小和 SHA-256。目前只发布经过再分发检查的部分器件包；其他本地或安装包自带器件包不受在线目录影响。

IDE 启动和打开器件页时只读取本地器件包，不自动访问 GitHub。在「器件与模板」页或「文件」菜单手动点击“检查更新”时，IDE 获取 GitHub `main` 分支的提交 ID 和该提交下的目录，与本地已安装版本比较；这一操作不下载或导入包。手动点击“同步下载”后，IDE 再读取一次固定提交的目录并下载缺少的新版本，避免更新过程中混用两个提交的文件。已安装的相同 ID 与版本会跳过；新包先完整验证并安装，刷新器件目录时再清理已被新版本完整覆盖的旧包。网络请求失败时本地器件包仍可使用，可稍后再点击重试。

重复版本按包 ID 和三段数值版本号判断：只有同 ID 的较新包包含旧包的全部器件及每个器件的全部模板 ID，才会清理旧版并只显示保留的版本。不同 ID 的包不会因显示名称相同而合并；旧版独有的器件或模板仍可选择。例如，公开仓库中的 STM32 更新包若仅提供 HAL 内容，含 SPL 或 RTOS 独有模板的旧版仍会保留。

发行版随附器件包按版本从高到低导入。若已安装的新包通过完整性校验并完整覆盖某个旧包，旧包不会被再次导入；新包缺少旧包的器件或模板时，两者都可安装。已安装新包损坏时，会报告原始校验错误并允许导入有效旧包。已有工程使用创建时复制到工程 `device/` 的资源和清单，工程记录的包版本与源码保持不动，全局器件包清理不会替换这些副本。

每个下载先限制压缩文件大小并核对完整文件 SHA-256，再检查包内清单 ID 与版本，最后交给 StudioX 格式 1 导入器验证内部文件索引、路径及内容哈希并原子安装。单个包失败时会报告原因并继续处理其他包；取消或下载失败会清理临时文件。同步只导入器件包，不会自动创建工程、编译或烧录硬件。

目录及包由同一公开 GitHub 仓库维护。固定提交和哈希校验能够发现下载损坏及目录与压缩包不一致；它们并不是独立的发行签名，因此发布权限仍须由仓库维护者保护。新内容应使用新的包版本号；已有同 ID/版本不会被静默覆盖。

维护验证：`dotnet run --project tools/StudioX.PackRetentionValidation -- <新输出目录>` 使用小型隔离包检查版本、模板覆盖、损坏保护、目录链接及已有工程副本。`MCU StudioX.exe --preview-pack-catalog <新输出目录> <旧包> <新包>` 验证选择器去重、旧包再次导入后选择新版，并渲染实际模板。
