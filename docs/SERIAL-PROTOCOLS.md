# 串口协议解析

入口：**串口终端 → 协议解析**。选择解析器和角色，点击「应用 / 重载」，之后的新收发字节会进入解析器。切换解析器会清空解析列表，不重放此前文字终端的历史，也不会向设备发送数据。

文字终端与协议解析共用单一串口会话，分别显示。UTF-8、GB2312、HEX 和 ANSI 设置只影响文字显示；解析器始终读取原始字节，不经过文本转码。暂停显示同时暂停两种视图刷新，采集和解析继续运行。

## Modbus RTU

- 显示宿主时间、RX/TX、站号、功能码、CRC / 状态与中文摘要。选择报文查看原始 HEX、计算与接收 CRC、地址、数量、寄存器 UInt16 / Int16 或线圈位数据。
- 展开 01/02/03/04 读操作、05/06 单点写、0F/10 多点写、16 掩码写、17 读写寄存器请求及异常响应。这里的功能码按十六进制书写。07/08/0B/0C/11 等已识别格式及其他厂商功能保留原始 PDU；未展开的功能不会猜测寄存器语义。诊断功能 08 当前只识别固定 8 字节 ADU，其他子功能变长报文仅按空闲边界查看原文。
- 电脑为主站：TX 是请求、RX 是响应。电脑为从站时相反；这只是解码方向，并不自动实现从站应答。被动监听同时考虑两种长度，方向为推断；写单点的请求和响应内容相同，无法仅凭报文确认方向。
- PDU 地址从 **0** 起，不能直接等同文档中的 40001 等引用编号。读响应本身没有起始地址，寄存器以响应内 `+N` 展示。当前不做请求关联、超时事务统计、浮点字序猜测或自动轮询。
- 按功能码长度和 CRC-16/MODBUS（初值 FFFF、多项式 A001、低字节先传）处理拆包和粘包；损坏前缀、CRC 错误、不完整帧不会静默丢失。
- 「空闲收尾」默认 100 ms，范围 20–2000 ms，用于结束残留/未知格式报文。USB、操作系统和驱动会合并或拆分接收，宿主时间不能测量 RTU 线上的 t1.5/t3.5；这是软件解析视图，不是总线时序分析仪。低波特率或长间隔分片可调大该值。
- 发送框「补全 Modbus CRC」将输入当作不含 CRC 的 HEX，追加两个校验字节，并切换 HEX / 无行尾。完整合法 CRC 不会重复追加；按钮不发送，仍需手动点击发送。
- 方向、搜索和「仅异常」可筛选显示；导出保存全部保留帧（不受筛选影响），包含原始 HEX、字段、宿主 UTC 时间与数据来源。

## 离线试用

断开串口后点击「离线示例」，查看读请求、包含 42 与 4660 的响应、异常响应和坏 CRC 共四帧。

「离线解析 RX」把发送框按当前发送格式/行尾/转义设置编码后送给当前解析器，方向为 RX，不写串口、不增加真实 RX/TX 计数。自定义脚本示例测试：

1. 保存示例脚本或加载 `examples/protocols/sensor-frame.js`。
2. 发送格式选 HEX，行尾选「无」，输入 `AA 55 03 01 09 C4 CF`。
3. 点击「离线解析 RX」，会显示 `传感器 · 25.00 °C` 和 XOR 校验结果。

所有离线帧在详情和 JSONL 导出中标注「离线样例（未发送）」，与真实串口帧区分。

## 自定义 JavaScript 协议（API v1）

脚本运行时随 IDE 内置，不需要安装 Node.js / Python。点击「加载脚本」即启用该文件；修改文件后点击「应用 / 重载」。当前不跨启动自动执行用户脚本，每次打开 IDE 后明确加载。语法错误会给出诊断，原解析器若仍可用会继续运行。

```js
function decode(bytes, context) {
    // bytes: 原生 JS 数组，每项 0..255，含上次尚未消费的字节。
    // context: { apiVersion: 1, direction: "RX" 或 "TX",
    //            timestamp: ISO UTC, clock: "host-utc", flush: false/true }
    if (bytes.length < 4) return { consumed: 0, frames: [] };
    return {
        consumed: 4,
        frames: [{ offset: 0, length: 4, summary: "固定四字节报文",
                   status: "ok", fields: { "首字节": String(bytes[0]) } }]
    };
}
```

- `consumed` 是可以从缓冲前端移除的字节数；半帧返回 0，宿主保留等待下一次数据。返回的帧必须按 offset 排序、不能重叠，并且全部位于 consumed 范围内。被消费但未作为帧返回的字节可用于跳过噪声。
- `summary` 必填，最多 256 字符。`status` 为 `ok` 或 `error`。字段名和值均为字符串，最多 32 项，名称 64 字符、值 512 字符。
- 一次输入最多 8192 B、返回最多 128 帧；过长的半帧缓冲会停止解析并报告错误。每次输入可包含多帧，应尽量消费所有完整帧。
- `flush=true` 表示宿主空闲收尾或连接边界；此时仍未消费的尾部会显示「不完整帧」并清除。RX/TX 各自独立缓冲。同一脚本全局变量则由两个方向共用，需要自行按 `context.direction` 区分。
- 清空、连接边界和观察队列溢出会重置分帧与脚本状态。脚本调用顺序执行，不能依靠串口的一次读取就是一个报文。
- 函数必须同步返回普通 JSON 数据。当前不支持 Promise、文件导入、异步网络请求或外部 npm 模块。

## 隔离、性能与限制

- 原串口收发是唯一所有者；协议解析有独立 256 项队列，不持有发送能力，慢脚本不会阻塞原始接收。队列溢出可见并重置缓冲，防止跨缺失片段拼帧。
- 解析列表保留最近 1000 帧；淘汰与解析丢帧计数单独显示。脚本解析失败后停止该解析器，保留诊断；文字终端仍可收发，点击应用 / 重载可以恢复。
- 用户脚本在独立 `StudioX.PluginHost --serial-script` 进程中由 Jint 4.16.3 执行。未开放 CLR、文件、网络、进程或串口接口。
- 每次引擎执行限制 250 ms、200000 语句、64 层递归、16 MiB 分配；父进程另有每次通信 3 秒超时及每 100 ms 的 256 MiB 工作集监测，异常时终止宿主。内存采样有延迟，限制并非操作系统级权限沙箱，不宣称恶意代码绝对安全。脚本异常不重试发送。
- 脚本源码最多 65536 字符 / 文件 256 KiB，IPC 行有长度上限，结果在宿主和主进程各校验一次。

## 验证与来源

`tools/Build.ps1` 构建 IDE 和随附宿主。`dotnet run --project tools/StudioX.SerialChecks` 检查已知 CRC 向量、拆包/粘包、坏帧恢复、主从角色、广播、错误字段、隔离脚本超时/异常/非法返回、跨片缓冲、导出和有界历史。真实 Modbus 从站事务尚未验收；此前 F407 文字串口固件仍为回显测试固件，没有为本功能烧录新固件。

协议依据：[Modbus 官方规范目录](https://www.modbus.org/modbus-specifications)、[应用协议](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)、[串行链路 V1.02](https://www.modbus.org/file/secure/modbusoverserial.pdf)。脚本运行时：[Jint](https://github.com/sebastienros/jint)，许可证连同 Acornima 解析器许可证放在 `licenses/Jint-*.txt`，随发行版复制。
