# RT51 IAP15F2K61S2 实板验收

2026-10-12（北京时间）在用户当前蓝桥杯板完成普通 ISP 下载、60 秒连续运行及
用户确认断电上电后的 30 秒接收检查，正式固件均通过。结论只覆盖下述芯片、
编译 ABI、时钟、栈布局和本次应用，不能扩大到其他 51 型号或任意 ISR/任务负载。

## 板卡与操作范围

- 原理图：用户提供的 `SCH_V31.pdf`，CT107D V3.1，4 页。U1 为 IAP15F2K61S2，
  U3 为 CH340C，USB 串口接 MCU P3.0/P3.1。S2 通过 Q1 控制 MCU 供电，S1 为复位。
- 当前连接：COM5；ISP 实际识别 IAP15F2K61S2，型号码 F449，61 KiB Flash，
  BSL 7.2.5S，UID `F44902204670E9`。本次不是根据串口名称猜测 MCU。
- 用户明确允许下载 RT51 验收固件、普通 ISP 代码 Flash 擦写、内部 RC 校准到
  12 MHz并写回其余已读选项。未单独写 EEPROM；读取到的 EEPROM 擦除选项为关闭。
- 使用 IDE 当前内置 `studiox-stcgal-guard.py` 的精确型号/固件哈希门禁和已验证校准适配，
  未调用官方 ISP 下载。下载工具有完整成功应答和退出码 0；未进行 Flash 字节回读。
- 普通 ISP 已替换旧用户程序，也不保留仿真监控。本轮验证独立运行 RT51，
  没有验证 RT51 在 Mon51 下的在线调试；普通示例与模板仍保留监控内存边界。
- 不驱动 P0/P2 外设锁存总线、继电器、电机、蜂鸣器，也不写板上外部 EEPROM。
  验收程序独占 UART1 默认引脚与 Timer2；不适用于 Mon51 占用 P3.0/P3.1 的会话。

## 时间源与程序

内核接口仍为 `rt51_start(timer_init, tick_ack)`。板级初始化回调选择 Timer0
1T、模式 0 自动重装；12 MHz 下重装 D120，名义 1 ms。tick 回调在已保存上下文、
EA=0 的内核工作栈执行，在真实 tick ISR 中给信号量，不自行切换任务。
UART1 用 Timer2 1T，重装 FFE6，115200/8N1，轮询发送有 3 tick 超时。
PC 接收端只接收，不发送；DTR/RTS 关闭。

当时的正式测试程序为 `firmware/StudioX.Rt51/tests/iap15_hardware.c`，旧源码备份在
`.artifacts/rt51-extensions-hardware-20261012/iap15_hardware-before.c`。
当前源码已加入扩展检查，新固件结果另见 [扩展实板记录](RT51-EXTENSIONS-HARDWARE-20261012.md)。
原测试的 3 个任务分别承担
高优先级消息消费、中优先级消息生产和低优先级持续 32 位计算。计算任务不主动 yield。
启动阶段另有中优先级忙循环干扰持锁者，验证优先级继承；初始 tick 为 FFF0，
用于直接覆盖 16 位回绕。

正式 HEX SHA-256：
`A904631F2CD1E41CF20C24E26F5FF90D751021DA33E8EE77AE5C54E5CAFF57D5`。
链接占用 11,063 字节 CODE、598 字节 XRAM；HEX 中 11,054 个有效数据字节，
普通 ISP 按最高地址填补空洞后写入。任务硬件栈 80..FF，128 字节；
内核工作栈 30..7F，80 字节；每任务 XRAM 保存上下文上限 96 字节。

## 实板发现的启动问题与修复

第一轮固定算术检查报错 17；调度、队列、事件、信号量和算术背景循环仍持续进展。
第二轮在任务开始前保存了 XRAM 变量原值：期望 `FEDCBA98`，实际 `01000000`；
未抢占时的商为 256、余数为 3840，与该错误输入吻合。显式 MOVX @DPTR 写入正确值后
运行检查通过，证明问题发生于进入 RTOS 前的 C 启动初始化。

SDCC 默认 `lib/src/mcs51/crtxinit.asm` 用 P2/`__XPAGE` 和 `MOVX @R0` 复制 XINIT。
该芯片片内 XRAM 的 `MOVX @Ri` 只能访问 00..FF；[厂商手册 3.2.2](https://www.stcmicro.com/datasheet/STC15.pdf)
说明完整内部 XRAM 要通过 `MOVX @DPTR` 访问。这使高于 00FF 的初值遗漏，并可能落到
低地址的其他对象。标准 C52 模拟器支持外部 RAM 分页，原有指令仿真没有体现此器件区别。

修复放在 `examples/iap15/stc15_xinit_sdcc.c` 板级启动适配：使用单 DPTR、16 位源地址、
目的地址与长度进行 XINIT 拷贝，不改 P2 或双 DPTR 控制寄存器。正式固件去掉逐变量
手动修正后仍在两轮实板检查中读到正确初值。内核调度代码未为此修改。
`tools/Test-Rt51Startup.ps1` 新增空块、单字节、256 字节和跨页初值的实际编译/指令检查。
