# MX251 工具链与 StudioX 适配

MX251 必须可独立使用，StudioX 是宿主而非运行前提。IDE 按 SDK 格式、构建契约及内容清单接入兼容版本，工程精确锁定用户选择的组件；独立入口见 [独立工具链使用契约](../toolchains/mx251/STANDALONE.md)。当前编译器候选尚未达到固定完整工程逐项不大于 Keil C251 110% 的体积、运行时间与正确性门槛，不随本次 IDE 源码发布，也不替换已安装工具链或授予 LST 资格。

以下为此前已安装的 R89 组件文档，不能视为新版全部功能已交付。

MX251 全称 **MCU StudioX 251 Compiler**，是基于 SDCC 4.6.0 分支持续修改的工具链。本次更名不改变 R89 编译核心或能力边界。上游版权、许可证和对应源码完整保留；内部 `sdcc.exe`、受锁定的目录与历史资格记录保留原标识，以维持冻结核心的哈希和调用兼容。

`studiox.mx251/0.1.89` 是独立 StudioX 格式 1 `.mcutoolchain`，编译器身份为 `mx251-r89`。配套器件归入独立 **STC251** 包（`stc.stc251/0.1.4`），显示为 **AI8051U-34K64-32Bit（STC80251）**。厂商仍是 STC；它与常规 8 位 STC 器件包、`stc.sdcc` 工具链分开，不修改系统 PATH。内部物理器件 ID 保持 `AI8051U-34K64`。组件版本不是 IDE 产品版本。

长期构建架构固定为 **MX251 + CMake + Ninja**：CMake 管理源码、包含目录和宏，Ninja 执行构建，MX251 编译链接。后续编译器版本或内部实现变化必须保留此链路。当前将构建工具独立管理为 `studiox.cmake/4.4.0`（CMake 4.4.0、Ninja 1.10.2），器件包声明两个精确依赖，均由 IDE 管理并按工程锁定；不借用系统安装，也不依赖8位SDCC组件。

## 导入与使用

需要包含此次 CMake 接入改动的 StudioX 构建。导入 MX251 和 CMake/Ninja 开发环境组件及 `stc.stc251-0.1.4.mcupack`；新建 **STC → STC251 → AI8051U-34K64-32Bit（STC80251）→ 寄存器开发**，F7 编译。

当前只提供一个寄存器开发模板，内存模型在工程详情中调整。模板直接初始化 P2.0 为高阻输入并读取电平，不含 HAL、SPL 或 RTOS，也不假定 LED 接线。STC251 0.1.2 的 `AI8051U.h` 提供完整寄存器名称集合：116 个 SFR、112 个位、676 个 XFR（含别名），并提供 USB 内部地址、中断号、常用掩码和 MDU32/TFPU 命令常量。所有 XFR 使用完整 0x7E 段地址与 8 位 volatile 访问，芯片身份区只读；覆盖清单、厂商依据和勘误见包内 register-reference.json、README.txt 与 provenance.json。声明完整不等同于全部外设或 ISR 已通过实板验收。

早期 `stc.ai8051u-mx251/0.1.89` 包名仅保留在历史资格材料中。已封存的 MX251 工具链归档不因器件包分类调整而原地改写；其中旧说明以当前独立 STC251 包说明为准。

新工程以 `CMakeLists.txt` 的 `target_sources(app INTERFACE ...)`、`target_include_directories` 和 `target_compile_definitions` 管理输入，支持变量、条件和 CMake 正常列表展开。使用 IDE“源码登记与编译列表”也能增删源码。模板包含 `include` 搜索目录，可直接 `#include "AI8051U_Delay.h"`。`mx251.json` 只保留芯片、模型、优化、ABI、运行库及统一IRC设置，不再要求同步登记另一份文件清单。头文件作为输入快照保存；未登记的 C 源文件不会自动参与编译。

当前使用 INTERFACE 目标描述固件，`mx251_firmware(app)` 生成 Ninja 固件任务，由 IDE 内的适配脚本调用原编译器/汇编器/链接器。`MX251_BACKEND` 和 `MX251_ARCHIVE` 源文件属性用于受支持的后端及按需静态库，逐文件 `COMPILE_DEFINITIONS` 生效。任意编译/链接选项、目标链接依赖和生成表达式等未接入项给出明确错误，不静默忽略。尚不是任意桌面 CMake/C++ 工程的交叉编译支持。历史纯JSON工程仍可编译和复现；它不再是新模板主入口。

构建服务核对两个组件和内容锁，运行 CMake 配置及 Ninja 构建；IDE适配脚本新增输入管理，不改写封存R89工具/profile。成功固件固定为 `.build/firmware.hex`，中间文件只保留 `.build/mx251/latest`，CMake缓存为 `.build/mx251-cmake`。保留命令、原始诊断、MAP、配置快照和固件 SHA-256；只有目标/栈/HEX/naked流程检查通过、源码未变化才发布成功凭据。失败或取消移除旧固件入口。配置操作只配置，不编译或发布固件。构建与下载共用工程级进程间锁，互不清理活动目录。

开放新建、编辑、CMake配置、源码登记、编译、HEX导出和下述USB下载。GCC专用参数及源码调试不开放。组件导入不会连接硬件。

## 资格与限制

编译器、汇编器、链接器、启动和运行库机器码保持 R89 原资格内容。普通模板为 ordinary-wide / standard / stack-auto；其它组合按包内 profile/README.txt 选择，不能任意混换 ABI 和运行库。30 个固定工程及 small/large 新建模板通过实际导入后的 IDE 构建服务验证；固定工程 HEX 与封存参考逐字节一致。

CODE 为 0xff0000 起 64KiB，物理 XDATA 32KiB，资格配置保守分配 28KiB；EDATA 栈预留 0x400–0x7ff。声明栈检查不是动态栈溢出保护。ABI4 返回 code 指针仍诊断 error365，可保留普通 ABI。通用符号 DR 立即数的汇编边界尚在，未审计的扩展手写汇编排除。公共 bit ABI、任意 ISR、完整语言合规及其它 MCU 不宣称全面合格。

完整数学既有实板结果 267/268，唯一已知差异是硬件 NaN 分类；不能宣称完整 IEEE754 合规。本次打包没有重新烧录，依赖相同 HEX 的既有实板证据。

## 制作与验证

`tools/Prepare-Mx251ToolRuntime.py` 保留早期 R89 工具链归档的复现流程。当前独立器件包由 `tools/New-Stc251Pack.py` 生成源目录，再交给 `StudioX.Cli pack` 写入格式 1 归档；器件包调整不重打或替换已锁定的编译器组件。工具链保留原 profile 锁、已锁定工具/标准库、原生数学与整数库，并补齐实际部署必需的 `libexec` 预处理器及完整许可证。`cc1.exe` 不在早期资格锁的 163 项内，独立部署必须携带；完整组件索引涵盖所有运行文件。

组件包含自有 PowerShell，用户无需安装 Python。Python 仅用于开发者制作包。配套 `mx251-r89-sources.zip` 保存编译器源码、原生库汇编及构建修订材料。C251 和厂商商业编译器不进入包。

`tools/StudioX.Mx251Validation` 验证格式 1 归档导入、中文/空格路径迁移、真实构建、固定 HEX 等价、错误诊断、失效凭据、内容被改动及取消。`--integration <已有验证目录>` 检查工具准备/健康检查和实际汇编输入在构建中改变后的拒绝发布。基础 IDE 编译仍用 `tools/Build.ps1`，可指定隔离产物目录。

## 工程内存模型

STC251 自 0.1.1 起仅提供“寄存器开发”模板，默认 small。在工程详情 → 编译参数 → 内存模型选择 small / large 后点击保存参数，下一次构建完整应用。该设置直接保存到 mx251.json；源码、ABI、运行库和其它字段不变。旧版 small / large 工程无需重建，恢复默认沿用原创建模板。原生运行库仅资格验证 small，切换为 large 时会明确拒绝不兼容组合。模型不改变芯片的 32 位工作模式。

## 构建分析器

构建成功后解析同次 ASlink MAP/MEM：Flash (CODE)、XDATA、EDATA（含栈预留）。低 256 字节按 MEM 分配图统计，避免 DSEG 汇总跨度、寄存器银行、位变量及 overlay 重复计算；扩展区按地址并集统计。XDATA 使用实际链接上限（当前28KiB，物理32KiB），EDATA当前2KiB包含1KiB栈预留；这些值不是运行时峰值。HEX实际有效字节另在说明中显示，Flash区段内的保留空间计入链接占用。

IDE构建凭据绑定MAP/MEM/入口凭据哈希，失败或输入改变时不显示旧占用。旧构建需重新编译一次才能取得绑定凭据；构建历史自动保存存储区快照并支持比较。ASlink未提供可靠函数长度或逐文件编译耗时，本次不虚构函数/文件贡献及计时；分页XDATA映射无法确认时给出诊断，不保存不完整快照。

## USB 下载与固定运行模式

直接点击工具栏“下载”即可保存、编译并下载。首次连接仅有一个支持的 AI8H2K12G 下载器时自动选用，无需先打开或保存配置页；之后复用已保存的设备。多个下载器未指定目标，或原设备已断开时，在下载流程内弹窗选择，不跳转工程详情；没有设备时就地提示连接 USB1。工程详情的下载设置仍可主动打开，已选择但未保存的设备在点击下载时应用。使用系统 HID 驱动，无需安装 stcgal、Python 或选择 COM。本机 HID 选择按工程保存在用户数据目录，不写入共享工程。small/large 是内存模型，二者下载均固定为 32 位。

当前仅开放既有白名单：34BF:FF0F / MI_00、已验证桥固件、AI8051U-34K64 / BSL 7.4.1U。CPU 32 位保持只读；工程详情中的“内部 IRC 目标频率（MHz）”可设置 1–48 MHz，默认 40，支持如 11.0592 的小数。保存设置或直接下载均使用所填频率，刷新下载器不丢失未保存频率；板未连接时也能保存。每次先编译，再校验本次凭据与 HEX、制作快照、重查设备身份、校准 IRC、写完整固件，最后实际发送已验证的32位硬件配置命令。全部代码块 ACK 后才允许写配置，配置 ACK 后重新进入 ISP 读取核对，才报告下载完成。不存在默认保留8位模式的下载分支。

频率表示分频后的启动系统时钟。校准实测四个 IRC 频段，优先不分频；低频或频段间隙自动选择 1–8 分频，原始振荡目标不超过 48 MHz。实际频率偏离目标超过 0.5%、测量异常或目标不可达时，在擦写前停止。配置回读必须核对频率、调节值、频段、分频与32位选项；日志区分目标和实测值。支持范围不是全温度精度承诺，既有40MHz实板记录也不能冒充所有频率均通过运行验证。

STC251 0.1.3 起提供 `Delay_MS(uint16_t milliseconds)`，包含 AI8051U.h 后即可调用。参数单位 ms，以 1 ms 为基准，范围 0–65535，0 直接返回，不占用定时器。实现作为静态库按需链接，不使用时不增加固件体积。工程详情的 IRC 频率以 `MX251_IRC_HZ` 保存于 mx251.json，同时生成并编译期核对 `MX251_DELAY_TICKS`。频率改变使旧构建凭据失效，直接下载先重新编译；设备选择仍留在本机，频率随工程迁移。

函数在内部 IRC 作为系统时钟、应用未另改 CLKDIV/PLL/IRTRIM/IRCBAND 时适用；临时使用 WTST=0 并恢复原值。固定循环每毫秒量化到最近的4个系统时钟，另有调用开销；IRC误差、中断及其它总线干扰可能延长实际时间。不是精密时序承诺，未完成示波器实测。应用自己切换时钟后必须同步适配，不能继续假定编译频率；串口和用户自写延时不会自动改写，可使用 MX251_IRC_HZ 计算各自参数。

编辑器只对 SDCC `__asm ... __endasm` 做保留位置的 C 分析投影，包含头文件内 NOP 宏和未保存文本；真实编译始终使用原始代码。汇编语义仍由实际编译器/汇编器检查，不压制普通 C 错误。IDE 构建额外检查 naked 函数的已知指令控制流，确定存在跌落到下一个函数的路径时拒绝发布最终固件；这不是任意宏或原始机器码的验证器。普通 C 函数不要使用 __naked。

未知既有硬件选项、8位HEX、其它时钟或原生USB接口拒绝处理；目前不承诺任意8位初始配置都能自动转换。没有证据的选项位不会猜测覆盖。首次使用若提示现有配置不匹配，请使用官方 ISP 将该板设为已验证配置后重试；IDE 不提供自动恢复被擦除选项的通道。

请先关闭官方 ISP 及该板串口监视器。设备使用原 CLI 的进程间 HID 租约，并与 IDE 下载/调试互斥；不宣称阻止不遵守租约的第三方程序。下载覆盖现有程序，可能按硬件选项擦除 EEPROM。中途失败保留原始诊断，不自动重试擦写或运行部分镜像。日志位于 `.build/mx251-isp/latest/transport.ndjson`，记录主机 UTC、原始报文、目标、快照 SHA-256 和阶段。下载 ACK、配置回读、运行命令发送是不同证据；当前无 Flash 回读，也不自动宣称用户程序功能验证通过。
