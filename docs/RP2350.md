# RP2350 C 工程适配

本文记录原 0.1.0 C SDK 与 DAP 验收。0.2.0 保留这些 C 模板并增加独立 MicroPython 工程模式，见 [MicroPython 适配](MICROPYTHON.md)；原 C 固件的实板结论不适用于 MicroPython。

独立器件包 `raspberrypi.rp2350/0.1.0`，基于官方 Pico SDK 2.2.0，复用 IDE 内置 `arm.gnu/1.0.0`（GCC 15.2.Rel1、xPack OpenOCD 0.12.0-7）。工程创建、编译设置、代码提示、DAP 下载和调试使用现有工作台入口。

交付包：`artifacts/packs/RP2350-0.1.0-verified/raspberrypi.rp2350-0.1.0.mcupack`（1,076,867 字节），SHA-256：`912841e7e0b295ebc95b74be8cdd962c88f23801603379b3ca43ca7a9f354ff0`。已导入本机 `%LOCALAPPDATA%/MCUStudioX/packs`。需要本次构建的开发版 IDE；此前发布的 0.2.0 安装包尚未重新封装 RP2350 调试实现。

## 使用范围

新建工程选择「树莓派 · Raspberry Pi」→「RP2350 · Pico SDK C 工程」→「RP2350A · Pico 2 / 兼容板（4 MB Flash）」。这是明确的板型配置：外部 12 MHz 晶振、150 MHz 系统时钟、4 MiB QSPI Flash、520 KiB SRAM（512 KiB 主区及两个 4 KiB scratch 区）。适用于本次连接的立创 Pico 2 兼容板及相同配置的 Pico 2。

| C 模板 | 行为 |
| --- | --- |
| 最小 C 工程 | 内存计数和延时，不初始化外部 GPIO |
| GPIO 闪灯 | GP25 每 500 ms 翻转；兼容板应按原理图修改 `LED_PIN` |
| 双核队列 | Cortex-M33 核 0 发出请求，核 1 计算，使用 SDK 队列同步 |

用户入口均为 `src/main.c`。没有混入 MicroPython 工程、解释器或固件。当前选择 ARM Secure Cortex-M33，不声称支持 Hazard3/RISC-V、Pico 2 W、其他晶振或 Flash 容量的板卡。

## SDK 与构建

包作者通过固定版本 SDK 的 CMake File API 和编译器依赖导出实际 C SDK 源码集，包含启动代码、私有汇编片段、配置头文件和 boot2 校验汇编。保留官方许可、源码和逐文件 SHA-256。普通用户创建工程后直接使用内置 GCC/CMake/Ninja，不需要额外安装 Pico SDK、Python 或 picotool，也不需要联网下载依赖。

收录 pico_stdlib、multicore、queue/sync、rand/unique_id，以及 GPIO、UART、定时器、时钟、ADC、DMA、Flash、I2C、SPI、PIO、PWM、interp、powman、SHA256 等 API 所需的依赖。未使用的函数通过 `--gc-sections` 删除。USB/TinyUSB、无线、FreeRTOS、PIO 汇编生成、UF2 生成、签名和任意外部 Pico CMake 工程导入暂未接入。

编译生成 `.build/firmware.elf/bin/hex/map` 和 `compile_commands.json`。默认应用入口使用 C17、`-Og -g3`；工程编译参数页可以覆盖优化和调试信息。SDK 内部保留官方实现使用的少量 C++ 支持代码，不产生 C++ 用户模板。

包中的 `device/sdk/generated/pico_base/pico/config_autogen.h`、`device/sdk/src/boards/include/boards/pico2.h` 和 `device/linker/rp2350-pico2.ld` 记录固定板型配置。根 CMake 仍用于添加用户源码、包含目录和宏，不调用上游 `pico_sdk_init()`。这是解析后的 SDK 源码包，不是完整 SDK CMake 包装器。

本次同时修正新工程生成器：链接脚本、MAP 和 objcopy 的文件参数使用构建目录中的相对路径，避免 Windows GCC 向 ld 转发绝对中文路径时出现编码问题；不重写已有工程的 CMake。

## 下载与调试

下载选择 DAP-Link (CMSIS-DAP)，默认 1000 kHz，可指定探针序列号。包内目标脚本在加载 `target/rp2350.cfg` 前设置 `SWD_MULTIDROP 1`，这是已连接 WCH CMSIS-DAP 的实际连接要求。脚本检查 RP2350 芯片 ID 和实际 4 MiB Flash 容量，匹配后才擦写映像涉及的页，校验后复位运行；不写 OTP、不自动解除保护。

调试入口只附加并核对当前 ELF，不自动下载。RP2350 的 GDB 内存映射会探测 QSPI，初始阶段保留带备份的 SRAM 工作区；检查目标后禁用算法工作区，让固件比较走主机只读访问。两颗 Cortex-M33 由 OpenOCD SMP 联合暂停，分离时清除 vector catch 并检查两核恢复运行。IDE 当前没有专门的核心选择界面。

## 制作与验证命令

```powershell
python tools/New-Rp2350Pack.py --sdk '<本机 Pico SDK 2.2.0>' --toolset artifacts/tool-runtime/toolsets/arm.gnu/1.0.0 --python '<包作者 Python 可执行文件>' --output artifacts/packs/RP2350-new
dotnet run --project tools/StudioX.DebugValidation -c Release -- --rp2350 '<新包.mcupack>' '<包含 toolsets 和 languages 的 runtime 目录>' '.artifacts/rp2350-check-new'
```

输出目录必须是新目录。SDK 固定提交 `a1438dff1d38bd9c65dbd693f0e5db4b9ae91779`；检测到版本或已跟踪源码被改动时拒绝打包。输出 `vendor/provenance.json` 保存原始文件摘要与必要改动说明，不包含开发机路径。

离线检查已通过三个模板的实际编译、中文及空格路径、优化参数覆盖与恢复、下载/调试准备、OpenOCD `noinit` 目标 ID/Flash 容量拒绝分支、SDK 补全/声明跳转/悬浮信息。记录：`.artifacts/rp2350-validation-4/result.txt`。离线检查不会访问 USB。

硬件验证工具必须显式使用 `--rp2350-hardware`，参数为包、runtime、新输出目录和已授权探针序列号。它先备份并校验完整 4 MiB Flash，再使用生产 BuildService / OpenOcdService / DebugSessionService 测试最小及双核 C 模板，最后恢复涉及的原 Flash 扇区并校验完整备份。不能把工具存在或命令行实验结果等同于本次集成实板通过，实际结果以输出 `result.txt` 和会话日志为准。

## 2026-09-23 集成验收

实板使用用户接入的立创 Pico 2 兼容板 / WCH CMSIS-DAP，SWD 1000 kHz。两个 C 模板均通过 IDE 实际调用的生产下载和调试服务：

- 最小模板在 `main.c:9` 命中硬件断点，`app_counter=0`；逐过程后停在第 10 行，变量变为 1。
- 双核模板在队列接收结果后暂停，`app_counter=1`、`core1_result=4`，核 1 确实完成了计算。
- 两个模板均通过寄存器、源码定位、运行/暂停、复位、暂停时结束、运行时结束和不断电重新附加；结束后两个核心确认运行，再附加时计数器继续增长。
- 完整备份 4,194,304 字节；测试最多涉及前 20,480 字节。恢复原扇区后完整 4 MiB 校验通过，复位运行，调试进程已释放。没有 OTP 写入。

验收确认原 Flash 恢复校验通过，未修改 OTP。原始日志与固件备份保留在本地，不随公开源码或安装包分发。GPIO 闪灯只完成编译检查，未假定兼容板 LED 一定接 GP25，也未进行 RISC-V 或独立核心切换界面测试。

Release 全量编译为 0 警告、0 错误。新建工程页的树莓派图标、三个 C 模板、深浅主题、创建后代码提示及 DAP 配置已通过桌面预览检查，截图在 `.artifacts/rp2350-ui/`。共同生成器改动另经 STM32F103、CH32V307 和 CubeMX 实编回归，见 `.artifacts/rp2350-build-regression/result.txt`。
