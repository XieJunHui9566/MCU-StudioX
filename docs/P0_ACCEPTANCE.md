# P0 本机、Windows 虚拟机验证与独立验收包

本轮目标是开发环境可迁移、组件选装可靠和可信编辑诊断。最初按用户要求完成本机软件验证与可移交的独立验收包，随后用户提供 Windows 11 虚拟机，开始补充实际来宾验收。此前分析配置归属、IDF 响应文件展开、会话刷新和显式重新配置继续保留。

组件修复采用先落盘记录、后替换目录的事务。桌面提供“恢复未完成操作…”及明确的继续/恢复原组件选择，操作前复核内容与租约；未知目录、损坏候选和变化的预览不会覆盖现有内容。原备份和原始异常保留，完成记录移至历史目录。下载进度在刷新到磁盘后报告，完整缓存在使用前仍检查 SHA-256。

验证入口：

```powershell
StudioX.EnvironmentReliabilityValidation.exe --boundaries <新证据目录> <已有ninja.exe>
StudioX.EnvironmentReliabilityValidation.exe --offline <明确plan.json> <新证据目录>
StudioX.EnvironmentReliabilityValidation.exe --offline-resume <同一plan.json> <已有夹具目录>
```

`--boundaries` 验证真实进程终止后的三种目录状态、首次安装恢复、损坏候选拒绝发布、显式恢复原组件、预览失效、取消、独占租约、整体移动和缓存损坏。`--offline` 从空目录导入明确选择的离线归档，核对缺失组件提示、全量哈希和重复导入；用过程内受限 PATH 与无效 IDF/Python 环境变量验证准确解析、真实编译和 clangd，结束恢复过程环境。新旧 IDF 的升级副本真实编译并逐文件证明原工程不变。`--offline-resume` 明确复用同一夹具并核对工程身份，先保存上次日志，不改用其他输入版本。

当前独立载荷选择 ESP-IDF 5.5.4、6.1.0 的 ESP32-C3 hello-world 与 ARM GNU 1.0.0 的 STM32F407ZG HAL 模板。归档、clangd、器件模板来自本机已保存材料，保留许可证、原组件指纹与包身份；不扩展为所有 MCU/SDK 的本轮验收。使用 ZIP 和 7z 两种受支持的离线容器。

`New-P0AcceptanceKit.ps1` 接受五个明确目录参数：`RunnerDirectory`、`DesktopDirectory`、`PluginHostDirectory`、`InputsDirectory`、`OutputDirectory`。前三项须提前自包含发布；最后一项须不存在，输入计划使用相对路径。包内包括 Windows PowerShell 5.1 脚本、CMD 启动器、说明及文件/源码 SHA-256 清单。复制完整目录即可独立运行，不安装全局语言运行环境，不改系统 PATH；可选工作台使用显式验收工具根和独立用户数据。

本机证据位于 `.artifacts/p0-reliability-20261004`，失败的初次日志保留，最终报告列出通过记录、载荷哈希、源码与机器事实。正式产品版本和现有安装不替换，不创建提交或推送；本轮不运行设备连接、固件下载或调试。

2026-10-04 已完成开发工具为空的 Windows 11 虚拟机软件验收。实际基线、完整结果、631 个证据文件的 SHA-256 和来宾清理回执均已核验，最终报告确认 `cleanWindowsVmTested=true`。指定正式安装器的验收已于 2026-10-05 补充，见下文；更多账户/权限/安全软件组合与真实断电仍待后续验收，本轮范围为软件验证。

来宾实际环境为当日安装的 Windows 11 Pro（10.0.26300），VMware 4 核 / 8 GiB。导入前未发现 .NET、GCC、CMake、Ninja、clangd、Git 等开发工具或常见开发目录；Python 命令仅为 WindowsApps 入口。来宾已有 VMware Tools、VC++ 运行库和系统应用，因此本次基线不等同于完全无运行库的裸系统。测试使用已安装 0.2.5.4B 应用核心的同哈希副本，从本地来宾磁盘执行，不修改持久 PATH，不下载 SDK，也不连接硬件。

最终结果：离线环境 25 项、组件恢复 34 项、实时诊断 94 项、真实 WPF 诊断界面 18 项、外设辅助 35 项均通过。IDF 5.5.4 / 6.1.0 与 ARM GNU 的三个基础工程实际编译成功；两版 IDF 分别编译 ESP32-C3 的八种外设生成代码，16 个源码文件通过真实 clangd 诊断，两版外设界面各通过 20 项检查。外设范围为 GPIO、UART、I2C、SPI、ADC oneshot、LEDC PWM、esp_timer 和 RMT TX。

验收曾因来宾 S1 挂起中断。VMware 恢复失败原文为 `Could not create anonymous paging file for 8192 MB`，宿主当时可用内存提交额度约 5.3 GiB；保存并核验 VMX、VMSS、VMEM 后撤回无效的单台虚拟机内存后备配置，未修改宿主分页文件。用户恢复宿主资源后，原挂起状态成功恢复，续跑完成全部软件检查；失败日志与恢复审计保留。

Windows PowerShell 5.1 的修复包括 UTF-8 BOM / JSON 编码、相同载荷跳过和只读文件替换、显式加载两个压缩程序集，以及 SDK 长路径清理。清理只作用于明确的私有目录，不跟随链接；长度统计失败不阻止清理，已删除来宾 ZIP 的续跑须重新核验宿主证据，完成回执支持重复执行。实际清理入口在本机 5.1 下验证了长路径、只读文件、删除中断、重复完成和损坏证据拒绝，随后在来宾成功完成。全量离线校验与编译时限为 90 分钟，临时电源请求结束即释放，不修改持久电源设置。

交付与证据位于 `.artifacts/clean-windows-vm-20261004`：`validation-report.json`、`guest-exchange/guest-evidence.zip`、`current-acceptance-overlay.zip` 和 `Expand-CurrentAcceptanceKit.ps1`。原验收包的 11,347 个文件全量哈希通过，原包未改写；463 个更新载荷作为独立补丁归档，可在新目录重建当前验收包。来宾测试目录和临时 ZIP 已清除，三项临时共享已撤销，虚拟机及 VMware Tools 保持运行；宿主构建、暂存、测试夹具和恢复备份共 5,428,187,455 字节已清理。来宾此前中断删除的字节数不作估算，保留最小审计记录、原始证据和可复用验收包。
