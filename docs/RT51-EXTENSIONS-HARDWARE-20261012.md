# RT51 扩展功能 IAP15F2K61S2 实板验收

2026-10-12（北京时间）。用户明确要求下载后，在同一块 CT107D V3.1 蓝桥杯板完成
普通 ISP 写入、60 秒连续接收及用户确认 S2 断电上电后的 30 秒接收。两轮均通过。
这是周期延时、挂起/恢复、软件定时器和统计快照的新增实板证据；
此前基础内核的记录仍保留在 [基础验收](RT51-HARDWARE-20261012.md)。

## 目标与下载

- COM5 / CH340C；ISP 实际识别 IAP15F2K61S2、F449、61 KiB Flash、BSL 7.2.5S，
  UID `F44902204670E9`。
- 使用当前 IDE 内置 `studiox-stcgal-guard.py` 的相同副本，核对精确型号、容量和固件
  SHA-256。完整写入结束、选项设置及成功标记均收到，进程退出码 0；未进行 Flash 字节回读。
- 普通 ISP 覆盖此前 RT51 用户程序，内部 RC 校准到 12 MHz，其余已读取选项写回；
  EEPROM 擦除选项关闭，未单独写 EEPROM。本次没有制作仿真芯片或使用 Mon51。
- 验收仍只使用 UART1 默认 P3.0/P3.1、Timer2 和用户提供的 Timer0 tick 回调；
  不驱动 P0/P2 外设锁存总线、继电器、电机、蜂鸣器或板上 EEPROM。
- 接收器 115200/8N1，DTR/RTS 关闭；两轮发送字节均为 0，结束后串口关闭。

固件为 `.artifacts/rt51-extensions-hardware-20261012/firmware/rt51-extensions-ct107d.hex`，
SHA-256：`09315BF8074D7D4FFD7EB53F380234F87B412B41F9C9A6B3BADE98052BF2F19E`。
SDCC 4.5.0 #15242，`--model-large --stack-auto --int-long-reent --float-reent`；
CODE 地址跨度 15,174 B、HEX 有效数据 15,165 B、XRAM 713 B。
普通 ISP 按最高地址补齐并填充到 15,360 B。XRAM 为 0001..02C9，CODE 最高 3B45，
均在当前用户区约束内。任务硬件栈仍为 80..FF / 128 B，内核工作栈 30..7F / 80 B，
每任务 XRAM 保存上下文上限 96 B。

内核源码、接口和 STC15 XINIT 适配与 `stc.stc8 / 0.1.5` 模板逐文件哈希一致。
本轮扩展了 `tests/iap15_hardware.c`，没有为实板结果改动内核。0.1.5 的现有包及 SDK
归档保持不变，其中的验收说明记录的是创建归档时的离线状态；本报告是后续补充证据。
IDE 产品版本仍为 0.2.6.13，未替换安装版或发布 GitHub。

## 实板检查

3 个用户任务和空闲任务继续覆盖抢占、队列/事件/信号量、互斥锁优先级继承、有限超时、
重入 32 位算术、ISR 唤醒、EA 恢复和 tick 回绕。新增检查为：

- 生产任务用 `rt51_delay_until` 保持 20 tick 周期，记录逾期；初始 tick 为 FFF0，
  启动即覆盖回绕，热接收期间又跨过一次 16 位计数回绕。
- 启动阶段暂停已释放锁的低优先级计算任务，读取 SUSPENDED 快照，经过 2 tick 后确认
  32 位计算计数没有变化，再恢复该任务并确认后续计算持续进展。
- 注册 50 tick 周期和 30 tick 单次静态定时器，由高优先级消费任务派发。
  检查单次回调恰好一次、周期回调持续增加、积压未溢出。
- 回调检查 EA=1、当前任务身份、context 指针；阻塞请求返回 CONTEXT，
  嵌套 dispatch 返回 BUSY，错误计数保持 0。
- 在同一个应用临界区内读取全部任务和内核快照，检查任务 tick 采样之和等于内核
  tick 增量、任务派发次数之和等于切换数，并检查栈预算与故障。
  UART 报告稍后形成，不能把其中采样总数与报告 tick 误当成同一瞬间的值。
- 初始化诊断仍读取 XRAM 的 `FEDCBA98`，商 65259、余数 43613；
  未用 main 手动重设变量，验证单 DPTR 启动适配在重启后继续有效。

## 证据与边界

原始证据位于 `.artifacts/rt51-extensions-hardware-20261012/`：
`download.log`、`download-exit-code.txt`、HEX / map / mem / 编译与仿真日志、
`hot-run/`、`cold-run/`、`source-snapshot/` 及 `hardware-verification.json`。
收据锁定固件、源码、原始串口字节和结果文件 SHA-256，保留 PC UTC、PC 单调计时及
MCU tick 的独立来源。当前验收固件留在板上运行，COM5 已释放。

这只是本型号、ABI、12 MHz、任务布局及当前负载下的功能验收；没有长期压力测试、
示波器级 ISR 延迟或最坏切换时间测量。栈峰值是在保存时观测的值，不保证捕获全部瞬时
峰值；tick 采样不等于精确 CPU 用时。RT51 在 Mon51 下仍只完成离线构建，
不能把本次独立 UART 运行扩大为其他型号、Keil C51 或所有负载的实板支持。
