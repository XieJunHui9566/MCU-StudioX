# FreeRTOS 调试

## 使用

启动支持的工程调试并暂停目标，打开底部「调试 → RTOS」，或菜单「调试 → FreeRTOS 状态」。窗口复用现有 GDB 会话的 ELF 符号、类型和目标内存，不调用 `uxTaskGetSystemState()`、`vPortGetHeapStats()` 等目标函数，不写内存，也不额外连接探针。普通裸机工程显示内核不可读取，不补造任务。

| 区域 | 可读取内容 |
| --- | --- |
| 调度器 | Tick、启动状态、挂起嵌套次数、当前 TCB、任务总数 |
| 任务 | 名称、TCB、状态、当前/基础优先级、栈地址和保存的栈指针；字段完整时显示记录栈容量、未使用填充区及累计运行计数 |
| 堆 | 标准 `heap_4` / `heap_5` 中可读的容量、当前/历史最小空闲量、最大空闲块、空闲块数及分配/释放次数 |
| 对象 | 注册队列及以队列实现的信号量/互斥量，包含计数/容量、单项大小、等待任务数、可读的持有者与递归次数 |
| 读取诊断 | 缺失符号、不可读字段、读取失败或暂时不一致的原始原因 |

未注册的全局句柄可在对象页输入，如 `sensorQueue` 或 `app.busMutex`。仅接受 C 标识符及点分隔成员路径，不执行函数、指针表达式或任意地址。没有注册表或对象列表为空，不能说明工程没有同步对象。

只在暂停状态读取；运行中保留标明过时的快照，结束、断开或切换工程后清空。断点停在内核链表或堆更新中间时，计数可能暂时不一致；可单步退出更新后复读，不能仅据此判定损坏。取消读取在当前 MI 响应完整返回后停止后续查询；继续、单步和结束也会取消后续读取。

## 固件准备

保留内核 C 文件的 `-g` 信息，调试优先采用 `-Og` 或 `-O0`；LTO、strip 或优化可能隐藏必要静态符号和类型。无需移除 `static`。`-g3` 可保留栈方向、填充条件等宏，便于判断水位扫描条件；无法确认时水位保持空值。

以下选项按内核版本和工程内存预算选择，IDE 不自动修改固件：

```c
/* 保留对象类型和任务栈填充证据。 */
#define configUSE_TRACE_FACILITY             1
/* 保留可供调试器读取的任务栈边界。 */
#define configRECORD_STACK_HIGH_ADDRESS      1
/* 按对象数量预算注册表空间。 */
#define configQUEUE_REGISTRY_SIZE            16
```

创建对象后调用 `vQueueAddToRegistry(sensorQueue, "sensorQueue")`；名称需要足够长的存储期，如字符串字面量。未保留对象类型字段时可能只能识别为通用信号量；普通队列与队列集合不能唯一辨别时会标明诊断。累计运行计数依赖固件正确配置 `configGENERATE_RUN_TIME_STATS` 及计时源，不直接代表毫秒或 CPU 百分比。

栈填充扫描是历史使用线索，不能保证没有溢出；记录容量受端口对齐影响，不等于实际分配大小。TCB 中的保存栈指针不能替代当前任务的硬件 SP。未知字段显示空值，不显示为零；堆数据不包含 libc malloc、静态对象或独立静态栈。

## MCP

内置 Agent 与外部 `StudioX.Cli mcp` 共用只读 `debug_rtos_snapshot`，可传 `objectSymbols` 补充未注册句柄：

```json
{"objectSymbols": ["sensorQueue", "app.busMutex"]}
```

工具要求当前工程已有暂停会话，返回 `snapshot`、`hardware`、`simulated` 和证据说明。读取不匹配的工程或已变化的会话会被拒绝。`snapshot.isAvailable=false` 或字段为 `null` 时应先读 `diagnostics`，不可推断成零或空内核。

## 已完成的实板观测

以下结果取自 2026-09-26 已完成的实际 MCP 会话；公开说明只整理结果，没有再次连接硬件。

### STM32F407ZG / ST-Link

在板上映像与 ELF 校验一致的 LVGL 固件上读取 FreeRTOS V10.3.1。三项任务为 IDLE（Running，优先级 0）、lvgl 和 Tmr Svc（Blocked，优先级 2）；当前/基础优先级一致。`Running` 只标记内核选择的 TCB，暂停的 CPU 本身没有继续执行。

`heap_4` 容量 32768 字节，当前空闲、历史最低和最大空闲块均为 22520 字节，空闲块 1，成功分配/释放 7/0。注册队列 TmrQ 的计数/容量为 0/10，单项 12 字节，等待发送/接收为 0/1。继续后再次暂停，Tick 增加 219；退出后确认恢复运行及探针释放。

此固件缺少栈末地址、运行时间计数及队列类型字段，栈容量/栈水位/运行计数保持空值；此板观测不包含信号量或互斥量的细分类型验收。

### CH32V307VCT6 / WCH-LinkE

使用由官方模板生成并补充观察配置的 7984 字节独立验收固件，明确授权后下载并完整校验，读取 FreeRTOS V10.4.6。

| 任务 | 状态 | 当前/基础优先级 | TCB 记录栈容量 | 未使用填充区 |
| --- | --- | --- | --- | --- |
| IDLE | Running | 0/0 | 500 字节 | 360 字节 |
| task200 | Blocked | 2/2 | 500 字节 | 344 字节 |
| task500 | Blocked | 2/2 | 500 字节 | 344 字节 |

`heap_4` 容量 12288 字节，当前空闲、历史最低和最大空闲块均为 9856 字节，空闲块 1，成功分配/释放 11/0。注册队列计数/容量 2/4、单项 4 字节；二值信号量 1/1，计数信号量 3/5；普通和递归互斥量均为 1/1、未持有、递归次数 0。所有对象发送/接收等待数为 0。继续后复读 Tick 增加 95，退出后确认恢复运行及探针释放。

初次使用不匹配 ELF 时发现 WCH OpenOCD 输出字节差异却返回 MI `done`。产品修复后正确拒绝该附加；成功验收来自随后明确选定并校验一致的试验固件，不采用最初无效快照。运行计数未配置，保持空值。

### 验证边界

Tick 变化证明暂停之间计数实际变化，不是调度时序、等待精度或 CPU 使用率验收。未实板测试持有/递归加锁、优先级继承、同步争用、堆碎片变化、死锁、SMP、CH32V307RCT6/WCU6 或其它芯片/内核版本。

`heap_1`、`heap_2`、libc `heap_3`、自定义分配器及裁剪/改名内核不属于完整支持范围。软件定时器、事件组和流/消息缓冲区不自动枚举；不提供任意任务寄存器恢复、调用栈切换、持续执行轨迹或确定的死锁判定。演示数据明确标记离线，不能作为实板证据。

## 软件验证

近期内核离线检查 25 项、映像输出检查 12 项、辅助程序检查 8 项，共 45 项通过。离线内核检查构造小型静态 ELF，交由实际 ARM/WCH GDB 解释 DWARF 类型；它不是运行中的 FreeRTOS。相关工具为 `StudioX.RtosValidation`、`StudioX.DebugValidation` 的映像校验检查及 `StudioX.RtosHardwareValidation --self-test`；硬件辅助程序只有显式硬件模式才连接。
