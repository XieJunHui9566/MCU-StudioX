## 窗口布局

- 工具菜单按工程与构建、开发环境组件、串口与波形、Git 与协作、插件与扩展分组。开发环境组件统一提供管理、按工程准备、GitHub 获取、本地导入和当前工程校验入口；管理页提供醒目的启用/禁用和删除按钮，并遵循透明背景设置。

- “帮助”菜单提供离线帮助手册、快速开始、快捷键速查和详细故障处理，F1 随时打开。手册支持分类、全文搜索、关联主题和复制；内容与验证入口见 [离线帮助中心](USER_HELP.md)。
- 欢迎页与帮助菜单提供七步交互式[第一个工程引导](FIRST_PROJECT_GUIDE.md)，连接真实创建、健康检查、保存、编译与输出入口。首次无工程时自动展示，结束后记住偏好，仍可手动返回。完成状态依据本次工程操作，修改源码会清除旧编译成功标记。

- 自定义标题栏和原生窗口缩放、菜单栏、常用操作工具栏。
- 顶部工具栏的「新建、打开、保存、编译、下载、调试、停止、外观」常驻中文标签与矢量图标；编译使用绿色代码构建符号，不使用 emoji。工程名称过长时省略显示，悬停可看全名。
- 最大化使用窗口所在屏幕的工作区，避免状态栏和日志末行落入任务栏后方。原生边界以物理像素计算，保留还原窗口和系统缩放行为，不通过固定底部留白补偿。
- 左侧工具条和可调整宽度的工程窗口；工程树按需读取真实目录，按 C、H、C++、汇编、链接脚本、CMake、JSON、XML/SVD 等类型显示矢量图标，文件夹区分展开/收起。
- 左侧功能栏的「AG32 引脚分配」打开图形引脚与时钟配置页，仅在已核实的 AG32 工程中显示；关闭工程或切换到其它厂商工程后隐藏。具体步骤见 [AG32 引脚映射与逻辑](AG32_LOGIC_MODE.md)。
- 工程树与编辑标签的文件图标使用稍高饱和度的金色文件夹、蓝色 C、紫色 H 和三色 CMake，轻微增强填充；浅色主题仍降低亮度以保持对比。
- 中央文档区：欢迎页、多文件源码标签、器件与模板、串口与波形、扩展管理。标签都有 X 关闭按钮，较多时单行横向滚动，选中标签自动滚入视野。
- 底部构建/设备输出，可调整高度和隐藏。
- 欢迎页提供新建、打开、导包、最近工程、外观和工具入口。未打开过工程时显示真实空状态，不填充演示项目。
- 最近打开的工程保存在用户目录。切换文件保留未保存内容；关闭文件、切换工程或退出时检查对应文件的修改并询问保存。取消批量关闭保留全部内存文档，保存失败也保留原标签。
- 启动先读取最近工程记录并显示首页，不等待历史工程磁盘，也不遍历/校验器件仓库。首帧之后后台检查就绪的本地固定磁盘，工程目录或 `.studiox/project.json` 已删除时从最近工程记录中移除；断开的磁盘、移动盘和网络共享不自动删除。回到欢迎页或重新激活窗口时会再次检查；点击最近工程时也复查，已删除的工程直接从列表移除，不中断当前工程。进入新建/导入器件包页面时，才在后台读取轻量器件目录；创建工程前只完整校验选中的包。现有工程打开和首页加载不等待其它器件包。
- 「文件 → 关闭工程」、工程栏标题右侧 X 或 `Ctrl+Shift+W` 关闭当前工程并回到欢迎页。先确认全部未保存文件，取消或保存失败保留工程；确认后清空资源树、源码标签、构建输出、工程/器件/开发环境组件信息及导航历史，停止当前工程的 clangd，禁用编译和下载。磁盘文件与最近工程记录保留。构建/下载等操作进行时不能关闭工程，应先停止或等待完成。
- 启动恢复遵循最近一次无工程状态，不回退打开旧工程；上次本地工程已删除时停留开始页，工程按钮保持禁用，草稿归档保留，不跳转故障处理或首次工程引导。工程仍存在但格式损坏时继续显示原始诊断。具体恢复边界见 [工程编辑工作区](EDITOR_WORKSPACE.md#退出与恢复)。
- 「新建工程」先执行相同的关闭流程，再显示空资源栏和重新开始的器件选择。取消关闭则停留在原工程。

窗口边界检查：`--preview-window-layout <output-directory>` 在隔离窗口中检查普通、最大化和还原状态，以及两种输出面板高度下的构建/设备日志末行，输出像素边界记录和截图。窗口会短暂出现在主屏；不打开用户工程或执行构建、下载。

启动性能回归：`dotnet run --project tools/StudioX.StartupValidation -c Release -- <用户数据目录> <新输出目录>`。真实用户数据只读；在新输出目录生成隔离包，检查目录读取、工程创建、SDK 修改/缺失/新增文件拦截、清单修改、过期选择和取消。

## 新建工程

新建工程列表对同一包 ID 显示已安装的最新版本，并显示版本号；较旧版本保留供已有工程追溯。导入旧版本不会让新建工程降级。

新建工程按「器件厂商 → 器件包 → 芯片型号 → 起始模板」逐级选择。厂商来自已安装包的 `vendor`，未选厂商时不展示器件包；切换厂商清空包、型号、搜索和模板，后续选项随选择启用。导入包后自动定位到对应厂商和包，仍由用户明确选择芯片和模板。已发布 STM32 包的 `STMicroelectronics / StudioX templates` 在选择器中统一显示为 `STMicroelectronics`，包文件本身保持不变；其他厂商按清单显示。

厂商选择框和下拉列表显示商标与中文名：AGM「遨格芯」、ST「意法半导体」、WCH「沁恒微电子」，悬停显示英文名；已打开工程的信息页共用同一份厂商图标。商标作为本地资源随软件内置，保持原色与比例，深浅主题均可见；未知厂商保留清单原名。商标来源和权属见 `licenses/Manufacturer-Logos-NOTICE.md`。

界面预览可用 `--preview-stm32 <output-directory> <STM32.mcupack> <AG32.mcupack>`，在隔离目录检查跨厂商筛选、选择清理和导入定位，并保存选择器截图。

## 编译与下载

构建日志末行显示「编译成功，退出代码：0」或「编译失败，退出代码：实际数值」；CMake 配置/构建和固件大小检查使用各自真实进程结果，超时另行标注。工具尚未启动、校验失败等无法获得退出码的异常显示「不可用」，原始诊断仍保留。内置下载流程在进入下载前也输出编译结论。

F7 保存修改并调用内置工具编译。带 `openOcd` 配置的器件包会启用工具栏下载按钮及「构建 → 下载固件…」。对话框列出该器件支持的烧录器、速度和序列号；用户点击「编译并下载」后才启动硬件流程。失败时显示原始 OpenOCD 诊断，不自动换协议、解锁或整片擦除。当前 STM32F407 提供 HAL/SPL/HAL+FreeRTOS/SPL+FreeRTOS 四种模板，描述中标明 8 MHz / 168 MHz 默认时钟。

## 输出颜色与构建进度

构建输出在日志内显示终端风格的字符进度条，例如 `[进度] 校验开发环境组件 stc.sdcc / 1.0.0 [=======>----------------] 30% (3,167/10,512)`。同一组件校验在原行刷新，完成后保留一行结果；没有独立的图形进度栏。组件校验仍对完整文件索引进行哈希，全部核对成功后才报告 100%。Ninja 的 `[完成/总数]` 和 CMake 的 `[百分比%]` 更新当前编译阶段的字符条，没有测量值时使用移动字符表示活动，不编造百分比。无计数的准备步骤复用活动行，有计数的阶段切换后保留最后一行；最终成功、失败或取消取实际操作结果，并在输出中显示颜色与耗时。

构建与设备输出复用只读 AvalonEdit 日志视图：阶段信息为主题强调色，成功绿色，警告黄色，错误红色，宿主时间戳使用弱化文字色。深浅主题分别使用可读的诊断配色。仍可全选、复制、滚动和 Ctrl+滚轮缩放；长路径可在构建页换行显示。普通工具行和诊断插入活动进度行之前，刷新进度不会覆盖警告、错误或文件名。工具输出块按完整行呈现并保留尾部片段，显示缓冲有上限且截断可见，引擎的原始构建日志独立保存，不受显示合并影响。

这套呈现覆盖公共构建服务的各工具链（SDCC、ARM/RISC-V GCC、ESP-IDF 等），以及 CubeMX/工程健康检查的独立 CMake 配置、AGM 引脚映射、升级副本验证、RTL testbench 仿真和 Verilog 综合。PC/LVGL 预览使用同一字符条格式及彩色日志组件，在自身诊断区合并重复的组件进度，保留原始快照与诊断。

`--preview-build-output <新输出目录> <已有 C 工程> <已有 runtime>` 在隔离副本内真实编译，检查警告/失败原始输出、实际字形颜色、阶段进度、取消、跨块 CRLF、复制及字体缩放，并验证独立配置成功与失败；ARM 用例额外运行内置 Icarus 和 Yosys。不访问硬件或更改安装版。窗口布局检查继续覆盖两个日志页的末行可见与最大化边界。

## 工程树文件操作

目录读取在后台执行，节点分批呈现；折叠再展开复用当前节点。外部新增或删除文件用 `F5` 刷新，取消不会缓存部分目录。大工程与 IDF 打开过程的测量见 [大工程性能](LARGE_PROJECT_PERFORMANCE.md)。

- 右键首先选中鼠标下的文件/文件夹；空白区菜单以工程根目录为目标，也支持键盘菜单键。菜单提供打开/展开、新建文件、新建文件夹、复制、粘贴、重命名、复制完整路径、复制相对路径、在 Windows 资源管理器中显示、刷新。
- 新建或粘贴到选中文件夹；选中文件时使用其父目录。新建文件自动打开；刷新保留展开目录并定位结果。`Ctrl+C` / `Ctrl+V` 仅在树获得焦点时处理文件，编辑器中仍复制粘贴文本；`F2` 重命名，`Enter` 打开或展开/折叠，`F5` 刷新。
- 使用 Windows 文件剪贴板，可从系统资源管理器复制多个文件/文件夹。复制使用已保存的磁盘内容；粘贴始终创建副本，不移动来源。同名项使用「 - 副本」编号，绝不覆盖已有文件。批量复制先暂存，取消或失败清理本次新副本；支持二进制文件及空目录，拒绝链接和复制目录到它自身的子目录。
- 重命名支持文件、目录及仅改变大小写。已打开的子文件同步路径、标签、文件图标、语法类型和导航历史，保留原文档、未保存内容、撤销记录及光标；之后保存使用新路径。主目录或 `main.c` 改名后仍能重新打开工程。新建、粘贴、重命名完成后更新语言索引；不会自动修改 CMake 或 `#include` 中引用的路径。
- 工程根目录、`.studiox`、`.git`、器件清单及生成的内部 CMake 配置禁止在树内改名，其祖先目录也受保护；路径名称与同名冲突由应用服务检查。名称对话框跟随主题并提示非法名称。
- 检查入口：`dotnet "src/StudioX.Desktop/bin/Debug/net10.0-windows/MCU StudioX.dll" --preview-explorer <output-directory> <AG32-project-directory>`。只在输出目录的工程副本内操作，覆盖深浅菜单、重命名与保存、未保存文档/撤销/光标/导航、新建及副本定位、缺少原 `src/main.c` 时重新打开工程；不改写用户工程或剪贴板。

## 源代码编辑

- 通用工程编辑新增 Ctrl+Shift+F / Ctrl+Shift+H 工程搜索替换、C/C++ 的 Shift+F12 引用与 F2 语义重命名、实时错误波浪线与问题列表、重启恢复源码标签及草稿。预览修改、批量撤销、磁盘冲突与恢复边界见 [工程编辑工作区](EDITOR_WORKSPACE.md)。
- 编辑菜单和编辑器右键菜单均提供「查找」「替换」「全部替换（当前文件）」。`Ctrl+F` / `Ctrl+H` 打开面板，`F3` / `Shift+F3` 前后查找并循环定位，`Esc` 关闭面板。支持大小写、Unicode 全词和正则，正则替换支持 `$1` / `${name}`；先计算完整替换计划，非法表达式、超时或超限不做部分修改。全部替换是一组撤销操作；只改当前编辑缓冲区，不自动保存。只读文件可以查找，不能替换。
- Python / MicroPython 的 `F12`、`Ctrl+F12`、`Shift+F12` 与右键菜单使用独立静态导航，不依赖 clangd。工程内定义和显式导入可跳转，引用列表双击定位；MicroPython 固定 API 使用只读声明文档，支持 `Alt+←` 返回。完整范围见 [Python 编辑](PYTHON_EDITOR.md)。

- 鼠标位于编辑区时，`Ctrl+滚轮` 调整字号（10–28 px，每格 1 px），保留源码、光标和撤销记录，字号串行保存到用户偏好。普通滚轮仍滚动文档；高精度滚轮的小增量会累积。底部构建/设备输出也支持相同手势，日志字号仅作用于当前窗口。
- 全局 `WindowMouseWheel` 为主窗口及设置等子窗口统一接入滚轮，覆盖代码、日志、资源树、欢迎/新建页、器件列表和下拉列表。普通滚动和 Ctrl 缩放均优先读取 Windows `WM_MOUSEWHEEL` 自带的 `MK_CONTROL` 和鼠标位置，完成当前显示器 DPI 换算；窗口和 ScrollViewer 级 WPF 事件作为后备。滚动鼠标下方最近的可滚动容器，内层到边界后交给外层，只有横向滚动条的标签栏则横向滚动；无需先点击抢焦点，保留系统每格行数/整页设置及高精度滚轮累积。视图菜单还提供「编辑器字号 → 放大 / 缩小 / 恢复默认字号」。
- `--preview-project <output-directory> <project-directory>` 使用隔离工程副本，经窗口消息入口检查 Ctrl+滚轮导致实际文字行高变化、反向/高精度滚轮、普通滚轮和保存偏好，并检查关闭时取消/放弃/保存/保存冲突、清空工作区、语言服务重启与新建工程入口；不构建或访问硬件。

- 编辑区使用 AvalonEdit 6.3.1.120；C/C++、CMake、汇编、链接脚本、JSON、XML/SVD 随文件类型切换语法配色，支持深浅主题。注释、关键字、内置类型、函数形式的标识符、普通标识符、宏形式的常量、字符串、数字使用不同颜色。
- C/C++、CMake、链接脚本及 JSON 中成对的 `{}`、`()`、`[]` 按嵌套深度循环使用六种颜色，同一对保持同色，未配对括号保留原色；忽略注释、字符串、字符常量、C++ 原始字符串及 CMake 长括号字面量。配色随深浅主题切换，兼容字体柔光与编译错误波浪线。编辑后延迟 120 ms 在后台分析，切换文件丢弃旧结果，滚动只处理可见行，不修改源码或撤销记录。
- `--preview-brackets <output-directory> <project-directory>` 检查括号配对、字面量排除、编辑/撤销/快速切换、深浅主题的实际字形颜色；只读工程，不编译或连接硬件。
- 配色使用词法规则；代码提示、悬停、导航、引用及重命名独立接入 clangd 语义分析。实时分析标注“实时 · clangd”，构建诊断来自实际 GCC/CMake 输出，保留独立来源和原始日志。
- 编辑区上方提供「撤销」「重做」按钮，无记录或只读时禁用；`Ctrl+Z` 撤销，`Ctrl+Y` / `Ctrl+Shift+Z` 重做。每个文件保留独立撤销栈。
- `Ctrl+/` 切换选中行的注释（未选择时处理当前行），编辑菜单和右键菜单也有入口。C/C++ 使用 `//`，CMake 使用 `#`；保留缩进和空行，选区结束在下一行行首时不处理下一行。全部已注释时取消注释，否则整批加注释；整次操作可一次撤销。其他语言及只读文件不启用。

## 构建分析器

工程资源栏底部显示可折叠的构建分析器，沿用工作台透明背景。每个 ELF 目标显示实际构建配置、各区域的容量、链接分配量和百分比；悬停可查看精确字节、剩余空间及起始地址。80% / 95% 分别使用黄色 / 红色提示。超过容量时保留实际百分比，进度条最多填满；零容量显示横线。

AG32 成功联合构建后，在存储区下方增加 FPGA 逻辑单元 (LE) 数量和百分比，数量及容量均取自 Supra 资源统计。按“已用 / 总量 个”显示；缺少统计显示未知，真实零占用显示 0%，不混用 LUT/寄存器之和或位流字节数。

区域名和容量读取 GNU ld MAP 的 `Memory Configuration` 表，包含自定义内存区，不根据型号、模板或 `.ioc` 猜测。ELF 的 PT_LOAD VMA 统计 RAM/BSS/NOLOAD/堆栈预留，LMA 的文件内容统计初始化数据在 Flash 的副本；同一区域合并实际分配区间，保留段内对齐、排除独立加载段之间的空闲空间，并避免重叠区间重复计数。不把 BSS 的加载地址当成 Flash 内容。固定在 RAM 顶部的栈不再让整个 RAM 被算满；旧统计缓存会自动重算。界面明确是上次成功构建的链接分配量，不代表运行时峰值；修改代码需要重新编译。

支持 StudioX 工程及 CubeMX 的多目标产物，MAP 须与 ELF 同名同目录。暂不支持的大端 ELF、重叠 MEMORY 别名、缺失 MAP 等显示原因，不伪造百分比、不影响固件构建成功状态。现有结果保存在 `.build/studiox-memory.json`，绑定工程记录及 ELF/MAP 长度和时间戳；打开工程只读这些明确路径，不扫描 SDK 或运行开发环境组件。实际编译开始时清除缓存，失败/取消不显示旧结果；单独 CMake 配置保留上次成功构建统计。关闭或切换工程清空当前视图。

离线验证：`tools/StudioX.BuildMemoryValidation` 覆盖 VMA/LMA、BSS、空洞、零起始地址、独立 CCM、自定义区域、错误输入与缓存失效。`--preview-memory <new-output> <F407-project>` 在隔离副本中检查实际编译、失败、关闭和重开，不连接硬件。
