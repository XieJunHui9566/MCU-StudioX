# 文字串口终端

入口：工具 → 串口终端、左侧终端图标、欢迎页「串口终端」。不依赖当前工程；可在工程编辑和串口页面之间切换，关闭串口标签会停止定时发送并释放连接。

## 串口参数

- COM 端口刷新；预设或自定义波特率 50–4000000，实际可用值由 USB 串口硬件和驱动决定。
- 5/6/7/8 数据位，1/1.5/2 停止位，None/Odd/Even/Mark/Space 校验。拒绝不合法的数据位/停止位组合。
- 无流控、RTS/CTS、XON/XOFF、两者组合；硬件流控时 RTS 交给驱动管理，不同时手动驱动 RTS。
- 手动 DTR/RTS，CTS/DSR/DCD 状态读取。输出信号默认关闭，启动时不恢复为已断言状态，不自动连接任何端口。
- 连接后锁定基础串口参数，断开后可修改。发送超时显示“可能部分发送”，不自动重试；掉线停止定时发送。

## 编码、发送和显示

- 接收和发送分别选择 UTF-8、GB2312 / GBK（Windows 代码页 936）或 HEX。接收 Decoder 保留跨分片的半个字符；发送遇到无法编码的字符明确报错，避免静默变成问号。
- HEX 接受 `01 A5 00 FF`、连续十六进制及 `0x` 前缀，支持空白/逗号等分隔；半字节或非法字符拒绝发送。每次最多 64 KiB。
- 发送末尾可选无、CRLF、LF、CR；Ctrl+Enter 发送。可选转义 `\r \n \t \0 \e \xHH \\`。转义先作为字符解释再按所选编码发送；需要任意原始字节时使用 HEX。
- ANSI 显示支持 SGR 16 色、256 色、RGB 前景/背景、粗体、斜体、下划线、反色及复位，保留跨分片转义序列。支持 CR/LF、退格、Tab、部分光标移动、行/屏清除及位置保存恢复；适合彩色 Logo、日志、进度行。
- 这不是完整 VT/xterm 仿真：不实现 alternate screen、终端查询回复、鼠标协议、OSC 剪贴板/链接/窗口命令、完整 CJK 宽字符终端栅格。收到 OSC/DCS 等非显示字符串会忽略，不执行设备文本中的命令。
- 关闭 ANSI 时显示可见的 `\x1B`，适合排查转义字节；HEX 为原始字节展示。颜色和文本内容来自串口数据，不执行任何代码。
- 显示 2000 行，每行最多 512 个 UTF-16 字符（到达边界换行）。ASCII Logo 推荐默认等宽字体。Ctrl+滚轮调整终端字号，Ctrl+F 搜索，Ctrl+C 复制选区。
- 鼠标位于输出区时普通滚轮上下滚动，无需先点击获取焦点。上滚查看历史会暂时取消自动跟随，滚回底部或重新勾选「自动滚动」恢复跟随；手动取消的自动滚动不会擅自恢复。持续接收时保留阅读位置和水平滚动位置。
- 接收区、发送框和定时间隔输入框复用编辑器的半透明表面；使用图片或视频背景时可透出背景，并跟随全局背景模糊设置。文字与 ANSI 颜色保持不透明，不对文本本身做模糊处理。

## 辅助功能与缓存

- 新增「协议解析」视图，支持 Modbus RTU 和用户 JavaScript 脚本、离线输入、CRC 补全及解析导出，详见 [串口协议解析](SERIAL-PROTOCOLS.md)。解析使用原始字节，不受本页显示编码影响。

- 自动滚动、暂停/恢复显示、时间戳、发送回显、RX/TX 字节计数与重置、30 条发送历史、定时发送（20 ms–1 小时）。暂停只冻结画面，后台仍接收；达到缓存上限时旧内容会淘汰。
- 时间戳为宿主读取数据的 UTC 时间，界面转换成本地时间；不能用于测量线上精确字节间隔。TX 计数表示完整提交给串口驱动的字节，不能代替对端 ACK。
- 原始收发缓存最多 2 MiB / 16384 个记录，达到任意上限淘汰最旧记录并显示淘汰字节数；慢观察者丢帧单独计数。显示缓存与原始缓存分别有界。
- 切换显示编码从保留的原始历史重建；缓存头部若恰好落在多字节字符或 ANSI 序列中间，开头可能出现替换字符/失去此前颜色，后续完整序列恢复。
- 清空显示同时清空历史缓存，保留字节计数。导出 TXT 为带宿主时间戳的当前显示文本（UTF-8），BIN 为保留的原始 RX 字节，JSONL 为保留的 RX/TX、时间、连接边界及 Base64 字节。导出不包含已经淘汰的旧数据。
- 设置保存在用户数据目录 `serial.json`；仅保存参数、编码/显示偏好及发送历史，不保存连接状态、自动发送状态或已断言 DTR/RTS。

## 实现与验证

- `StudioX.Devices/SerialTransport` 使用 Microsoft `System.IO.Ports` 10.0.12，后台有限超时读取/发送；DeviceHub 保证连接唯一，首个订阅建立后开始读取，避免丢启动首包。
- `StudioX.Application/Serial` 负责连接用例、连续解码、ANSI 状态、原始历史与导出；Desktop 仅调用服务，150 ms 合并刷新可见终端，关闭和断开释放会话。端口拔出不会自动重新发送旧命令。
- `dotnet run --project tools/StudioX.SerialChecks`：编码、非法输入、跨包 ANSI/中文、颜色复位、CR/退格、OSC 忽略、缓存上限、首包、单一所有者、二进制发送、模式重建、原始/JSONL 导出、断开/重连、模拟掉线及控制输出偏好。
- 已通过基础编译及 45 项后台检查。用户恢复联调后，F407 / ST-Link / COM15 的真实 IDE 界面验收已完成，详见 [实机验收记录](F407-SERIAL-ACCEPTANCE-20260922.md)。已验证 UTF-8/GB2312/HEX 双向收发、ANSI 彩色、115200/57600 切换、定时发送、暂停、导出及关闭标签后重连；其他硬件参数组合仍按记录中的边界处理。

## EXPLORER F407 测试准备

验收时使用 `examples/F407-Serial-Terminal` 测试工程。该工程及其复制的 SDK 已按用户要求清理；需要追溯时可从清理前提交 `6e480b7` 恢复。原板固件、实际测试固件副本和验收日志的归档位置见 [开发产物清理记录](DEVELOPMENT-CLEANUP-20260922.md)。

依据用户原理图 `EXPLORER_V3.5.pdf`（图内标题标 V3.4），PA9/PA10 通过 P10 跳帽连接板载 CH340；枚举发现 USB-SERIAL CH340 (COM15)。该板 RTS/DTR 接 RESET/BOOT0，而非 USART RTS/CTS；因此默认无流控、DTR/RTS 关闭，硬件流控需要另外接出相应引脚才能实测。

2026-09-22 已通过真实 IDE 完成上述主要收发流程，并保存烧录前 1 MiB Flash 备份。`.burst` 的 2000 行、100000 字节连续日志在界面导出的原始 BIN 中逐行核对一致。实际 USB 拔插、其他串口参数组合和 RTS/CTS 接线验证仍待具备对应条件时进行。
