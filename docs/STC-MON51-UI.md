# STC Mon51 调试界面

已接入原生 C# 后端和 WPF 界面。当前实板范围为 **IAP15F2K61S2 / Mon51 V2.5 / CH340C / 115200 8N1**；型号由用户确认，监控握手只能核对版本。Desktop 调用应用服务，串口由 DeviceHub 单一所有者管理。

## 入口和源码调试流程

本次原生制作和冷启动复测见 [实板验收](STC-MON51-SETUP-ACCEPTANCE-20261009.md)。冷启动上下文 PC=0 时，会话先通过监控命令映射到 DBFD 用户跳板并保持暂停，避免直接运行物理监控入口；已有非零 PC 的热连接保留原位置。

入口是顶部 **调试菜单 → 启动调试**、工具栏 **调试**，快捷键 **Ctrl+F5**。先打开两步窗口，选择准确型号与串口；不会在开窗时编译或连接。第一步直接选择器件包提供的 **Mon51 2.5.0 · stc.stc8 / 0.1.2** 并点击「设置为仿真芯片」，IDE 校验并下载包内监控固件，无需 AiCube、STC-ISP 或其他外部程序。写入应答成功后必须断电上电并勾选确认。已制作且监控生效的芯片可跳过制作。第二步「开始调试」自动保存、编译最新源码、通过 Mon51 更新用户区，回读核对并加载 CDB 后保持暂停。窗口显示本次程序大小和 BIN 哈希，失败可重试或取消；不再提供附加/下载模式切换。

监控资源可以来自独立安装的兼容器件包，不迁移旧工程的编译包/工具锁定。只在唯一候选或工程锁定包提供固件时默认选择；多个候选要求明确选择。缺少包内固件时制作按钮禁用，提示通过 IDE 导入兼容 `.mcupack`；已经制作的目标仍可勾选确认并调试。选择后包被改变、镜像损坏、路径越界或型号/ISP 版本不符都在擦写前拒绝。

顶部 **下载** 始终自动准备普通构建并执行原有 STC ISP 下载流程，不启动调试。调试构建强制标准 CDB、保留监控内存；普通下载恢复该工作流保存的编译信息/容量偏好。普通 ISP 不能保证保留仿真监控，之后可能需重新制作并断电上电。新原生制作入口仅限定 IAP15F2K61S2 / ISP 7.2.5S / 状态尾字节 70；已在 COM18 / CH340C 实板通过原生制作、制作后上电握手、188 字节程序更新、源码断点及单步。实板检查通过应用服务执行，WPF 交互另用协议夹具验证，不视为实际 GUI 操作验收。固件来源、专用编码写入及功能边界见 [监控固件调查](STC-MON51-FIRMWARE.md)。

使用 CH340 等普通转串口工具制作仿真芯片后，必须给目标 MCU 本体断电后再上电，仿真功能才生效；软件连接成功提示、关闭串口或按复位键不能替代这个步骤。官方 Link1D / USB 转双串口工具带有自动断电上电电路时，由该工具完成这一步。此要求来自用户提供的 STC-ISP 仿真页提示；截图只确认所选 IAP15F2K61S2、串口仿真及 P3.0/P3.1，未显示制作成功结果、监控波特率或时钟频率。其它 STC32/AI32/AI8 型号的提示不能用于推断本芯片的资源或固件要求。

1. 打开 IAP15F2K61S2 的 STC SDCC 工程，点击「调试」，选择型号和串口。
2. 需要制作时，第一步会覆盖用户程序及监控，按专用 ISP 流程写回选项/时钟参数；制作后给 MCU 本体断电约 2 秒再上电。已配置过且监控生效时，只需勾选确认。低优化可按工程选择；工作流保留用户优化档位，低优化只关闭列出的 SDCC 优化，不等同于 GCC 的 `-O0`。
3. 点击「开始调试」，自动保存和编译，强制标准 CDB、CODE ≤56317 字节、XDATA ≤1024 字节。编译失败不连接芯片、不复用旧构建。原生 Mon51 下载单独擦除用户程序、写正文、最后单独写三字节 LJMP 复位向量；完整回读用户二进制和 DBFD 跳板后停在逻辑复位入口。监控生效后用户更新不需重新上电；编译容量限制不会安装或保护芯片中的监控程序。
4. 应用服务核对器件/包/工具组件身份、构建时的源码指纹及 HEX/CDB 哈希，再逐段回读目标 CODE；匹配后启用源码调试。失败时显示原因并保留地址调试。只有文件存在、PC 命中或串口 ACK 均不足以启用源码映射。
5. 底部「源码 · 观察 · 调用栈」提供观察、局部变量、调用栈、源码断点和反汇编。加载按钮只读取当前工程构建回执，不能把任意 CDB 强行对应到板上固件。CDB 的纯文件名依据回执中实际编译来源匹配；同名模板不参与映射，多个实际来源同名时明确拒绝。会话期间源码被外部改变后，继续/源码步进将明确拒绝。

保存的源码断点请求在未核对符号时显示空心标记和具体原因，只有已绑定、已启用的断点显示实心。缺失构建回执、缺失 CDB、源码改变或目标固件不一致会直接显示在调试面板。存在已启用但未绑定的源码请求时，「运行」明确拒绝且保持暂停；若只需地址调试，可在源码断点表禁用或删除这些请求。

## 内存、断点和恢复

- 用户 CODE 可读 0000–DBFF；源码构建/普通 PC/软件断点避开 DBFD–DBFF 跳板及 DC00–F3FF 监控区。断点还避开最初 3 字节复位向量。
- 用户 XDATA 0000–03FF；0400–06FF 为监控保留区。P3.0/P3.1 用于监控串口。
- 用户程序不得向 P3.0/P3.1 写数据或使用相关中断、定时器时钟输出与外部计数功能。STC-ISP 提示监控不占用串口 1；用户串口 1 如需使用，应按该准确型号资料改接可用引脚，当前连接适配未验证用户串口并行运行。
- 同时最多 16 个不同地址的断点，包含内部临时断点。超限源码偏好显示未绑定原因；增加内部返回断点需要预留名额。临时 A5 改写涉及 Flash 寿命。
- 仅暂停时允许读取/编辑。其它 SFR 在内存窗口中明确选择读取，可能产生外设副作用；自动变量观察仅使用已知保存寄存器上下文。
- 恢复记录位于独立用户数据 `debug/mon51-recovery/`，按目标/连接保存。写入 A5 前保存原字节，恢复回读成功后删除对应记录；恢复失败保留日志并使目标保持暂停，不能假报成功或自动续跑。
- 下载在擦除前保存 `debug/mon51-download-recovery/` 记录；取消、超时或写入/回读失败不续跑，释放串口并保留记录。后续普通附加不能绕过；明确重新下载完整固件并核对成功后才清除。用户程序擦除单独等待最多 8 秒，其它普通命令仍为 2 秒。实板擦除约 2.5 秒，首轮 2 秒超时及擦除后全 FF 回读均保留为失败证据。
- 原始 TX/RX 位于 `debug/mon51-logs/`，标明宿主 UTC。校验错误、超时和接收溢出可观察。串口终端/下载/采集与调试不能同时拥有该串口。
