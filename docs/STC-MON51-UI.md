# STC Mon51 调试界面

2026-10-21：新增 IAP15L2K61S2 / Mon51 V2.5 的软件适配，见 [L 型号说明](STC-MON51-IAP15L2K61S2.md)。包含独立制作镜像、调试构建及源码调试流程；L 的本轮实板记录见 [验收报告](STC-IAP15L2K61S2-ACCEPTANCE-20261021.md)，下文旧硬件记录仍仅属于 F 型号。

已接入原生 C# 后端和 WPF 界面。F/L 两型号的既有实板验收分别记录，不互相替代；下文早期记录对应 **IAP15F2K61S2 / Mon51 V2.5 / CH340C / 115200 8N1**。型号由工程声明并在监控制作的 ISP 会话中核对，Mon51 握手本身只能核对版本。Desktop 调用应用服务，串口由 DeviceHub 单一所有者管理。

## 入口和源码调试流程

本次原生制作和冷启动复测见 [实板验收](STC-MON51-SETUP-ACCEPTANCE-20261009.md)。冷启动上下文 PC=0 时，会话先通过监控命令映射到 DBFD 用户跳板并保持暂停，避免直接运行物理监控入口；已有非零 PC 的热连接保留原位置。

入口是顶部 **调试菜单 → 启动调试**、工具栏 **调试**，快捷键 **Ctrl+F5**。2026-10-31 起不再弹出独立 Mon51 连接/制作窗口。IAP15F2K61S2 和 IAP15L2K61S2 均直接复用 **器件与模板 → STC 串口下载与时钟** 中已保存的下载串口及传输波特率；未选择串口时跳到该设置位置，修改尚未保存时提示先保存。

工程能力按准确型号判断；其它 STC 型号的调试按钮和启动菜单禁用，悬停说明当前支持的两个型号，Ctrl+F5 不会启动。源码断点边栏和断点编辑同步停用，编译及 ISP 下载仍可使用。直接调用调试命令也会在保存源码或修改工程设置前拒绝，不尝试握手或制作监控。

调试入口先检查编译参数草稿（优化方式、调试信息、Flash 容量和 Mon51 预设）。尚未保存或输入无效时保留表单，定位到编译参数并提示保存或修正；此时不重载工程、不自动保存源码、不改写编译配置，也不编译或连接串口。即使还没选择下载串口，也先保护编译草稿。保存后再次调试，才按已保存参数准备 Mon51 构建。

1. 先在选定串口尝试 Mon51 同步和 V2.5 版本握手；冷启动先 `80/80/hello`，运行中附加仅在首次 hello 超时后暂停重试。握手成功后自动编译最新源码，通过同一连接更新用户区、完整回读并加载 CDB，直接进入调试面板并保持暂停。
2. **只有版本握手超时或版本不匹配**才自动制作工程准确型号的监控。串口占用、串口断开/接收失败、取消、恢复记录未处理、握手后寄存器读取失败、编译失败及用户区更新失败都保留原始错误，不转入监控制作。失败启动释放连接而不续跑目标程序。
3. 制作前先释放调试串口，由 DeviceHub 单独预留给 ISP；按工程器件选择包内专用编码镜像，F/L 固件不能互换。优先工程锁定包；其它兼容候选的固件必须具有同一已核对型号散列，因此可确定性选择同镜像资源，无需版本选择弹窗。缺少固件时提示导入兼容器件包，不启动 ISP，也不要求安装外部软件。监控包不会迁移工程编译包或工具锁定。
4. 输出区第一次提示 **给 MCU 断电再上电，进入 ISP 下载模式**。在工具开始等待后操作。制作仍只接受准确型号、ISP 7.2.5S、状态尾字节 70，以及固定镜像散列；在本次 ISP 会话中核对后才能擦写。制作覆盖用户程序和监控，保留读取的选项及当前时钟来源；RC 重新校准的既有约束不变。传输使用已保存的下载波特率，监控使用同一波特率同步；目前实板速率证据仍仅为 115200，其它速率通过离线参数路径验证。
5. 只有完整制作成功应答后，输出区才第二次提示 **给 MCU 本体断电约 2 秒再上电**：这是仿真固件激活要求，复位键不能代替。随后本次调试结束，串口释放；用户重新上电后再次点击调试。不会在制作完成后自动重连或下载用户程序。下次握手成功再执行第 1 步。

监控制作与普通烧录共用输出区的逐行解析、字符进度条、耗时及成功/警告/错误颜色。专用写入脚本只在块应答通过后推进字节数，不显示原生 tqdm 样式；到达 100% 后仍等待最终应答和实际报告。取消、失败和迟到回调不会误报成功或重新启动活动进度。

调试构建强制标准 CDB、CODE ≤56317 字节、XDATA ≤1024 字节，保留末尾监控区及 DBFD–DBFF 复位跳板。编译失败不擦除用户程序；HEX/CDB/源码/包/工具指纹匹配和完整代码读回后才启用源码断点。监控需要 P3.0/P3.1；用户程序仍须避开监控使用的引脚、INT4 和定时器 2 资源。低优化不等同于 GCC `-O0`。

顶部 **下载** 保持普通 STC ISP 流程，不启动调试；它会恢复工作流保存的普通编译容量/调试信息偏好。普通 ISP 可能覆盖监控，后续点击调试按上面的握手/自动制作流程恢复。制作镜像及编码协议见 [监控固件调查](STC-MON51-FIRMWARE.md)，既有实板证据见 [F 制作验收](STC-MON51-SETUP-ACCEPTANCE-20261009.md) 与 [L 验收](STC-IAP15L2K61S2-ACCEPTANCE-20261021.md)。本次改动的协议、编译和 WPF 流程验证为离线验证，没有新增实板验收。

## 源码符号与断点

底部「源码 · 观察 · 调用栈」提供观察、局部变量、调用栈、源码断点和反汇编。加载按钮只读取当前工程构建回执，不能把任意 CDB 强行对应到板上固件。CDB 的纯文件名依据回执中实际编译来源匹配；同名模板不参与映射，多个实际来源同名时明确拒绝。会话期间源码被外部改变后，继续/源码步进将明确拒绝。

保存的源码断点请求在未核对符号时显示空心标记和具体原因，只有已绑定、已启用的断点显示实心。缺失构建回执、缺失 CDB、源码改变或目标固件不一致会直接显示在调试面板。存在已启用但未绑定的源码请求时，「运行」明确拒绝且保持暂停；若只需地址调试，可在源码断点表禁用或删除这些请求。

## 历史连接诊断

以下保留 2026-10-09 的旧版流程与故障证据；当前自动制作、上电提示与入口行为以上文 2026-10-31 流程为准。

2026-10-09 初期截图来自旧安装目录，没有新入口；随后按用户要求制作并安装 0.2.6.12，新入口已在正式安装目录核对。`--acceptance-workbench <已有 runtime> <独立用户数据> <工程目录>` 仍可用于隔离工作台检查。

连接失败或取消后可在同一窗口修改参数并重试。零接收超时明确显示「未收到任何应答」，与收到不完整/校验错误的应答分开；原始日志保留波特率、串口线路参数、TX/RX 和超时统计。没有应答时先核对供电、端口、监控波特率、接线和芯片仿真配置；软件不会因此自动下载、修改芯片配置或反复尝试其它波特率。

2026-10-09 COM18 故障复核：只读 ISP 已识别 IAP15F2K61S2、BSL 7.2.5S，标称时钟读数 11,062,800 Hz；BSL 版本不是 Mon51 版本，芯片识别成功也不能证明监控程序存在。原生后端和独立接收实现均未获得有效 Mon51 V2.5 握手；初期零接收，随后收到过单字节 FE。用户随后同意并报告已在 STC-ISP 中重新设置仿真芯片；重设后原生附加、跳过初始暂停的握手及有限串口参数对比仍为零接收，90 秒上电同步等待也未收到同步字节。该等待期间是否实际完成上电尚待用户确认，不能据此证明监控程序在冷启动时也不响应。原始证据保存在 `.artifacts/mon51-com18-diagnostic-20261009/`。IDE 和诊断探针没有擦除、固件下载或芯片配置写入；用户手动恢复操作单独记录，未确认监控程序是否曾被覆盖。此前 17 项成功验收覆盖已连接监控下的执行和恢复，不能用来宣称本次重新上电后的连接已通过。

随后恢复情况：用户提供 STC-ISP 的重新上电要求，并确认再次上电；COM18 / 115200 的原生 C# 握手返回 V2.5。回读前 216 字节为 `81 57 F0` 加 213 个 FF，DBFD 跳板也是 `81 57 F0`，与此前选定的计数程序不匹配。最初独立探针恢复该未核对代码运行后，重连再次没有应答；这只证明该次运行后的状态，不能把最初所有失败归结为同一原因。按照既有的 216 字节固件授权，通过 Mon51 用户程序擦除/下载通道恢复原选定固件并逐字节回读；未使用普通 ISP，也未发送监控区地址或芯片配置写入命令。原生后端随后 14 项地址调试验收通过，包括逻辑复位、原生指令单步、真实 A8 断点、RAM counter=1、连续运行后暂停、原指令恢复、结束及重新连接，固件哈希一致。结果见 [COM18 恢复验收](../.artifacts/mon51-com18-diagnostic-20261009/native-hardware-recovered/result.json)。但用户随后确认断电上电后，原生附加和跳过初始暂停的握手均再次零接收；[冷启动失败结果](../.artifacts/mon51-com18-diagnostic-20261009/native-hardware-after-cold-power/result.json) 单独保存。下载流程的持久启动条件仍未查清，不将 14 项热调试通过当成冷启动验收或完整恢复。源码映射未在本次 14 项验收中重新测试。连接窗口的连接/取消按钮固定在底部，资源说明可滚动查看；18 项离线界面检查通过。

## 已接入能力

历史冷启动失败随后定位到首次连接顺序：所有失败的冷启动原生附加都先发了暂停帧，之后的无暂停重试不能作为独立冷启动对照。单独写复位向量仍失败；再次上电后第一条操作直接发送 `80/80/hello`，得到 V2.5，216 字节代码完整匹配。客户端已改为首次先同步，只有 hello 超时才暂停重试；已经连接的会话继续使用正常暂停顺序。用户再次上电后，修正版 14 项冷启动实机检查通过，另一次热调试也通过，结束时完整代码恢复、程序运行、串口释放。[修正版冷启动验收](../.artifacts/mon51-com18-diagnostic-20261009/native-synchronize-first-cold/result.json)、[热调试验收](../.artifacts/mon51-com18-diagnostic-20261009/native-synchronize-first-warm/result.json)。两次验收均未重新下载或修改芯片配置；本次未重新验收源码映射或其它芯片型号。

Mon51 是实机监控调试，不是外围硬件模拟器。GDB 专用外设描述、RTOS、GDB 插件和对应采集入口在此会话中隐藏；Keil OMF/其它 Mon51 版本尚未适配。

## 内存、断点和恢复

- 用户 CODE 可读 0000–DBFF；源码构建/普通 PC/软件断点避开 DBFD–DBFF 跳板及 DC00–F3FF 监控区。断点还避开最初 3 字节复位向量。
- 用户 XDATA 0000–03FF；0400–06FF 为监控保留区。P3.0/P3.1 用于监控串口。
- 用户程序不得向 P3.0/P3.1 写数据或使用相关中断、定时器时钟输出与外部计数功能。STC-ISP 提示监控不占用串口 1；用户串口 1 如需使用，应按该准确型号资料改接可用引脚，当前连接适配未验证用户串口并行运行。
- 同时最多 16 个不同地址的断点，包含内部临时断点。超限源码偏好显示未绑定原因；增加内部返回断点需要预留名额。临时 A5 改写涉及 Flash 寿命。
- 仅暂停时允许读取/编辑。其它 SFR 在内存窗口中明确选择读取，可能产生外设副作用；自动变量观察仅使用已知保存寄存器上下文。
- 恢复记录位于独立用户数据 `debug/mon51-recovery/`，按目标/连接保存。写入 A5 前保存原字节，恢复回读成功后删除对应记录；恢复失败保留日志并使目标保持暂停，不能假报成功或自动续跑。
- 下载在擦除前保存 `debug/mon51-download-recovery/` 记录；取消、超时或写入/回读失败不续跑，释放串口并保留记录。后续普通附加不能绕过；明确重新下载完整固件并核对成功后才清除。用户程序擦除单独等待最多 8 秒，其它普通命令仍为 2 秒。实板擦除约 2.5 秒，首轮 2 秒超时及擦除后全 FF 回读均保留为失败证据。
- 原始 TX/RX 位于 `debug/mon51-logs/`，标明宿主 UTC。校验错误、超时和接收溢出可观察。串口终端/下载/采集与调试不能同时拥有该串口。

## 验证与实板证据

`tools/Build.ps1` 构建；`StudioX.Mon51Validation <新输出目录>` 检查协议、分片校验、状态机、恢复失败、CDB/真实编译类型记录、指令、源码操作及表达式。夹具只返回协议数据和指定 PC，不执行 CPU 或外设。`--built-symbols <隔离工程> <输出目录>` 检查真实 SDCC 构建产物和源码/CDB/器件/编译设置改变后的拒绝行为。

`StudioX.Mon51Validation --launch-offline <stc.stc8 包> <工具 runtime> <新输出目录>` 检查 F/L 两型号的共用串口/波特率、握手优先、自动制作、两次上电提示、制作后退出、错误分支、产物租约及真实 SDCC 构建。ISP 执行使用夹具，不打开串口或写入硬件。`MonitorGuardChecks.py` 检查专用编码包与 ACK/型号/版本门禁，以及下载波特率转发。
