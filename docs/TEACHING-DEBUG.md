# 与 MCU StudioX / Keil5 联动调试

联调对象是本电脑“单片机示教平台”中的 STC89C52RC 软件模型。实际的 STC89C52RC 没有因此获得硬件单步能力，也不需要向实物烧录 IAP15 监控固件。

## MCU StudioX

1. 先打开支持联调的“单片机示教平台”，保持运行。
2. 在 MCU StudioX 打开 STC89C52RC 的 SDCC 工程。工具栏会显示“示教平台调试”，提示需要本电脑运行示教平台。
3. 点击该入口。StudioX 保存源码、启用调试信息并编译，将本次固件载入模拟板，初始停在程序入口。
4. 在源码设置断点，再使用继续、暂停、单步进入、单步跳过和变量/寄存器窗口。
5. 结束调试后，模拟板保持暂停。命名管道断开时自动恢复临时断点并释放控制权。

此连接不使用串口。无需选择 COM181 或配置 IAP15 监控资源；工程仍使用 STC89C52RC 的完整 8 KiB 程序区。首次连接失败时先检查示教平台是否已经打开；不会自动转为真实芯片下载。

## Keil5（C51）

1. 使用 STC89C52RC 的 C51 工程，开启 `Options for Target → Output → Debug Information`。不要为此把芯片改成 IAP15，也不需要预留实体监控程序区。
2. 打开示教平台，在“下载 → 联动调试”查看 **Keil 仿真串口**。本机为 **COM183**，另一端 COM184 由示教平台持有；其他电脑以页面实际显示为准。
3. Keil 的 `Options for Target → Debug` 右侧选择 `Use: STC Monitor-51 Driver`，勾选 `Load Application at Startup`。进入右侧 **Settings**，选择页面显示的 Keil 仿真串口、波特率 **115200**，依次确认两个设置窗口。参数应在 Settings 中保存，不填入底部的 CPU / Driver DLL Parameter。
4. 若列表没有 STC Monitor-51 Driver，通过 STC 官方工具提供的“添加型号和头文件到 Keil”安装其 C51 调试驱动。此安装包不附带或修改 Keil / STC 的专有驱动。本轮实际联调使用驱动 **1.19**。
5. 编译工程，然后按 **Ctrl+F5** 开始调试。用 **F9** 设置源码断点，**F5** 继续，**F11** 单步进入，**F10** 单步跳过，工具栏 Stop 暂停，Reset CPU 返回用户启动入口。
6. 按 Ctrl+F5 退出 Keil 调试后，在示教平台点击 **结束联调**，将控制权交回板面或 StudioX。原厂串口协议没有可靠的退出会话消息，串口空闲也可能只是用户正在观察暂停状态，因此不以空闲超时自动抢回控制。

Keil 在刚载入或 Reset CPU 后可能显示 `PC=0xDBFD`。这是兼容原厂监控驱动的启动入口别名；下一步回到真实用户代码。模拟 CPU 仍从 0 地址执行，未增加 IAP15 内存或监控固件。Reset CPU 与原厂驱动一致，返回程序入口；要完整重新上电、复位外设，请先结束联调再操作板面。

## 串口和功能边界

| 连接 | 本机示例 | 用途 |
| --- | --- | --- |
| StudioX 联调 | 同用户本机管道 | 源码调试，不占用 COM |
| 下载 / UART | COM181 ↔ COM182 | AiCube / STC-ISP 下载，或串口助手与模拟固件收发 |
| Keil 联调 | COM183 ↔ COM184 | 专用仿真调试，与下载 / UART 分开 |

安装器自动配置两对空闲虚拟串口，已有配置原样复用。旧便携版升级后可以从“下载”页创建独立仿真串口；需先有有效的下载端口对。端口创建失败的诊断保留在安装日志中，不关闭 Windows 的安全设置。

同一时间只允许一个 IDE 控制模拟 CPU。联调期间禁止另外载入固件、通过 ISP 覆盖程序或从板面强行运行/复位；UART 和板面按键仍可参与实验。暂停时 CPU、定时器和板载外设的模拟时钟一起暂停。断点、运行、单步均操作正在显示的这块模拟板。

模型仍限 8 KiB CODE 和 256 字节 XDATA；Keil 的空白反汇编窗口允许读取程序区之外的占位字节，但不能在其中下载或执行用户程序。不要将 IAP15 的专有外设、内存容量或真实板调试能力套用到当前模型。高优化代码可能有源码行合并或变量不可见，教学调试建议先降低优化。

## 本轮验证

2026-11-16：实际 Keil5 + STC Monitor-51 1.19 + 已登记虚拟串口完成自动载入、指令和 C 源码单步、源码断点、变量读取、继续、暂停及返回入口。独立 C51 验证程序的 counter 从 0 变为 1，执行 `P1 = ~counter` 后 A 为 FE；调用栈显示 main → increment。

StudioX 验证使用实际 SDCC 编译、CDB 源码映射、同用户命名管道和同一 CPU 模型，覆盖程序读回、源码断点、单步、变量、P1 引脚、暂停时钟、排他控制和断开后的断点恢复。以上为电脑软件联调，不是实板验证。
