# 工程编辑工作区

这些能力属于通用 IDE 编辑基础设施，与 AG32 或其它器件系列无关，随 0.2.5.3 提供。使用隔离的通用 Arm 工程和内置 clangd 验证，不连接设备、不下载固件、不更改系统 PATH，也不安装全局工具。

## 使用入口

代码模板使用 `Ctrl+Alt+T` 打开管理，编辑菜单和源码右键菜单提供“将选区保存为代码模板…”。输入缩写后 `Ctrl+Space` 调用，支持当前语言的个人、工程与内置模板；离线模板不依赖 clangd。详细格式与验证见 [CODE_TEMPLATES.md](CODE_TEMPLATES.md)。

| 操作 | 入口 | 行为 |
|---|---|---|
| 工程查找 | 编辑菜单 / Ctrl+Shift+F | 搜索当前工程，使用已打开文件的未保存内容 |
| 工程替换 | 编辑菜单 / Ctrl+Shift+H | 预览匹配位置与修改前后文本，勾选文件后应用 |
| C/C++ 查找引用 | 符号右键 / Shift+F12 | 使用 clangd 语义索引，列表双击定位 |
| C/C++ 重命名 | 符号右键 / 编辑菜单 / F2 | 输入名称，审阅跨文件计划，整体应用语义修改 |
| 实时错误 | 源码波浪线 / 视图 → 问题列表 | 输入后约 450 ms 开始分析，显示错误、警告、来源和位置 |
| 恢复编辑现场 | 正常启动时自动恢复 | 最近工程、源码标签顺序、当前源码、光标、选区、滚动与未保存内容 |

当前文件的 Ctrl+F / Ctrl+H、F3 / Shift+F3 和全部替换继续保留。C/C++ 的 F2 只在源码上下文重命名符号；工程树中的 F2 仍然重命名文件。

## 搜索、替换与重命名

工程搜索支持大小写、全词、正则及捕获组替换。包含和排除规则以分号分隔，可填写 `*.c;*.h`、`src/**`、`tests/**`。默认忽略版本库、构建输出、缓存和环境目录；`device` 支持目录默认不搜索，可手动勾选。二进制、不支持编码和链接会跳过，原因写入构建日志；系统生成的只读文件可搜索，不能应用修改。

预览同时展示匹配位置及修改前后文本。应用前重新检查所有选中文件的磁盘哈希和编辑快照，任何过期、只读或路径问题使整批计划停止。修改进入编辑器，Ctrl+Shift+S 才保存至源码文件；每个文件可一次 Ctrl+Z 撤销，也可在预览页撤销整批修改。整批撤销前若某个文件又被编辑或关闭，会拒绝覆盖后续编辑。

语义重命名使用 clangd 返回的声明、定义与引用编辑，保留无关的同名局部变量；不会用文本替换模拟符号重命名。当前接受 ASCII C/C++ 标识符。目标超出工程、只读、包含文件操作、快照或原标识符不匹配时拒绝整批应用。宏、复杂模板等范围取决于 clangd 支持；索引未就绪或拒绝时保留原始诊断。

为避免极端输入阻塞界面，一次搜索最多检查 10,000 个文件、返回 10,000 处匹配和 500 个匹配文件，修改前后文本合计不超过 32 Mi 字符；超限明确报错。单文件遵循文件服务 4 MiB 读取限制。预览文本超过 200,000 字符时只截短展示，实际计划仍完整保存。

## 实时诊断

使用 IDE 内置 clangd 和当前工程分析参数，不执行后台固件编译。诊断绑定工程实例、文档版本与 UTF-16 位置；修改依赖后刷新相关文档，过期返回不套用到新文本。问题列表区分“实时 · clangd”和“构建”；同文件已有匹配快照的实时结果时优先显示它，原始编译日志始终保留。

问题列表和源码诊断悬停同时显示中文释义与工具原文；常见 clangd / GCC 诊断在本机匹配中文规则，不调用在线翻译。未知诊断明确提示“暂未收录中文释义”，不推测工具含义。错误使用红色“错误 Error”标识，警告使用琥珀色“警告 Warning”标识，随深浅主题调整；选中行后仍保留颜色，复制说明会包含两种文本。长说明自动换行，原始诊断、快速修复信息及构建日志保持完整。显示验证入口为 `--preview-diagnostics <output>`，不创建工程或连接设备。

本轮实时诊断和语义重命名面向 C/C++。Python / MicroPython 继续使用既有高亮、补全和静态导航；没有在本轮宣称具备 Python 类型诊断。实时分析不能替代实际编译器与链接器检查。

## 退出与恢复

编辑现场在独立用户数据目录 `editor-sessions/<实例>/state.json` 原子保存，约每两秒记录一次，正常关闭等待最后一次写入。正常退出无需逐个确认源码草稿；手动关闭标签、切换工程仍按原有保存/放弃/取消选择处理。AG32 图形配置等工具文档不属于源码草稿，继续使用各自的关闭流程。

每个运行实例独占租约，另一实例不会接管其草稿。无显式打开参数的启动会恢复最近可接管的工程；`--open` 优先使用指定工程。未保存内容与原磁盘哈希一同恢复，外部修改会提示冲突并阻止直接覆盖；原文件已删除时仍恢复草稿，用户保存时才重建。若磁盘已保存同一草稿，恢复为干净文档。

保存源码与保存恢复记录是不同操作：恢复不会自动写源码。断电/强制退出可能损失最近约两秒尚未记录的编辑；写入失败会在状态栏与日志提示。恢复保存最多 1,000 个源码标签、32 Mi 字符草稿与基线；超过范围需先保存或关闭部分文件。撤销栈、工具页运行会话和设备连接不跨重启恢复。

## 验证

`StudioX.slnx` 包含 `tools/StudioX.WorkspaceEditingValidation`。运行时传入内置 runtime 目录与新的独立输出目录：

```powershell
dotnet run --project tools/StudioX.WorkspaceEditingValidation -- <runtime-directory> <new-output-directory>
```

验证包括脏缓冲区搜索、过期计划、取消、正则、UTF-16、路径边界、实例租约、删除/外部修改/二进制替换后的草稿恢复，以及真实 clangd 的跨文件引用、同名变量隔离与多文档诊断。

实际 WPF 回归先运行 `MCU StudioX.exe --preview-workspace-editor <ui-output> <test-output>/semantic-project`，再用同一个 `ui-output` 运行 `--preview-editor-recovery`，在两个独立进程验证重启恢复。生成深浅主题、语义重命名、实时错误和恢复截图；使用专用用户目录，不操作当前用户工程或设备。


## 开发效率与工作台

| 操作 | 入口 | 说明 |
|---|---|---|
| 格式化文件 | 编辑菜单、右键、Ctrl+Alt+F | 使用内置 clangd，遵循工程格式规则，先预览再应用 |
| 格式化选区 | 编辑菜单、右键 | 格式器可能调整相邻语句，差异页显示实际范围 |
| 快捷修复 | 编辑菜单、右键、Alt+Enter（也支持 Ctrl+.） | 在错误所在行获取 clangd 修复，选择后预览；标点键被输入法占用时使用 Alt+Enter |
| 快速打开 | Ctrl+P | 按名称或相对路径筛选，跳过产物和链接 |
| 工程符号 | Ctrl+T | 搜索 clangd 工程符号，选中后跳到定义 |
| 命令面板 | Ctrl+Shift+P | 检索菜单、编辑器和已启用插件命令，显示当前可用状态 |
| 本地历史 | 编辑菜单、右键、命令面板 | 选择时间点，比较修改前后，审阅后恢复为未保存内容 |
| 编辑分组 | 视图菜单、Ctrl+Alt+Right | 将活动文档移到另一个分组；可拖动标签跨分组和调整顺序 |
| 合并分组 | 视图菜单、命令面板 | 保留每个文档内容及各自撤销栈 |
| 开发环境组件 | 工具菜单、命令面板 | 版本、空间、工程依赖、哈希校验、离线导出与修复 |
| 故障处理 | 帮助菜单、命令面板、操作失败时 | 显示具体处理步骤、操作入口及原始诊断 |

大工程的异步文件树、快开窗口内复用扫描和 IDF 后台统计说明见 [大工程性能](LARGE_PROJECT_PERFORMANCE.md)。外部文件变化后，工程树按 `F5` 刷新，快开窗口关闭后重新打开；不会持久化可能过期的文件名索引。

格式化和快捷修复目前针对 C/C++。修复只接受当前文件的直接文本编辑，不执行语言服务任意命令或文件操作；多文件修复会明确拒绝。所有编辑仍使用磁盘哈希和缓冲区快照验证，Ctrl+Z 可撤销。

本地历史位于用户数据 `local-history`，与 Git、源码和重启草稿分开。在保存及批量编辑前记录内容，每个工程文件保留最近 50 个版本且最多 32 MiB，连续相同内容去重；恢复前验证内容哈希。它不是无限归档，无法替代工程备份。

两个编辑分组共用文档会话，切换焦点不会复制文本或撤销栈。标签顺序、分组、光标、选区、草稿随编辑现场恢复；窗口尺寸、工程面板、底部面板、分隔比例和文件结构偏好独立保存在 `workbench-layout.json`。空间不足时文件结构面板自动收起。

开发环境组件在后台枚举内置文件，不修改系统 PATH。开发环境组件以 `.mcutoolchain` 为默认扩展名，容器使用 7z/LZMA2；已有 ZIP 和 `.studioxtools` 归档继续兼容。导出先完整校验；修复要求 ID、版本与编译器一致，先在工具目录的独立临时区域展开并核对，再替换并保留 `.rollback-*` 目录。错误版本、损坏内容、路径越界、链接、重复或未索引文件不能替换已安装工具。SHA-256 校验表示内容完整性，不表示发行者签名。选中开发环境组件显式校验前，页面不会把它标记为已通过。

`tools/StudioX.ProductivityValidation` 使用真实 clangd、独立插件进程和隔离文件测试格式化、修复、历史、布局、工具修复、API 2/3 兼容及大目录边界。参数依次为 runtime、语义测试工程、示例 DLL、新输出目录。`--preview-ide-next` 与 `--preview-ide-next-recovery` 分两个进程测试 WPF 分屏及草稿恢复。`--show-ide-next <fixture> <isolated-user-data>` 用于实际鼠标、键盘测试，不读取日常用户账号配置。
