# 大工程性能与打开过程

源码登记按需扫描用户 CMake 和源码，复用统一目录排除规则，跳过 SDK/产物/链接，最多核对 20,000 项并响应取消；文件通知只标记待核对，不在每次文件写入时扫描或改写 CMake。构建列表预览显示范围有界，应用仍复核完整快照。详见 [源码登记](SOURCE_REGISTRATION.md)。

工程树在后台读取一个目录，再分批呈现节点；默认只加载根目录和应用入口目录。折叠、再次展开会复用已加载节点，避免重复枚举和重建界面。应用服务监听当前工程的文件变化，外部工具与 IDE、插件、AI 写入进入同一同步流程。普通内容变化保留工程树；增删改名只核对相关的已加载目录，复用未变化的节点、展开范围与选择。`F5` 完整核对已加载目录和打开文档，也用于通知丢失后的重试。停止打开或刷新可以取消读取，取消不会缓存不完整列表。链接文件和目录仍不能展开。

`Ctrl+P` 的一个窗口复用文件名快照。普通输入和内容修改不重新扫描；结构变化撤销旧发现任务并刷新当前窗口的结果，新增或删除文件无需关窗再打开。覆盖已有文件的原子保存不重复发现，构建产物和分析数据库不进入快开索引。取消旧查询不会取消共享发现任务；关闭窗口会停止扫描并释放过期快照，实际打开文件仍经过路径与磁盘检查。隐藏构建目录、环境目录、`node_modules`、`cmake-build-*` 与链接不会进入结果。最多发现 100,000 个目录、100,000 个文件，一次显示 300 个匹配项；发现超限明确报错，不返回貌似完整的部分索引。

自动 C/C++ 数据库发现使用可取消的逐项枚举，继续遵循 5,000 个源文件、10,000 个目录及单文件 4 MiB 的既有限制。原生编译数据库中的翻译单元不受这个自动发现上限限制。未直接列入数据库的头文件沿用相邻翻译单元，选择过程不再排序整套数据库；推断命令只缓存当前数据库的最多 1,024 个文件，工程重载后清空。

## ESP-IDF 打开时的自检

上次构建占用统计需要校验 SDK 工具、源码和构建输入。它在后台继续进行，编辑器和 clangd 先就绪，工程操作可以使用。左侧构建分析器显示自检进度，顶部停止按钮可以取消；切换、关闭工程或开始构建会取消旧统计，迟到结果不能覆盖新工作区。没有构建记录或统计缓存时直接显示“编译成功后显示各存储区占用”。

工具目录的完整哈希校验与编译、下载前检查仍然保留。取消统计不会把工具标记为校验成功，也不会改变工程的工具锁。语言服务只解析需要的工具入口元数据，跳过大型发行哈希字典；语言提示不表示目标 ABI 或工具完整性已经验收。已有有效统计缓存的复用、构建失败后清除缓存等行为继续保留。

## 本机测量

2026-10-08 的器件目录测量包含 235 个已安装版本：本地目录初读约 341 ms、重复读取约 263 ms。页面原先还同步核对 36 个缺少精确本地版本的随附归档，较新的已安装包需完整检查 SDK 才能跳过这些旧归档；这部分不再阻塞新建工程页。测量没有删除、导入或修改真实包库，数字是本机样本，不是通用时限承诺。

`--preview-pack-catalog` 使用隔离小包和可控的后台等待，验证后台检查未完成时页面操作已结束、已有器件可选择、空目录导入后自动补充、选择保留、重复打开以及取消和失败。导入、覆盖清理和创建工程前的内容哈希检查继续保留。

2026-10-02 在同一台 Windows 机器上，对 30,000 个文件的隔离夹具和一个已有 ESP-IDF 5.5.4 / ESP32-S3 工程副本进行前后测量。宽目录含 6,000 个 C 文件，另有 24,000 个 SDK 头文件；IDF 副本含 1,007 个文件及约 3.5 MiB 的原生编译数据库。原实现先运行，没有清空操作系统文件缓存，因此这些是本机样本，不是所有机器的时限承诺。

| 操作 | 优化前 | 优化后 |
|---|---:|---:|
| IDF 编辑器与 clangd 服务就绪 | 49.79 秒 | 1.93–1.97 秒 |
| 宽目录首次加载总耗时 | 3.92 秒 | 2.38 秒 |
| 首次加载最大 UI 调度间隔 | 3,914 ms | 43 ms |
| 折叠后再次展开 | 3,034 ms | 4.50 ms |
| Ctrl+P 后续文件名筛选 | 59–73 ms / 次 | 0.3–2.8 ms / 次 |
| 首次加载累计托管分配 | 392 MiB | 77 MiB |

首次快开发现仍需扫描磁盘，本机约 87 ms；后续输入不再扫描。IDF 就绪指标表示文档可编辑和语言服务连接可用，后台语义索引及内存统计可能继续进行。本次 IDF 打开最大 UI 调度间隔约 127–140 ms，宽目录完整刷新约 143 ms，仍有布局、GC 与调度抖动；没有宣称所有帧都低于 16 ms。

## 复现与验证

先运行 `tools/Build.ps1 -Configuration Release`。独立应用检查入口：

```powershell
dotnet run --project tools/StudioX.LargeProjectValidation -c Release -- <fixture-directory> <new-report-directory>
```

夹具目录不存在时生成 30,000 个文件；已有目录必须是该专用夹具。输出查询耗时、托管分配和边界检查，测试内容包括完整结果、排序、取消、快照不可变性、外部新增刷新、生成目录排除、未编译 IDF 跳过自检。

真实 WPF 检查入口：

```powershell
& '<MCU StudioX.exe>' --preview-large-project <new-ui-report-directory> <fixture-directory>
& '<MCU StudioX.exe>' --preview-project-open-performance <new-idf-report-directory> <isolated-idf-project-copy>
```

使用独立用户目录，输出 JSON 与界面截图；验证 6,000 项树节点、重复展开复用、刷新定位、从 UI 取消后重试，以及 IDF 自检期间编辑/撤销、停止和关闭后的迟到回调隔离。IDF 验证必须传入工程副本，统计服务可以更新该副本的缓存。本轮不执行固件构建、不连接或烧录设备。

另运行 `StudioX.WorkspaceEditingValidation` 的真实 clangd 回归、`StudioX.BuildMemoryValidation` 的统计缓存回归，以及 `StudioX.EspressifValidation --language-fallback` 的未配置 SDK 语言提示检查。
