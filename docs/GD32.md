# 兆易创新 GD32 器件包

StudioX 0.1.0 将 GD32 按固件系列拆成独立器件包。Arm 型号以 GigaDevice 的 Keil DFP 为型号、Flash 和主 SRAM 依据，并对已知 DFP 容量错误按官方数据手册修正；VF103 使用官方数据手册 Rev2.3 的正式料号。发行索引为 `artifacts/packs/GD32-0.1.0-r5/index.json` 及 `artifacts/packs/GD32-E51x-0.1.0/index.json`，`file` 字段相对于各自索引目录。

基础 13 包的模板是标准外设库最小工程，使用原厂 `SystemInit` 的内部时钟分支。默认编译启动、CMSIS、RCU、GPIO，Arm 包在存在时还编译 `misc.c`；其余驱动仅放在 `device/sdk/peripheral/` 供按需加入。E51x 独立包还提供纯 CMSIS 模板。模板不绑定开发板 LED、引脚或外部晶振，也没有逐项验证其余外设驱动。F4xx 仅链接主 SRAM；VF103 按容量选原厂 `.lds`。

Arm SDK 来自 [GigaDevice 官方 GitHub](https://github.com/GigaDevice-GD32-MCU)，逐系列固定提交和 SHA-256 见 [`sources.json`](../examples/packs/gigadevice.gd32/sources.json)。E50x 采用[官方 1.7.0 固件库](https://www.gd32mcu.com/download/down/document_id/282/path_type/1)及[官方 1.9.0 AddOn/DFP](https://www.gd32mcu.com/download/down/document_id/260/path_type/1)；原 SDK 缺失的 GNU CMSIS 两个头文件补自固定版本的 [Arm CMSIS_5](https://github.com/ARM-software/CMSIS_5/tree/5.2.0/CMSIS/Core/Include)，也有独立哈希。每包包含 `provenance.json`、DFP 描述和原许可文件。EPRT 是专用系列，官方 DFP 的部分缩写与当前正式料号不完全对应，暂不混入 E50x 常规型号。

厂商源码的使用与再分发遵循各包保留的原始许可；E50x 的 SLA-GD0001 限定其软件用于 GigaDevice 器件。

E51x 独立包按固定提交的[官方固件库](https://github.com/GigaDevice-GD32-MCU/GD32E51x_Firmware_Library)与官方 AddOn/DFP 1.5.0 构建，缺失的 GNU CMSIS 头也按固定版本补入。官方 [GD32E513 数据手册 Rev1.6](https://www.gd32mcu.com/data/documents/datasheet/GD32E513xx_Datasheet_Rev1.6.pdf)将 E513ZE 的 SRAM 列为 128 KiB，旧 DFP 误列 96 KiB；包内按数据手册修正并在 `provenance.json` 记录。专用 EPRT 型号未收录，详情见 `examples/packs/gigadevice.gd32e51x/README.md`。

F10x、F20x、E50x 固件库仅提供 ARMASM 启动文件，生成脚本按原厂向量表顺序生成 GNU 启动，并记录原始文件哈希及向量表到 `vendor/vectors.json`。VF103 使用 `riscv.xpack/1.0.0`，GCC 15 编译参数为 `-march=rv32imac_zicsr_zifencei -mabi=ilp32`；CSR 与栅栏扩展需显式列出。VF103 原厂头文件还要求 `HXTAL_VALUE`，模板提供名义 8 MHz 值，但当前 `SystemInit` 选择内部 IRC8M → 48 MHz。VF103 的原始固件库及数据手册来源见包内 `provenance.json`。

离线验收使用 [`StudioX.VendorPackValidation`](../tools/StudioX.VendorPackValidation/README.md)：导入每包、逐型号核对容量与链接脚本并创建工程，对容量、CPU、启动和 SDK 源文件的代表组合真实构建，检查 ELF/BIN/HEX 及入口/向量。基础 13 包 **398 个型号、398 次工程创建、117 次代表性真实编译、0 失败**，结果见 `.artifacts/gd32-validation-r5/result.txt`；E51x **20 个型号、25 次工程创建、10 次代表性真实编译、0 失败**，结果见 `artifacts/validation/GD32-E51x-0.1.0/result.txt`。全过程未连接或访问硬件。

**下载与调试仍未开放。** 当前 GD32 包均不声明 OpenOCD，因为尚无样片及逐型号可靠的芯片 ID、Flash 容量校验。即使内置 OpenOCD 含部分 GD32 target 脚本，离线编译成功也不能证明可安全擦写或调试。[E23x 手册 Rev1.5](https://www.gd32mcu.com/data/documents/userManual/GD32E23x_User_Manual_Rev1.5.pdf)给出 Flash density 字段和 DBG_ID 地址，未给出可用于逐型号严格比对的 ID_CODE 常量。取得样片后应核对探针、芯片身份、下载、复位、断点及寄存器读取，再逐型号开放。

F50x、W51x 等系列尚未完成同等级的启动、链接和真实编译验收，未列为已支持型号。
