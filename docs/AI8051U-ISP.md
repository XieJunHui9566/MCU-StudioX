# AI8051U 下载桥协议与脚本验证（2026-10-23）

2026-10-26 更新：MX251 的 IDE USB 下载已接入本协议核心及共用 `IspSession`。其入口强制使用 `configure` 等价流程，每次实际发送32位及用户指定的IRC配置并读取核对；没有 `preserve` 或8位选项。使用方式和当前限制见 [MX251](MX251.md)。下文未接入 IDE 的说明是原协议实验阶段记录。

## 交付与范围

`tools/StudioX.Ai8051Isp/` 提供独立 C# 核心、PowerShell 入口和 JSON 配置。无需打开官方 STC-ISP，使用系统 HID 驱动即可识别、下载、校准和读取配置。未修改 IDE 下载入口、产品版本或安装版。构建方式和调用示例见 [脚本 README](../tools/StudioX.Ai8051Isp/README.md)。

本轮仅验证当前 AI8051U-34K64 / BSL 7.4.1U，板载芯片丝印由用户确认为 AI8H2K12G。USB 枚举为 `34BF:FF0F` / MI_00 / `STC USB Serial`；官方工具称其为 `USB-HID1CDC`。下载走 HID，数学自测走同一复合设备的 CDC / COM6。不要把此协议当成所有 STC USB 下载器或芯片原生 USB 的通用协议。

支持的代码是 32 位模式的 Intel HEX，应用页 `FF0000..FFFFFF`，64 KiB 上限，桥接到 ISP 的块地址为页内 16 位偏移。只支持本次验证的初始 2400、传输 115200 波特率流程。其他型号、BSL、下载桥固件、8 位 HEX、原生 USB、其他速度、EEPROM 映像、用户系统区、密码和加密下载均未开放。

## 报文

Windows API 收发长度 65 字节：1 字节 Report ID 加 64 字节 HID 数据。所有字节加和的低 8 位为 0，末字节是前面字节加和的二补数。每个接收报告均核对长度、报头、载荷长度、校验和，再检查当前阶段期待的应答。

| Windows 缓冲区偏移 | 主机发出 | 下载桥返回 |
| --- | --- | --- |
| 0 | Report ID `00` | Report ID `00` |
| 1 | `5A` | `A5` |
| 2 | 桥命令 | 载荷长度高字节 |
| 3–6 | 分片偏移，大端 32 位 | 偏移 3 为长度低字节，4 起为载荷 |
| 7 | 本片载荷长度，最多 56 | 载荷的一部分 |
| 8–63 | 载荷与零填充 | 载荷至多 60 字节及填充 |
| 64 | 二补数校验 | 二补数校验 |

| 桥命令 | 已观察用途 |
| --- | --- |
| `00` | 查询下载桥身份；本板返回 19 字节、起始 `51 01 04 FF`，偏移 15 为 `71` |
| `40` | 下载桥控制。初始化及结束使用已观测的序列，尚未给每个未知控制位命名 |
| `41` | 进入 ISP 并取得目标状态；本轮载荷 `28 00 03 05 00 09 00 00` |
| `43` | 交换一个目标 ISP 命令：校准、准备、擦除或配置 |
| `44` | 写入下载桥的分片缓冲区 |
| `45` | 提交缓冲区中的写块，载荷 `45`；等待目标返回 `02 54` |
| `FF` | 结束桥会话。未观察到完成应答，不能把发送完成等同于目标程序已运行 |

目标命令包括：`01` 切换参数、`05 00 00 5A A5` 准备、`03 00 00 5A A5` 擦除、首块 `22` / 后续块 `02` 写程序、`04 00 00 5A A5 ...` 保存配置。

每块含 1 字节命令、2 字节地址、`5A A5` 和 64 字节代码，共 69 字节；分为 56 字节和 13 字节两个 `44` 报告，第二片偏移为 56。最后不足 64 字节时补 `FF`。必须收到严格的 `02 54` 后才增加确认字节数；坏应答和超时立即失败，不自动重放写块。

检测返回 54 字节状态。当前目标 ID 位于 20–21，为 `78 B4`；版本由 17、18、22 对应 `7.4.1U`；1–4 为大端保存的 IRC Hz；5、6、7 为调节值、范围与分频。本工具还要求桥身份、状态长度和已验证选项组合一致，未把相似料号自动代用。

## 配置流程与关键失败发现

默认 `flash` 保留硬件配置。明确提供 JSON 配置时，执行两轮 IRC 测量：先测四个范围的两端，共 8 点，再根据测量插值选择 12 个邻近调节值；选择最接近目标的测量点，误差超过 0.5% 时拒绝继续。原始实板验收为40MHz/分频1。2026-10-26新增目标1–48MHz（分频后的系统频率），默认40MHz；根据实测四频段选择1–8分频，原始振荡目标不超过48MHz。分频字段与保存频率的语义参考stcgal Stc8d的公开源码及本芯片手册8.4，硬件选项模板保留原抓包不变。完整链路离线验证与实板验证分开记录于mx251-irc-20261026，不将离线回传当实板证据。RC 频率是当次测量结果，不能硬编码一个历史校准值用于所有芯片。

在研究中尝试了“准备后直接写配置，不下载代码”的流程：配置命令无完成应答，重新检测时关键配置字节为 `FF`。这一失败保留在 `script-config-1.ndjson` 和 `script-inspect-after-config-error.ndjson`。不能据此断言所有 STC 型号都如此，但当前 BSL 不应开放这条路径。

随后使用同一份自测固件完成下载和配置恢复，取得 `04 54` 并重新读取匹配的配置。最终工具在 CLI 和协议状态机两层强制：**配置必须与同一会话中全部收到确认的固件下载绑定**。未知选项组合拒绝覆盖；配置写入或下载失败不报告成功，也不自动运行不完整镜像。`configure` 并不是无损的选项编辑器，需要明确的 HEX 和 SHA-256。

专用 `--recover-erased-config true` 仅在 `configure`、固定已验证配置、指定固件、关键状态均为全 FF 时启用。用于本次失败恢复，不是默认行为，不是解除读保护，也不会自动重试。

配置 ACK 后结束会话、重新进入 ISP，核对保存的 Hz、调节值、范围、分频以及既有选项组合；全部一致才报告 `configurationReadback=true`。这只属于配置读取核对，不是代码 Flash 读回。该板原有配置允许擦除 EEPROM，代码擦除可能同时影响 EEPROM，工具未承诺保留其内容。

## 软件结构和 StudioX 接入点

- `FirmwareImage`：严格解析 HEX、校验和、EOF、重叠、页范围、填充和文件哈希；预检不开硬件。
- `HidTransport` / `IHidReportTransport`：使用系统驱动枚举和有界异步 I/O，可替换为离线模拟。C# 核心不依赖 WPF。
- `BridgeProtocol`：检测、校准、准备、擦写、配置、退出的状态约束；错误保留原始诊断。
- `DeviceConfiguration`：带版本的配置模型及已验证字段限制。
- `Program`：严格命令参数、JSON 行事件、原始收发日志、取消和退出码。
- `Invoke-Ai8051Isp.ps1`：构建和调用入口；文件名参数使用参数数组传递，不拼 shell 命令。

Windows 为本下载桥的 consumer HID 保留共享句柄，因此本工具使用系统要求的共享打开方式，并以用户数据目录中的独占文件租约阻止本工具多进程并发；这不等于 Windows 全系统独占。启动时拒绝与已运行的 AiCube/AIapp/STC-ISP 共用设备。其他不遵守租约的第三方程序仍须释放设备。

后续 IDE 可由 Engine 的下载服务管理目标与设备所有权，准备不可变固件快照和工具锁，再启动此 CLI 或提取同一 C# 核心。Desktop 只显示计划、进度、状态和日志。串口监视器应由同一应用服务在下载前释放、结束后按原订阅恢复。不得让 Desktop 直接打开 HID 或串口，也不能将软件预检当作授权后的硬件下载完成。

## 验证

`verify-capture` 将官方发送包重新编码比较、核对所有完成 I/O 与应答校验、重组代码块并与实际 HEX 比较；573 块对应 36,615 字节固件，尾部 57 字节为 FF。另覆盖坏校验、短报告、非法长度、坏 HEX、重叠、错误页和 EOF。

`selftest` 离线检查状态机：未识别就编程、未完成固件就写配置、错误芯片、错误握手、坏写块 ACK、超时、取消、不完整镜像复用/运行、未经验证的配置等拒绝分支。完整下载、配置保存及数学自测另外在当前板上验证，机器可读结果见研究目录 `acceptance.json`。

下载器记录 `programAcknowledged=true` 和 `flashReadback=false`；独立串口自测验证实际执行。数学结果保持 267 通过、0 软件失败、0 未判定，另有此前已知的正 NaN 分类硬件/手册差异。未把该差异改成通过，也未宣称泛化到其他板型。
