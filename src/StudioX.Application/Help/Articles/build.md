# 编译工程与检查输出

## 正常编译流程
1. 打开工程，核对当前器件、框架和锁定工具。
2. 保存源码与构建配置，按 `F7` 或“构建 → 编译工程”。
3. 观察底部输出中的工具校验、配置、编译和链接阶段。首次使用工具集或首次配置可能耗时较长。
4. 查看最终成功或失败结论与退出代码。成功通常为 0；停止或超时应重新执行，不能沿用旧产物当作本次成功。

## 日志与产物
原始日志位于工程 `.build` 内，构建日志常见为 `studiox-build.log`。ELF 用于符号与调试，BIN/HEX 用于对应下载流程，MAP 可检查内存占用。ESP-IDF 的应用、bootloader 与分区表共同构成原生下载布局，不能只拿一个任意 BIN 替换全部布局。

## 编译失败怎么读
先找最早的 `CMake Error`、`fatal error`、`error:` 或链接错误，再读前后命令和文件位置。最后的“build failed”“exit=2”只是结果。双击问题列表中的源码诊断定位；没有行号的工具或链接错误继续看完整输出。

## 停止与再次编译
“构建 → 停止构建”取消当前操作。修改源码后通常增量构建；工具、编译参数或构建环境变化时会重建相关缓存。缓存清理保留源码和 SDK 配置，但首次重建可能重新编译较多文件。

## 判断修改有没有生效
确认文件已保存并被列入构建目标，观察该源文件是否编译，以及最终产物时间和本次日志。新建了文件但没有加入 CMake 时，`F7` 成功也可能完全没有编译该文件。不要通过修改 `.build` 里的 Ninja 或临时 CMake 文件来长期修复问题。
