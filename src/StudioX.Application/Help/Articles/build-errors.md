# 编译失败、头文件与链接错误

## 工具缺失或完整性失败
遇到 `TOOLSET_MISSING`、工具不存在或哈希变化，打开开发环境组件管理，核对工程需要的 ID 与版本并校验。使用对应离线包修复。不要改系统 PATH 指向另一套编译器，造成编译结果与工程锁不一致。

## 找不到头文件
`fatal error: xxx.h: No such file or directory` 或 `file not found`：
1. 检查文件是否存在，名字、大小写、相对路径是否正确。
2. 检查该源文件所在目标的包含目录；普通工程看 `target_include_directories`，IDF 组件看 `INCLUDE_DIRS` 与依赖。
3. 若是厂商头文件，确认选择了相应器件包及模板。
4. 保存配置并重新编译，再检查编辑器分析是否与真实命令一致。

## 未定义符号
`undefined reference to ...` 表示链接时缺少定义。检查实现文件是否加入构建、函数签名是否一致、条件宏是否把实现排除、所需库是否正确链接。C 与 C++ 混用时核对符号链接约定，必要时按接口使用 `extern "C"`。增加一个声明并不能补出缺失的实现。

## 符号重复
`multiple definition` 常见于头文件中定义全局对象、同一源文件编译两次、应用和库重复实现入口或中断。头文件通常保留声明，定义放在对应源文件中。检查目标源列表和库关系，勿靠删除启动文件来消除不理解的重复符号。

## Flash 或 RAM 超限
`region ... overflowed`：先核对真实器件容量和链接布局，再查看 MAP 与占用统计。检查大数组、栈堆、常量和重复组件，按需要减少内容或使用合适优化。不要把链接脚本的容量随意放大到超出实际芯片。

## CMake 配置错误
若工程移动后提示缓存属于其他目录，打开“工具 → 工程与构建 → 工程健康检查…”，选择缓存冲突项并预览修复。确认后只把已知生成缓存和旧构建凭据移入备份，保留源码、SDK、sdkconfig、工具锁和固件；下次编译重新配置。检查报告可以导出 JSON，包含原始诊断。不要通过删除工具锁绕过版本指纹不一致。

从第一条 `CMake Error` 的文件和行号开始，检查命令、目标名、源路径及依赖。新增文件后的失败优先核对用户维护的 CMake。工具、环境或配置确实变化时使用正常重新构建，让 IDE 处理原生缓存，保留原始配置和源码。
