# 保存冲突、恢复草稿与本地历史

## 外部文件已变化
遇到 `EDITOR_FILE_CHANGED` 或保存冲突时，说明磁盘内容与编辑版本不同。先复制当前草稿到安全位置，或查看本地历史，再比较磁盘文件与当前内容。确认保留哪些修改后重新打开或保存，避免用连续覆盖代替比较。

## 批量预览过期
`WORKSPACE_EDIT_STALE`、重命名版本变化或修复版本变化表示预览依据已失效。保留当前内容后重新生成搜索、格式化或重命名预览，审阅最新差异再应用。旧预览中的行号和文本可能已不再对应当前文件。

## 使用本地历史
1. 打开相应文件，选择“编辑 → 本地历史…”。
2. 查看版本时间与内容，找到需要的修改前状态。
3. 恢复前再次核对当前草稿和磁盘版本，确认目标文件。
4. 恢复后检查差异，保存并按需要重新编译。
历史保留数量与总空间有上限，连续相同内容会去重，不能替代完整工程备份。

## 意外关闭后的草稿
重新启动后查看恢复工作区和草稿提示，先确认对应工程路径与文件存在。恢复草稿属于用户恢复数据，磁盘源码属于工程；审阅后保存才会将需要的内容写回文件。磁盘版本已有新的外部修改时先比较两者。

## 无法保存或拒绝访问
根据错误找到具体文件，检查目录权限、只读属性、占用程序与磁盘空间。工具安装目录、共享 SDK 和生成配置有不同维护方式；应用代码应放在可写的工程目录。移动工程前先保留未保存内容，再从新路径打开。

## 长期保护工程
对源码和关键配置使用 Git 或独立备份，定期检查备份能否读取。重要设备固件和采集记录另行保存，不把缓存目录或单一恢复草稿作为唯一副本。
