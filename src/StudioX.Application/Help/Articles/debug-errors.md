# 调试连接失败与断点不命中

## 连接失败
核对完整器件型号、探针类型、接口模式与当前支持范围。STM32 常用 SWD，CH32 的 WCH-Link 通路和 AG32 专用通路各有目标要求，不能只因都叫 OpenOCD 就互换配置。
1. 检查供电、公共地、SWD/JTAG/SDI 及复位连线。
2. 查看电脑是否识别探针、序列号是否正确，以及是否被其它工具占用。
3. 使用该目标支持的较低连接频率后手动重试。
4. 保存从 OpenOCD 启动到失败的日志，区分 USB、目标识别和 GDB 阶段。

## 固件不一致
启动调试会核对当前 ELF 和板上程序。源码或配置变化后，先重新编译并下载当前固件，再连接。旧的 ELF、复制来的 BIN 或其它工程固件可能导致拒绝连接或错误源码位置。

## 断点不命中
确认目标已经运行到相应代码，断点处存在可执行指令，相关源文件属于当前构建。核对调试信息、优化等级、条件表达式和断点启用状态。高优化可能合并或删除代码；硬件断点数量也可能受目标资源限制。

## 单步跳行或变量不可用
先选择正确调用栈帧，核对变量作用域和当前执行位置。使用 `-Og` 与合适调试信息重新构建，再判断是否是优化消除。寄存器和内存窗口按实际目标与地址读取，不能把错误地址显示当成有效变量值。

## 读保护与异常退出
日志明确指向保护配置时，先确认芯片状态和需要保留的数据，再选择独立的保护处理流程。日常连接失败先排查设备与连线。断线后目标可能仍暂停，只有恢复操作得到确认后才能认为程序重新运行。
