# 串口占用、乱码与绘图无数据

## 端口被占用或拒绝访问
1. 检查 IDE 的串口终端、绘图、MicroPython 和下载是否占用同一 COM。
2. 断开已有会话，再检查其它串口助手或厂商工具。
3. 刷新列表，确认设备重新插入后实际 COM 是否变化。
4. 查看 Windows 设备状态和驱动错误，确认后手动重连。不要对已经占用的会话连续强行打开。

## 接收乱码
先核对波特率、数据位、校验位和停止位，然后匹配 UTF-8 或 GBK 编码。二进制协议使用 HEX 查看原始字节。若连 ASCII 都随机变化，优先检查波特率、地线与电平，而不是反复切换中文字体。

## 可以连接但没有数据
确认固件已经运行并确实发送，TX/RX 与 GND 连接正确，流控设置与硬件一致。查看接收计数：计数不增加时排查设备与传输；计数增加但文本异常时检查编码、控制字符和显示模式。DTR/RTS 可能影响复位或启动模式，按板卡要求设置。

## 发送后设备不响应
检查设备要求的是文本还是字节、命令是否区分大小写、末尾需要 LF 还是 CRLF。HEX `01` 与文本字符 `1` 不同。超时提示“可能部分发送”时先看设备状态，避免自动重复具有副作用的命令。

## 绘图空白或通道错误
先在终端查看原始一行数据，确认是数值、分隔符正确、含完整结束符、每组通道数量相同。然后断开终端再开始绘图。首段用于同步组边界；错误组会被计数并使曲线断开。混入日志、空字段或 ANSI 颜色时，应整理固件的绘图输出流。

## 断线之后
定时发送或采集会停止。核对板卡与端口后重新开始，新的采集会话会按页面规则处理旧数据。需长期保存时使用相应记录或导出功能，而非依赖窗口始终保持打开。
