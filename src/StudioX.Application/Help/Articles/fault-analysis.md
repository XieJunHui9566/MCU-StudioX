# HardFault、ESP Panic 与离线转储

打开“调试 → 固件故障分析…”。工作台支持暂停现场、粘贴日志、离线转储和导出 JSON 报告。

## 分析前检查

保存完整原始日志，记录对应工程、器件和固件版本。地址定位使用本工程当前成功构建的 ELF；仅文件名称相同不能证明固件匹配。导入来自其它设备的日志或转储时，先核对来源，保留未确认标记。没有匹配的符号文件时仍可查看故障状态与原始证据，不应把解析出的行号当作结论。

## Cortex-M 故障现场

已经连接且暂停的 Cortex-M3/M4/M7 工程可点击“读取暂停现场”。工作台只读 CFSR、HFSR、MMFAR、BFAR、当前寄存器及已获得的调用栈，不自动连接、单步或复位。

CFSR 中 PRECISERR 表示精确总线故障，IMPRECISERR 表示异步错误，DIVBYZERO 表示除零，UNALIGNED 表示未对齐访问。HFSR 的 FORCED 表示可配置故障升级为 HardFault。MMFAR/BFAR 只有相应有效位存在时才当作有效故障地址。缺失的寄存器表示证据缺失，不当作零值。

当前 PC 可能已经位于异常处理函数。处理函数的序言会改变 SP，因此工作台不会把当前 SP 猜成原始异常栈帧，也不会把 EXC_RETURN 当作源码地址。结合实际回溯、故障状态和代码判断根因。

## ESP Panic 与 Core Dump

粘贴完整 Panic/Backtrace 日志并点击“分析日志”。从 Backtrace 的 PC:SP 对中提取代码地址，SP 不当作代码地址。日志中的提示是线索，不等于已验证根因。

ESP-IDF 工程可点击“导入 ESP 转储”，明确选择 Base64、原始二进制或 ELF 格式文件。使用本工程锁定的 ESP-IDF Python、esp_coredump 和 GDB 读取所选文件，不读取设备 Flash。工程需有成功构建的匹配 ELF；工具错误保留完整输出。日志或转储必须由用户确认来自对应固件。

## 定位与分享

“使用工程 ELF 定位”用锁定工具的 GDB 将地址解析为符号和源文件行。源码已变更或 ELF 已改变时拒绝沿用旧构建。报告记录 ELF SHA-256、证据来源、宿主采集时间和原始诊断；没有确认匹配的导入日志会明确标记。

“导出报告”保存 JSON；“导入报告”重新分析证据并将其标记为导入数据，不继承原报告的实板匹配声明。分享前检查原始日志可能包含的工程路径和业务信息。
