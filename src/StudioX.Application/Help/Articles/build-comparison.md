# 比较两次构建的体积与耗时

打开“工具 → 工程与构建 → 构建历史与对比…”。IDE 成功构建后保存快照，独立用户目录中每个工程最多保留最近 20 次；不会向工程源码写入历史统计。已有成功构建可点击“保存当前构建快照”。源码或 ELF 与构建回执不一致时拒绝采集旧结果。

## 使用方法

1. 成功构建并保存基准。
2. 修改代码、配置或组件，再成功构建。
3. 刷新历史，选择“基准”和“比较”，点击“比较”。
4. 查看正增长、负减少的项目；需要分享时点击“导出对比”。

## 解读静态存储与符号

存储区显示链接后 Flash/RAM 静态占用；符号行关联输入段、符号名称和目标文件；文件行汇总对应输入段。MAP 解析排除被丢弃段和调试段，但输入段的体积不一定能完全对应某个 C 函数，链接填充和匿名段也不保证包含在文件汇总中。运行期堆和栈峰值不属于此统计。

## 解读耗时

Ninja 步骤耗时采用每个目标输出最后一次编译记录，增量构建可能沿用旧记录。并行步骤不能相加作为总时间。构建墙钟时间只统计 IDE 实际构建调用，不含之前的健康检查和之后的分析；手动采集的快照可能没有墙钟时间。

## 比较前核对

比较前核对开发环境组件版本和优化等级。不同器件或工具系列不能直接比较；相同系列换版本也可能影响结果。这里只记录成功构建，编译失败的原始日志仍从构建输出检查。
