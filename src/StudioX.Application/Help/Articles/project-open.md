# 打开现有工程与 CubeMX 导入

## 打开 StudioX 工程
1. 选择“文件 → 打开工程…”或按 `Ctrl+O`，选择工程根目录。
2. 根目录应包含对应的 `.studiox` 工程信息，以及模板自己的源码和构建入口。
3. 打开后先核对器件、框架和开发环境组件版本。缺少锁定工具时到开发环境组件页检查，不要自行切换到系统编译器。
4. 最近工程只是路径记录；移动工程后请从新位置重新打开。

## CubeMX CMake 工程
使用“文件 → 导入 CubeMX CMake 工程…”，选择已有 CubeMX CMake 工程，按导入界面核对目标和工具配置。不是所有 Keil、IAR 或任意 CMake 目录都能通过这个入口导入；不要把其它格式伪装成 CubeMX 工程。

## 普通文件夹为什么不能直接编译
只有源码文件还不足以确定 CPU、ABI、启动文件、链接脚本、框架与编译器版本。可新建对应器件模板，再把自己的应用源码与依赖加入用户维护的构建配置。先保留原目录，确认编译后再整理旧文件。

## 关闭或切换工程
`Ctrl+Shift+W` 关闭工程。未保存内容会要求处理；取消会保留当前工作区。构建、下载或调试进行中先停止或结束会话，再切换工程。工程终端和插件会话与当前工程关联，切换后应重新核对它们的工作目录和状态。

## 常见问题
最近工程提示不存在：确认盘符和目录是否移动、删除或暂时离线。打开时模板信息不全：检查 `.studiox` 和 `device/manifest.json` 是否完整，不要只复制 `main.c`。保存冲突：先保留草稿，再比较磁盘内容。
