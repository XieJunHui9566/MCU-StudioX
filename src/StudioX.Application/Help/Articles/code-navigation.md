# 代码提示、跳转与格式化

## 提示与导航
- `Ctrl+Space` 请求代码提示，`Ctrl+Shift+Space` 查看参数提示。
- `F12` 跳到定义，`Ctrl+F12` 跳到声明，`Shift+F12` 查找引用。
- `Alt+Left` 返回上一处导航位置。
- `Ctrl+T` 搜索工程符号，`Ctrl+P` 快速打开文件。

## C/C++ 为什么需要先配置
C/C++ 分析需要当前文件真实使用的宏、头文件路径、语言标准和目标信息。打开工程后先让配置完成；ESP-IDF 首次编译会产生原生编译数据库。若 SDK API 没有提示，先成功配置或编译一次，再查看索引状态。编辑器实时诊断与 GCC 构建诊断在问题列表中分别标明来源。

## 格式化与快捷修复
“编辑 → 格式化文件”或 `Ctrl+Alt+F` 生成格式化预览；审阅后再应用。选区可用“格式化选区”。`Alt+Enter` 或 `Ctrl+.` 查看当前位置可用的快捷修复。功能灰色时检查文件语言、只读状态和语言服务是否就绪。

## Python 和 MicroPython
Python 使用独立静态导航；工程内定义和显式导入可跳转。MicroPython 的固定 API 声明可只读查看。动态生成的属性、运行时导入和复杂动态行为不一定能静态定位，需结合脚本实际行为判断。

## 提示与编译不一致
从真实构建日志确认文件是否已加入目标、包含目录和宏是否正确。重新配置后再观察分析状态。编辑器红线不能代替固件编译结果；同样，编译成功也不代表每个未参与构建的文件都已得到正确分析。
