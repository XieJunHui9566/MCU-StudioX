# ESP-IDF 外设开发辅助

从 **工具 → 工程与构建 → 外设开发辅助** 打开，也可在命令面板或源码右键菜单中搜索“外设开发辅助”。

首批支持工程锁定的 ESP-IDF **5.5.4 / 6.1.0**。窗口依据当前器件包、目标芯片和安装 SDK 核对能力、头文件与组件文件，显示 GPIO、UART、I2C 主机总线、SPI 主机总线、ADC 单次采样、LEDC PWM、软件周期定时器、RMT 发送通道。缺少文件或目标没有该能力时，会显示原因并阻止生成。

## 生成与插入

1. 打开当前工程的 C 源文件，在外设辅助窗口选择外设。
2. 填写实例名称和板上的 GPIO。引脚默认留空，请依据当前板原理图填写；芯片 GPIO 范围不代表模块上引脚已引出或可用。
3. 阅读代码、组件依赖和使用提示。相同外设内部的重复引脚、越界参数和非法名称会阻止生成。
4. 点击“插入 C 文件顶部”。代码进入未保存缓冲区，Ctrl+Z 一次撤销；插入前工程、SDK 和编辑快照必须仍一致。同一文件的实例名称不可重复。
5. 按“复制依赖说明”给代码所在组件的 `idf_component_register(...)` 补充 `PRIV_REQUIRES`，保留原来的依赖。例如 I2C 需要 `esp_driver_i2c`，预览也会列出通用 GPIO 依赖。无需复制头文件或写 SDK 绝对路径。
6. 在任务中明确调用 `sx_实例名称_init()` 并检查返回的 `esp_err_t`。不再使用时调用 `deinit()`，失败时保留错误并重试或报告。

代码以 C 生成；在 C++ 或只读文档中仍可查看和复制预览。I2C/SPI 模板初始化总线，设备地址、片选、频率和收发流程需根据设备资料补充。RMT 还需配置 encoder。ADC 示例返回原始值，电压换算需要目标对应的校准与量程。软件定时器的回调不能阻塞。

## 核对占用与 SDK

Flash、PSRAM、USB、控制台、启动绑带引脚和板载器件可能占用 GPIO。多个模板之间的引脚、控制器、PWM 定时器和通道也需统一分配；辅助窗口不推断板级连线，不自动解决跨实例占用。

如果提示缺少 `driver/xxx.h`，先查看完整缺失路径和工程锁定版本，在“开发环境组件管理”中检查该精确版本。文件存在但编辑器提示找不到时，核对组件 CMake 依赖并重新配置/编译，让实时诊断读取工程的实际编译参数。不要改用系统 SDK 或拼接其他版本的头文件。

窗口核对代码所需的核心头文件/API和组件入口，真实编译还会检查传递依赖及链接库。软件验收不能证明开发板引脚、电气连接或实际外设运行结果。
