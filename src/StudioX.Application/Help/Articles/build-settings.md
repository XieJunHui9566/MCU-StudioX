# 优化等级与调试信息

## 设置入口
打开工程后进入“工具 → 工程与构建 → 器件与模板”，找到可见的“编译参数”卡片。按当前后端选择参数，然后点击“保存参数”。恢复“工程默认”也要保存，下一次构建才会使用新设置。下载连接、时钟、硬件和调试配套使用下载按钮旁的独立设置页。

## 先确认编译后端

- STC 8 位 SDCC：编译参数页提供默认、低优化、体积优先和速度优先，以及 small / medium / large、内部 RAM（IDATA 总容量）和 XDATA 大小。容量空值沿用包配置，超限拒绝；RT51、Mon51 的模型及资源约束仍有效。低优化不等于 GCC `-O0`，调试使用标准 CDB。
- MX251：在同一卡片选择 small / large、体积优先 / 速度优先及 C 语言标准。三个选项统一保存到 `mx251.json`；恢复默认取创建工程时的模板值。页面不会将这些参数保存到隐藏的下载区域，也不套用下方的 GCC 档位。
- PIC、Arduino、Zephyr：尚未接入这套通用编译参数卡片，使用对应工程的 CMake、SDK 或 sketch 设置。
- 下方优化等级与调试信息说明仅适用于提供相应 GCC 风格选项的后端。

## 怎么选择优化

| 选项 | 适合场景 | 使用时注意 |
|---|---|---|
| 工程默认 | 保留原模板或原生 SDK 行为 | 沿用工程实际配置 |
| `-O0` | 调查源码执行顺序 | 体积与速度可能变差 |
| `-Og` | 常规源码调试 | 通常比高优化更容易观察变量 |
| `-O1` / `-O2` / `-O3` | 逐步考虑速度优化 | 变量可能被消除，单步可能跳行 |
| `-Os` | 优先减小体积 | 仍需测试速度和实时性 |

## 调试信息
源码调试可使用 `-Og` 与 `-g3`。`-g2` 提供标准调试信息；`-g3` 还包含宏信息；`-g0` 不生成调试信息。选择 `-g0` 后需恢复信息并重新编译、下载，才能期望源码断点与变量观察正常工作。

## 设置保存在哪里
通用及 STC SDCC 编译设置保存在工程 `.studiox/build.json`；MX251 使用 `mx251.json`，独立命令行构建也读取同一配置。设置与用户主题、器件包和工具本体分开。构建、下载或调试期间修改入口会受状态限制。保存新参数会使旧的构建凭据失效，下次编译会按新环境配置缓存。

MX251 配置文件有未保存编辑或磁盘内容已变化时，先处理该文件，再重新读取页面设置。当前没有跨后端的命名构建配置管理，优化档位不等于完整的 Debug / Release 配置。

## 参数不生效
检查本次构建输出和真实编译命令，而不是只看下拉框。如果自定义构建规则不支持参数注入，保留诊断，选择工程默认并维护工程自己的 CMake。优化设置不会修正错误的中断声明、时钟参数或链接脚本。
