# 插件 API：契约、语言与能力

## 从哪里开始

打开“帮助 → 插件 API 文档”，或在帮助中心搜索“插件 API”“SDK”“Python 插件”。本篇说明可用接口和语言范围；关联主题“插件 API：开发、协议与错误处理”提供可复制的 C# 示例、清单、打包命令和进程协议。使用现成插件的步骤见“安装、启用与使用插件”。所有帮助均随 IDE 分发，离线可读。

## 三个版本号分别表示什么

| 字段 | 当前契约 |
| --- | --- |
| 产品 / SDK 包版本 | 本发行版为 0.2.6.15；插件自己的 version 独立管理 |
| formatVersion | 清单格式 1 |
| apiVersion | 1 为旧解码器，2 为通用插件，3 为设置与开发扩展 |
| protocolVersion | API 2 / 3 的进程通信均为 2 |

这是 StudioX 自有的版本化接口：.NET 插件实现公开 SDK，进程插件实现 UTF-8 JSON Lines v2。MCP 是宿主工具桥接的一部分；插件进程包络并不是 MCP、JSON-RPC、LSP 或 DAP 协议。旧 API 1 解码器仍走自己的明确契约，不会自动作为 API 2 / 3 工作区插件运行。

## 支持哪些开发语言

| 语言 | 交付与支持范围 |
| --- | --- |
| C# | 正式 StudioX.Plugin.Sdk，目标 .NET 10；有真实宿主、安装及调用验证 |
| Python | 冻结 EXE，或随包携带便携 Python、脚本、标准库和必要 DLL；双向调用和取消已验证 |
| Rust / C++ | 原生 EXE 实现相同协议；仓库有源码模板，本轮没有实编所有语言工具链 |
| F# / VB.NET | 可在兼容 .NET 接口的条件下实现 SDK；当前没有独立语言验收 |
| 其他语言 | 能交付包内 Windows EXE 并实现协议即可适配；须分别验证运行依赖和行为 |

进程入口是插件目录内受文件索引保护的固定 EXE。不能把系统绝对路径或单独的 .py / .js / .ps1 当作入口；依赖运行时须随插件交付，IDE 不查找系统 Python 或 Node，也不会代装语言开发工具。C# DLL 的公开入口类型必须实现 IStudioXPlugin，可由无参数构造函数创建，不引用 Desktop 或 WPF。

## API 能做什么

| 版本 / 能力 | 实际提供的功能 |
| --- | --- |
| API 1 decode | IFrameDecoder 字节帧解码 |
| API 2 commands | 工具、命令面板及允许位置的命令 |
| API 2 panels | 宿主绘制的声明式数据面板 |
| API 2 agentTools | 会话启动时固定定义的 Agent 工具 |
| API 3 settings | 字符串、布尔、整数设置及范围校验 |
| API 3 events | 工程、文档与设置变化通知 |
| API 3 languages | 自定义文件后缀的有限补全接口，位置为 UTF-16 |
| API 3 debugAdapters | 解释当前调试快照并返回只读面板 |

语言扩展目前没有完整 LSP 的诊断、重命名等能力。调试扩展不提供任意 DAP 驱动，不创建硬件会话，不通过快照接口执行目标表达式或写寄存器。连接、下载、发送和工程修改须通过具体宿主工具及其授权检查。

API 2 / 3 还有按清单声明的独立面板窗口、程序员计算器等能力。API 3 的 MCU 配置试行能力包含准确工程匹配、托管时钟和受限生成 / 保存事务，须满足对应模板、来源及贡献契约；不能把尚未开放的完整 mcuConfigurationV1 草案当成现有能力。清单未知能力或版本不兼容会被明确拒绝，不静默忽略。

## 生命周期、数据与权限

工程级插件绑定当前工程：启动后先 Describe，校验贡献，再 Activate，随后接收 Invoke；停用、更新、崩溃、工程退出时撤销会话。应用级插件显式声明 scope 为 application，可在欢迎页提供命令和面板，不借用当前工程的 hostTools 或设备授权。

命令调用串行处理；panel / log 事件按接收顺序交付，同一连接内较早发布的慢面板不会在较新面板之后回写。协议读取独立于事件处理，事件回调等待双向 hostCall 响应时仍可收包。等待事件数量有界，超限返回原始诊断，不丢弃部分状态后继续伪装正常。插件应传递取消令牌，停止自己的后台任务和订阅。

hostTools 只开放清单声明并由宿主实际提供的工具。工程路径、文件哈希、未保存缓冲区、审批和设备单一所有者检查继续生效。后台激活不应自动修改工程或连接硬件；拒绝授权后不能绕过 IDE 自行写入来完成原操作。

插件按当前用户权限执行。独立进程提供故障隔离和资源回收，文件哈希提供完整性验证；当前没有作者签名验证或操作系统权限沙箱。经 StudioX 桥接的白名单不能限制受信任插件直接访问该用户本来就能访问的文件与网络。

## UI、工具 schema 和数量边界

面板提交纯 JSON 数据，不加载任意 XAML、WPF 控件或 Web 页面。常用控件包括 text、table、tree、form、plot、button、input、number、checkbox 和 select。独立窗口需声明 panelWindows；每个控件引用的 commandId 必须已注册。

| 项目 | 上限 |
| --- | --- |
| 每个插件的命令 / Agent 工具 | 各 128 个 |
| 每个插件的面板 | 32 个 |
| 每个面板的顶层控件 / 总控件 | 128 / 256 个 |
| 面板嵌套 | 8 层 |
| 表格 | 2048 行、32 列 |
| 面板 JSON / 单控件 value | 1 MiB / 512 KiB |
| Agent 工具输入 schema | 64 KiB、16 层 |

Agent 输入使用明确的有限 JSON Schema 子集：支持 type、properties、required、additionalProperties、items、enum、const 和长度 / 数值范围。根类型必须为 object，每个对象显式给出 additionalProperties。远程引用、$ref、组合 schema、pattern、format 等未支持项会在启用前拒绝。工具描述在会话启动时固定，不能在同一 Agent 会话内动态改写。

能力数量按所选 API 的已知集合校验，不再将 API 3 的合法组合硬限为 10 项；仍拒绝重复能力、未知能力和不满足前置条件的组合。能力个数不等于控件、工具或文件数，各自的资源限制仍有效。

## 安装与验证结果怎样理解

安装只校验包，不执行插件。首次安装和更新默认禁用，启用表示信任该版本的内容；更新内容会撤销旧信任。停用会撤销在途调用和动态工具，迟到结果不能恢复已关闭的面板。

插件开发应分别验证：归档和清单、真实宿主生命周期、双向调用与取消、声明式 UI、工程写入拒绝及允许路径、所需语言运行时。离线测试或模拟快照通过不能代替 MCU 实板验收。完整开发说明和发布步骤见关联主题“插件 API：开发、协议与错误处理”。
