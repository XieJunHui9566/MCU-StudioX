# 断点、单步与源码调试

## 开始调试
1. 使用已支持器件与探针，核对下载设置。
2. 选择合适的调试信息，例如 `-Og` 与 `-g3`，成功编译并下载对应固件。
3. 按 `Ctrl+F5` 或“调试 → 启动 / 结束调试”。连接时会核对目标及当前 ELF 与板上程序的一致性。
4. 连接成功后观察暂停位置。需要从头运行时，在 `main` 内设断点，再使用复位和运行。

## 断点与单步
- `F9` 设置或删除当前位置断点；也可点击源码左侧断点槽。
- `Ctrl+F9` 启用或禁用断点，`Shift+F9` 打开条件、日志或临时断点设置。
- `F5` 运行，暂停按钮中断执行。
- `F10` 逐过程，`F11` 进入函数，`Ctrl+F11` 跳出函数。
- `Ctrl+F10` 运行到光标；先确认光标位置属于当前可执行源码。

## 看哪些窗口
调用栈用于选择栈帧；局部变量跟随所选帧，观察窗口查看指定表达式。寄存器、只读内存和反汇编帮助定位低层行为。黄色位置表示当前执行行，选择其它栈帧可能显示不同的源码位置。

安装并启用具有调试快照能力的插件后，可从插件管理页“打开调试扩展”或“工具 → 插件与扩展 → 调试快照扩展…”打开独立视图。暂停和单步后自动刷新，运行或断开时清除结果。扩展只解释已有快照，不自动连接或下载；使用离线示例时会注明模拟数据。解释出错时查看视图下方原始诊断，暂停后可以重试。

## 变量或源码看起来异常
高优化会消除变量或改变指令与源码行关系。先检查 ELF 是否含调试信息、板上固件是否一致，再考虑优化影响。把缓冲区或地址当变量观察时，还需核对作用域、类型和有效生命周期。

## 正确结束
用“结束调试”退出会话，检查目标恢复和探针释放结果，再下载或使用其它工具。异常断线可能使目标仍暂停；按实际状态重新连接或复位。源码调试入口会附加并检查固件，更新板上程序应使用下载流程。

## 外设寄存器（SVD）
从“调试 → 外设寄存器（SVD）”打开。选择厂商 SVD，并核对它适用于当前工程的准确型号后绑定。可按外设、寄存器、地址和说明搜索；选择后显示权限、参考复位值、位域和枚举。
只在固件已与 ELF 匹配的实机暂停会话中读取。点击“读取选中寄存器”才获取一次数据；有 readAction 副作用时单独确认，窗口不自动轮询。运行、单步、复位或切换工程后旧值清除。
写入前输入完整寄存器值并核对地址、位宽及 W1C 等语义，再确认写入。不执行隐式读改写或读回；只读、一次性写入、未知权限和写约束会阻止操作。目标状态变化后，旧写入预览失效。

## ESP-IDF 转储与历史 ELF
在固件故障分析选择“转储 + 工程 ELF”或“转储 + 归档 ELF”。工程 ELF 要求当前源码与成功构建记录一致；归档 ELF 由你明确选择故障固件对应的历史文件。
Base64 输入仅保留 CORE DUMP START/END 之间的正文，不含标记和串口前缀。明确选择 Base64、原始二进制或 ELF core 格式后解析，报告显示转储与 ELF 的 SHA-256、目标、开发环境组件版本、崩溃任务和调用栈。
带 ELF 摘要的转储会比较实际保存的摘要前缀，不一致即拒绝。旧格式可能没有摘要，此时不会把解析成功当作固件匹配。重新导入历史报告不会重新验证原文件。
解析使用工程锁定的 Espressif GDB，工具包缺少 GDB 时先准备补齐的受管理工具；不使用系统 PATH 的替代 GDB、不读取实板、不自动下载 ROM。
