# 工程终端、Git 与 GitHub

## 工程终端
“工具 → 工程终端”或 `Ctrl+反引号` 打开当前工程的终端。先核对工作目录与激活的开发环境组件，再执行命令。终端中的命令会真实影响文件；IDE 的保存快捷键与终端控制输入有不同上下文。

## Git 的常用顺序
1. 修改后先查看工作区差异，确认哪些源码和配置需要纳入版本记录。
2. 审阅并暂存所需文件，再填写清楚的提交说明。
3. 提交后检查记录，按需要切换分支或与远端同步。
4. 推送、合并或删除前核对当前仓库和分支，保留尚未提交的内容。
“工具 → Git 图谱”可查看提交与分支关系；新的工程可能已初始化仓库但还没有任何提交，这是正常状态。

## GitHub 协作
打开“工具 → GitHub 协作”，选择正确账号和仓库，查看远端分支或协作内容。登录和授权状态以该页面为准，不把 API Key、密码或账号文件提交到工程。

## 什么文件适合记录
一般记录源码、根 CMake、必要的配置和许可证。`.build` 缓存、编译产物和用户私有设置通常不纳入源码记录；ESP 的 `sdkconfig` 是否提交应按团队规则决定。先看工程 `.gitignore`，再审阅实际差异。

## 遇到冲突或目录移动
先保留未保存草稿，核对本地修改和远端变化，再逐文件处理。不要用强制覆盖整个工作区来消除不了解的冲突。移动工程后重新打开新路径，并在终端再次确认当前目录。
