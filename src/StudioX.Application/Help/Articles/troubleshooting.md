# 故障处理：先定位再修复

## 先收集四项信息
记录当前工程、准确器件或 SDK target、锁定开发环境组件版本、触发失败的具体操作。保留从阶段开始到失败结论的原始日志，尤其是最早的实际错误和前后命令。截图有助于说明界面，但只有最后一行“失败”不足以定位原因。

## 按失败阶段选择主题
| 现象 | 先检查 | 继续阅读 |
|---|---|---|
| 工具校验失败 | 所需 ID、版本、文件与完整性 | 内置开发环境组件 |
| CMake 配置失败 | 第一个 CMake Error、目标与路径 | 编译失败 / ESP-IDF 故障 |
| 编译或链接失败 | 文件、包含目录、目标源码与内存 | 编译失败、头文件与链接错误 |
| 串口连接或数据异常 | 端口占用、参数、编码与数据组 | 串口故障 |
| 调试失败或断点不命中 | 目标、探针、符号及板上固件 | 调试连接与断点 |
| 保存、替换或恢复异常 | 草稿、磁盘版本与文件权限 | 保存冲突与本地历史 |

## 建议处理顺序
1. 保存或复制当前未保存内容，避免排错过程中失去草稿。
2. 查第一条真正失败的诊断；单纯警告可能与失败无关。
3. 按具体原因只调整相关配置或文件，一次改动后重新验证。
4. 记录重试结果。检查退出码、产物和实际界面状态，而不是只看旧的成功文件。
5. 仍然失败时提供完整日志和已经做过的步骤，便于继续定位。

## 日志在哪里
构建日志通常在工程 `.build/studiox-build.log`；ESP-IDF 额外原始输出在 `.build/log`；调试和下载在对应会话目录或设备输出；插件日志在插件管理页。日志可能包含本地路径和工程内容，分享前检查是否含密钥或私有信息。

## 尽量保留的内容
保留源码、`sdkconfig`、工程工具锁、未保存草稿和原始设备日志。不要通过清空整个工程、删除 Git 记录、混用开发环境组件版本或盲目擦除芯片来处理尚未定位的问题。
