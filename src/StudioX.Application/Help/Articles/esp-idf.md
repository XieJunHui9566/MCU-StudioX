# ESP-IDF 工程与模组配置

## 新建时选择 IDF 版本
选择厂商、ESP32 器件包、准确芯片和模板后，页面会显示“ESP-IDF 开发环境组件版本”。列表显示 SDK 版本、开发环境组件版本及可用状态；初始选择保持你明确选定的器件包，不自动换到最新 SDK。

切换版本时，页面同时选择该芯片和模板的匹配器件包，“所需开发环境组件”随之更新。点击创建后，新工程锁定所选 SDK 和组件版本；以后导入其他 IDF 不会改变它。已安装组件但缺少匹配器件包时显示“缺少匹配器件包”，需导入对应 `.mcupack`，不能借用另一 SDK 的模板。

“组件未安装”仍可创建和编辑工程，编译前通过“准备工程开发环境组件”导入对应 `.mcutoolchain`。已禁用版本需要先在组件管理重新启用，损坏版本需要修复。ESP8266 RTOS SDK 使用独立入口，不混入 ESP32 的 IDF 版本列表。

## 工程版本身份
工程信息和构建日志会显示框架、SDK 版本与 target，例如 `esp-idf 5.5.4 · target=esp32s3`。ESP32、S3、C3 等是不同目标，编译器和配置需匹配。ESP8266 使用独立 RTOS SDK，不能作为 ESP-IDF 5.5.4 的一个 target 直接套用。

开发环境组件版本与 SDK 版本分别记录；组件包的修订不一定改变内部 SDK。工程同时锁定组件 ID/版本、内容指纹及 SDK/target，不会因为导入新组件而自动切换。需要升级时，先导入声明新需求的器件包和对应组件，再从“软件与组件分发”创建升级验证副本；核对预览、编译和应用行为后使用副本，原工程仍可继续使用原版本。配置输入会保留在副本的 `.studiox/migration-inputs/`，具体操作见“安装精确版本工具和插件”。

完整安装包预置的 IDF 仍为 5.5.4；其他版本由对应开发环境组件和匹配器件包提供，多版本可以并存。只支持明确的 SDK 版本，不使用 latest 或版本范围。新建验证副本使用不含空格或分号的 ASCII 目录名；原生工具遇到路径约束时会在运行前提示。Windows 短名称不一定能把中文转换为 ASCII，工具所在目录也需要满足此条件。IDE 不自动下载 SDK，也不代替 SDK API 迁移。

## 原生工程结构
根配置包含 IDF 的 `project.cmake`，应用通常位于 `main/`；组件维护自己的 `idf_component_register`。`sdkconfig.defaults` 提供默认值，原生配置生成或使用 `sdkconfig`。StudioX 使用锁定 SDK 的原生 `idf.py`、CMake 与 Ninja，不要求安装全局 Python。

## 打开时的后台自检
上次构建占用统计可能需要校验大量 SDK 文件，左侧构建分析器会显示后台进度。编辑器与代码提示先就绪，可以继续编辑；点击顶部停止按钮可取消这项统计。切换、关闭工程或开始编译时会取消旧统计，取消不会修改源码、sdkconfig 或工具锁。未编译过的工程直接提示“编译成功后显示各存储区占用”；编译和下载前仍会进行必要的工具校验。

## 设置 Flash 和 PSRAM
1. 打开“工具 → 器件与模板”，找到 ESP 模组配置。
2. 按模组完整标识选择预设，或者明确填写实际 Flash 容量、频率、PSRAM 类型和容量等。
3. 核对摘要，保存配置后重新编译。
4. 如果选择沿用原生配置，继续以已有 SDK 配置为准；不要根据开发板商品名猜 PSRAM。

## 添加组件与编译
把源码加入应用或新组件的注册列表。模板启用 `MINIMAL_BUILD` 时，要明确声明新增功能所需的组件依赖。保存后按 `F7`，配置成功将生成编译数据库，随后编译应用、bootloader 和分区表。SDK 头文件提示可在原生配置完成后获得更完整的信息。

## 下载前检查
核对实际芯片、COM 端口和 Flash 参数，使用当前工程生成的完整布局。ESP 下载时串口需可用；先断开占用同端口的串口终端或 MicroPython 会话。出现配置冲突、target 不匹配或缓存问题时，继续阅读“ESP-IDF 常见配置与编译故障”。
