# 安装精确版本工具和插件

打开“工具 → 插件与扩展 → 软件与组件分发…”，点击“已验证组件库”即可读取 MCU StudioX 公开组件仓库的签名目录，无需手动填写地址或选择公钥。IDE 随程序分发发布者公钥并固定核对指纹；签名失败会显示原始错误，不会改用未验证目录。打开页面不自动联网。

也可以输入自定义 HTTPS 地址或选择本地 catalog.json，点击“读取目录”后访问。自定义目录可选择通过独立可信渠道取得的发布者公钥。

## 选择和预览

按开发环境组件、插件或组件筛选，也可搜索 ID、名称和许可证。选中条目后核对精确版本、来源链接、许可、更新说明、插件 API、归档 SHA-256，以及下载和展开大小。磁盘预估包含缓存和安装暂存；空间不足时不能开始安装。

“工程所需工具”定位当前工程锁定的 ID/版本。目录缺少该版本时，换用正确目录或通过“导入开发环境组件…”导入 .mcutoolchain；已有 .studioxtools 归档仍可使用。不能用“最新版本”替代缺失的工程锁定版本。

“下载并预览升级”只下载所选工具归档并显示与当前已打开工程的比较，不安装、不执行工具。预览包含精确组件/编译器身份、内部开发环境组件版本差异、被移除的文件样例和迁移前提。相同编译器不代表组件兼容；不同 IDF SDK 版本还需要 SDK 配置与 API 迁移。没有打开工程时只显示组件信息，不给出工程兼容结论。

“下载并预览安装”先检查归档长度和 SHA-256，再展示上述比较和安装信息。相同工程版本但编译器、入口或内容指纹不符时阻止安装；其他版本可并存安装，工程仍使用原来明确指定的版本。安装前重新核对归档和工程配置，变化后需要重新预览。工具完整文件由安装服务校验。

换版本需要明确匹配的器件包、工程迁移及实际编译验证；当前页面提供只读预览，不自动修改工程版本或删除内容锁。原版本可在工具管理中保留或恢复。

## 创建升级验证副本

先导入明确声明新组件版本的 `.mcupack`，安装所需组件，再打开原工程并点击“创建升级验证副本…”。从已安装包中选择同一器件和模板的新包版本，选择父目录和新的子目录名称，核对预览后创建并编译。原工程保留，验证通过后可从“文件 → 打开工程”检查副本；随时重新打开原工程继续使用原版本。

副本保留应用源码、用户根 CMake 配置、编译设置和 STC 时钟配置，器件支持换成明确选择的新包；旧内容锁、构建缓存、Git 历史和调试会话不会带入。器件支持文件被修改、添加或删除，架构、CPU/ABI、内存布局或构建目标改变时，自动迁移会停止，须人工审阅。源码、配置、锁或目标包在预览后发生变化时须重新预览。副本必须是原工程以外的全新目录，路径不能通过链接指回原工程。

编译失败或取消后，已创建副本及 `.studiox/component-migration-result.json` 保留，页面显示原始诊断，可打开副本修复；原工程不受影响。ARM、RISC-V、STC 的原生 Pack、Espressif SDK、AGM 引脚映射及自定义逻辑工程使用此入口。CubeMX、MicroPython 和 Zephyr 当前需要专用迁移流程，页面会明确提示。编译成功只证明软件构建通过，应用行为和实板功能仍需确认。

ESP 工程保留原生组件、CMake、`sdkconfig`、`sdkconfig.defaults`、依赖锁和模块选择；配置输入另存于副本的 `.studiox/migration-inputs/`，可与构建后的配置比较。SDK 的 Kconfig 可能更新副本配置，IDE 不改写应用 API；真正切换 SDK 时请核对对应[官方迁移指南](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32/migration-guides/index.html)。当前开发构建已在隔离工程验证 IDF 5.5.4、5.5.5、6.0.3、6.1.0；预装仍是 5.5.4，新增版本的本地编译验证不代表公开组件发布或实板验收。ESP8266 RTOS SDK 为 3.4.0。不同 SDK 须使用经过验证的组件和匹配器件包，新建 ESP 工程明确选择 IDF 组件版本，不按最新版猜测。

新建 ESP 验证副本请选择不含空格或分号的 ASCII 目录名。已有父目录可以使用实际可用的 Windows 短路径；新目录尚未创建，不能保证短名称可用。预览会在复制和工具校验前提示不支持的路径，不调整系统磁盘设置或搬移原工程。

AGM 工程保留 VE 的引脚、命名、时钟、模拟配置，以及 Verilog、SDC、逻辑/仿真设置。副本重新生成系统文件并构建映射或逻辑镜像；手动改过的系统生成文件会阻止替换。本机 Supra 许可沿用私有用户目录，不随工程或组件复制。

开发环境组件版本与内部 GCC/SDK 版本分别记录。修订 IDF 组件包可以继续使用同一个 SDK；工程同时锁定组件身份和 SDK 身份，构建核对受索引的 `version.txt` 及目标支持文件。仅改目录名或清单的版本不能把一个 SDK 冒充另一个发行。

## 来源与信任

已验证组件库固定使用 IDE 内置公钥，不从服务器下载公钥；取消自定义公钥也不会取消此目录的验签。发布者 SPKI SHA-256 指纹为 `02f415bbe0abdf7ffaf456731187354593de93663a66f3dc4b48bf1be3e7e594`。密钥更换需要新的受信任 IDE 发行，不能通过修改目录自我授权。

自定义目录没有公钥时“发布者”只是目录自述，哈希验证内容完整性。“自定义目录公钥”从可信途径取得 PEM 公钥后，验证目录旁的 catalog.json.sig；签名匹配所选密钥并显示密钥指纹。不要仅因为公钥和目录来自同一地址就认定发布者可信。更改来源、公钥或取消自定义公钥会清除旧目录选择，须重新读取。

## 插件更新与回退

插件安装后默认停用，更新和回退都会撤销旧信任。到插件管理页审阅能力后重新启用。“回退插件”使用更新前保存并校验的归档；普通安装仍拒绝降级。插件运行在独立进程，仍拥有当前用户权限。

## 轻量版与完整版

默认完整版预装开发环境组件，适合开箱使用。轻量版保留相同的自包含 IDE、器件包、内置插件、语言服务、Git 和独立宿主，开发环境组件按工程需要导入 .mcutoolchain 或从可信目录安装。两种版本都能导入组件，共用产品身份和版本规则；IDE 本身仍由安装包更新且拒绝降级。

完整包和轻量包可以在原安装位置互换。已有组件按整个版本目录保留，损坏的目录需要使用“工具校验与修复”，覆盖安装不会把它与预装文件混合。新组件版本可以并存，已有工程的版本和内容锁不自动改变。卸载 IDE 也保留这些组件，可在卸载前用工具管理检查占用并清理无用版本。

独立开发环境组件仓库 [MCU-StudioX-Toolchains](https://github.com/XieJunHui9566/MCU-StudioX-Toolchains) 保存组件登记、来源、验证和签名目录。首个公开组件是 `stc.sdcc/1.0.1`，包含 SDCC 4.5.0、CMake 4.4.0 命令行和 Ninja 1.10.2，约 55 MiB；Release 同时提供源码、许可证和验证材料。其余原有组件仍在补齐发布材料，登记不代表可下载。

新版 SDCC 组件从官方文件组装，不包含旧安装目录中的 STC 厂商头文件和备份。原有工程和器件包声明的 `1.0.0` 不自动改为 `1.0.1`；使用新组件须明确切换版本或使用声明该版本的器件包，并检查工程是否依赖被移除的额外头文件。

两种安装包共用“已验证组件库”入口和内置公钥。产品代码签名与组件目录签名分别管理。目录签名确认发布者和内容，升级预览只检查元数据；编译验证和实板验收仍是独立过程。

## 准备工程开发环境组件

“工具 → 开发环境组件 → 准备工程开发环境组件…”也可从第一个工程引导、健康检查缺失工具项、开发环境组件和分发页进入。它只读取工程明确的版本、编译器、内容锁和必要入口，不遍历 SDK 或自动联网。

选择“自动从 GitHub 获取”，点击“获取并安装工程缺少的组件”，IDE 用内置来源和可信公钥自动匹配、下载、校验并安装全部缺失版本，无需输入地址。全部版本有公开条目才开始获取；未提供的版本明确列出，不能用其它版本代替。被禁用或损坏的已有组件分别进入启用和修复流程。

选择“手动导入本地组件”，点击“选择 .mcutoolchain 并导入…”，可一次选择多个工程所需归档。整批身份检查后展示预览，确认后完整校验安装，不访问网络。支持 7z/LZMA2、新旧 ZIP 格式 1 组件和已有 .studioxtools；本地归档不会继承在线目录的签名状态。

“浏览 GitHub 组件库 / 其它版本”直接打开并验签读取分发页，工具菜单也有“从 GitHub 获取开发环境组件…”入口。自定义 HTTPS / 离线目录、公钥和逐项下载预览保留在折叠的“高级”区域。

页面“取消操作”或顶部停止按钮取消下载或安装。取消和网络中断保存下载进度；下次获取同一归档可继续。服务器不支持续传时从头获取；范围、长度或哈希异常会清除无效片段。每个组件独立暂存并原子发布，取消保留已完成组件，页面刷新后可以只准备剩余组件。安装时再次校验完整工具内容。缓存位于独立用户目录 distribution-cache，不修改系统 PATH。

已有工具目录损坏时点击“工具校验与修复”，用精确版本离线归档修复。安装后请重新运行健康检查或编译；快速入口通过不代表 SDK 完整校验通过。预览后工程配置或内容锁改变时拒绝安装，请刷新检查。MicroPython 不要求原生编译工具；Zephyr 实验工程不会被自动当作已验证环境。
