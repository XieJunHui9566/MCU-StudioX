# 内置工具环境与离线修复

## 版本从哪里来
工具随 IDE 管理，工程按自己的工具 ID 和版本锁定。系统另装 GCC、Python 或 OpenOCD 不会成为当前工程的默认工具；通常无需改系统 PATH 或安装全局语言环境。

## 检查工具
可先打开“工具 → 工程健康检查…”：快速检查当前工程需要的版本、工具锁、SDK 入口与缓存，不遍历全部 SDK。需要核验内容和程序能否启动时，点击“深度工具检查”；大型 SDK 耗时较长，可用顶部停止按钮取消。选择问题后可定位到工具环境中的具体版本，或阅读对应帮助。

1. 打开“工具 → 工具环境管理…”。
2. 找到“工程需要”列标出的工具集，核对 ID、版本和组件信息。
3. 选中条目并执行“校验所选工具集”，查看缺失、变化或完整性通过的结果。
4. 将结果与构建日志中的实际可执行程序路径对照。

## 导出离线包
选中完整且通过校验的工具集，点击“导出离线工具包”，保存 `.studioxtools` 文件。导出包用于搬运或修复明确的工具版本；它与器件包 `.mcupack`、插件包 `.studioxplugin` 是不同类型。

## 从离线包修复
结束正在使用工具的调试、构建等会话，选中待修复工具，点击“从离线包修复”。使用同 ID、同版本的包，查看校验与备份结果，再重新构建。修复过程中保留原工具备份，失败时检查原始诊断，不手工拼接多个版本的目录。

## 常见错误
`TOOLSET_MISSING` 表示所需工具集不可用；哈希变化表示文件与分发索引不同。路径错误应核对安装目录与工程路径。对于带空格的 Windows 路径，ESP 工具使用受检查的短目录路径；磁盘无法提供可用路径时按具体提示调整存放位置。

## 占用、升级与旧版本
打开“工具 → 工具占用与升级管理…”。列表显示版本、逻辑文件大小、依赖来源和 IDE 占用。选中条目查看哪些工程、工具内容锁、器件包或内置功能要求此版本。当前工程、最近工程和手动登记工程参与检查；其他工程使用“登记其他工程…”加入，不能由扫描结果推断整台电脑都没有引用。无法读取任何依赖记录时，清理会暂停。

“预览并安装新版本…”读取 `.studioxtools` 的明确 ID、版本、组件信息、已有版本及展开大小。确认后完整校验归档，安装到独立版本目录。现有工程和器件包继续使用原先锁定的版本；SDK 升级需要匹配新版器件定义，不通过删除工具内容锁强行切换。相同版本已存在时改用上面的离线修复入口。

未被依赖或占用的旧版本可以“移至可恢复区…”。每种工具的最新已安装版本保留。可恢复区仍占磁盘空间；“恢复此版本…”先完整校验，再放回原目录，不覆盖同版本。确实不再需要时另行“永久删除可恢复版本…”，再次检查工程依赖后才能执行。永久删除不可恢复；失败中断后刷新重试剩余内容，该版本不会再提供恢复按钮。

逻辑大小包含文件内容长度，硬链接、压缩和文件系统分配会使实际释放空间不同。不要按显示数字推断一定释放同等空间。工具校验、编译进程及调试会话使用跨进程租约；正在使用时维护会被阻止，不通过强杀工具进程完成清理。报告保存到本机，不自动上传，不修改系统 PATH。
