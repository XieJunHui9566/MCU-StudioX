# 开发环境组件管理与修复

## 版本从哪里来
工具随 IDE 管理，工程按自己的工具 ID 和版本锁定。系统另装 GCC、Python 或 OpenOCD 不会成为当前工程的默认工具；通常无需改系统 PATH 或安装全局语言环境。

## 何时校验
IDE 启动和打开管理列表只读取组件清单，不自动校验全部组件。构建、调试或使用专用功能时，只校验该工程或功能明确需要的 ID 与版本；工程声明的辅助组件也参与检查。同一次启动中，未发生变化的目录复用成功校验结果。进度显示正在检查的组件 ID、版本和文件数，不会把其它版本混入当前工程。

“工具 → 开发环境组件 → 校验当前工程的开发环境组件”完整核验当前工程声明的组件及内容锁，并查询可执行入口版本。没有打开工程时此入口不可用。“完整校验”按钮只检查管理页选中的那个版本。大型 SDK 可用顶部停止按钮取消；取消或失败的检查结果不会被缓存。

## 检查组件
新建工程时，“所需开发环境组件”列出所选器件和模板要求的精确版本。缺少组件也可以先创建和编辑；编译前需准备全部组件。器件包可以声明额外工具需求，安装了主 GCC 不一定表示全部准备完成。

打开“工具 → 开发环境组件 → 准备工程开发环境组件…”查看每个组件的 ID、版本、用途和状态。选择“未安装”项，用“导入开发环境组件…”选择对应 `.mcutoolchain`，核对预览后安装；已有目录缺失文件或内容不符时使用修复入口。刷新后所有组件就绪，再尝试配置/编译。目录未配置时可直接使用离线包，不需要先连接 GitHub。

可先打开“工具 → 工程与构建 → 工程健康检查…”：快速检查当前工程需要的版本、工具锁、SDK 入口与缓存，不遍历全部 SDK。需要核验内容和程序能否启动时，点击“深度工具检查”；大型 SDK 耗时较长，可用顶部停止按钮取消。选择问题后可定位到开发环境组件中的具体版本，或阅读对应帮助。

1. 打开“工具 → 开发环境组件 → 开发环境组件管理…”。
2. 选中工程锁定的 ID 和版本，在详情中核对用途、依赖和组件信息。
3. 点击列表上方的“完整校验”，查看缺失、变化或完整性通过的结果。
4. 将结果与构建日志中的实际可执行程序路径对照。

## 导出离线包
选中已安装的开发环境组件，点击“更多操作 → 导出为 .mcutoolchain…”。导出前自动完整校验所选版本，默认保存 7z/LZMA2 格式的 `.mcutoolchain` 文件，包含编译器、SDK 及该版本配套依赖，用于搬运、并存安装或离线修复。它与器件包 `.mcupack`、插件包 `.studioxplugin` 是不同类型。已有 ZIP 格式 `.mcutoolchain` 和 `.studioxtools` 格式 1 归档仍可导入和修复。

## 从离线包修复
结束正在使用组件的调试、构建等会话，选中待修复版本，点击“更多操作 → 从本地文件修复…”。使用同 ID、同版本的包，查看校验与备份结果，再重新构建。修复过程中保留原组件备份，失败时检查原始诊断，不手工拼接多个版本的目录。

## 常见错误
`DEVELOPMENT_COMPONENT_REQUIREMENT` 表示工程、器件或模板的需求声明不一致，例如同一组件指定两个版本；重新核对创建时选择的包和工程配置。`TOOLCHAIN_LOCK` 表示版本或清单内容与已有内容锁不一致，应恢复相同组件，不删除锁来切换版本。首次构建完整校验通过后建立的 `development-components.lock.json` 记录全部组件，旧主工具锁也继续有效。

`TOOLSET_MISSING` 表示所需开发环境组件不可用；哈希变化表示文件与分发索引不同。路径错误应核对安装目录与工程路径。对于带空格的 Windows 路径，ESP 工具使用受检查的短目录路径；磁盘无法提供可用路径时按具体提示调整存放位置。

## 占用、升级与旧版本
打开“工具 → 开发环境组件 → 开发环境组件管理…”。列表显示版本、逻辑文件大小、依赖来源和 IDE 占用。选中条目查看哪些工程、工具内容锁、器件包或内置功能要求此版本。当前工程、最近工程和手动登记工程参与检查；其他工程使用“登记其他工程…”加入，不能由扫描结果推断整台电脑都没有引用。无法读取任何依赖记录时，清理会暂停。

“工具 → 开发环境组件 → 导入开发环境组件…”和管理页的“导入开发环境组件…”读取 `.mcutoolchain` 的明确 ID、版本、主机平台、内部开发环境组件版本、已有版本及展开大小。此入口同时用于完整包和轻量包。确认后完整校验归档，安装到独立版本目录。文件名不决定组件身份，预装组件与导入组件使用同一个 ID。相同 ID 和版本已经安装相同内容时，重新完整校验归档和现有组件，成功后跳过重复安装；不同内容拒绝覆盖，组件损坏时使用离线修复入口并保留原目录备份。

现有工程和器件包继续使用原先锁定的版本；SDK 升级需要匹配新版器件定义，不通过删除工具内容锁强行切换。“准备工程开发环境组件”提供自动从 GitHub 获取与手动导入两个模式；点击获取按钮后才联网，缺少公开条目时不会改用其它版本。“工具 → 开发环境组件 → 从 GitHub 获取开发环境组件…”可浏览已验证组件库。尚未公开发布的版本使用经过确认的本地归档。

### 禁用与重新启用
在“开发环境组件管理”选中已安装版本，点击列表上方的“禁用”。有依赖时先显示受影响的工程、器件包和功能，确认后切换状态。文件、工程配置和内容锁保留；需要该版本的工程会报 `TOOLSET_DISABLED`，不会自动改用其他版本。禁用后按钮变为“启用”，重新启用即可恢复使用。状态只存入当前用户的独立数据目录，关闭 IDE 后仍保留。同一 ID 的其他版本不受影响。

正在构建、校验、维护或调试占用的组件不能切换状态。已禁用的组件仍可做完整文件校验及离线导出，但不能启动其中的工具程序。工程工具准备页面显示“已禁用”，应到组件管理启用，而不是重复下载。

### 调试环境检查
选中已启用的组件，点击“调试环境检查”。它先完整校验文件，再查询组件声明的 GCC、GDB 和 OpenOCD 版本，显示退出码、超时状态和原始输出。当前工程需要该组件时，按工程 target 选择对应工具；没有声明这些入口的专用组件会给出说明。

此入口不探测端口、不复位、不连接设备，也不启动调试会话。实机调试仍从当前工程的调试菜单选择探针与会话；工具能启动不代表硬件已经通过验证。

### 删除与可恢复区
“删除…”直接删除所选 ID 与版本，包括最新版本。确认框列出受影响的依赖、逻辑大小和不可恢复提示。删除不会改动工程源码、配置或内容锁；需要该版本的工程会提示缺少组件，重新导入相同版本后才可继续使用。确认后重新核对文件身份、依赖和占用；新出现的依赖会使本次操作停止，要求刷新并重新审阅。正在使用或身份、依赖无法核实的组件不能删除，按钮旁会显示原因。

不确定是否还需要时，选择“更多操作 → 移至可恢复区…”。此步骤移出安装目录但仍占磁盘空间；列表选中该版本后点击“恢复…”即可完整校验并放回原目录，不覆盖同版本。也可点击“删除…”清空它。永久删除中断后，管理记录保留，刷新可重试剩余内容；已经开始删除的版本不能恢复。常规旧版本清理接口仍保留最新和有依赖的版本，只有明确审阅并确认的管理操作可以移除它们。

逻辑大小包含文件内容长度，硬链接、压缩和文件系统分配会使实际释放空间不同。不要按显示数字推断一定释放同等空间。工具校验、编译进程及调试会话使用跨进程租约；正在使用时维护会被阻止，不通过强杀工具进程完成清理。报告保存到本机，不自动上传，不修改系统 PATH。
