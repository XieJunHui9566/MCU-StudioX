# STC图形化配置 0.01

准确支持 **IAP15L2K61S2 / LQFP44 / 裸机 C / SDCC 4.5.0**。插件显示版本为 0.01，契约版本为 0.0.1；配套器件包为 0.1.4，profile 为 3.0.0。插件也支持 0.1.3 包 / 2.2.0 profile 的旧能力，不静默替换旧工程资料。活动栏图标包含 STC 字样，颜色跟随 IDE 主题。产品版本不变；仅验证离线配置、工程写入与实际编译。

## 使用

1. 使用包含本轮通用界面和 `mcuCodeGenerationV1` 应用服务的 IDE 源码构建；旧安装版会拒绝未知能力。
2. 导入 `stc.iap15l2k61s2.config-preview-0.1.4.mcupack`，选择 IAP15L2K61S2 与 LQFP44 图形配置模板创建工程。新模板具备稳定 main 接入点；普通 STC 工程与旧版配置工程不自动迁移。
3. 导入并明确启用 `studiox.stc15-configurator-0.0.1.studioxplugin`。从 0.1.x 开发试用版切换时先卸载旧插件，再导入并启用；用户工程与配置保留。入口、命令和面板仅在该准确工程显示；其它型号、普通工程或未打开工程时隐藏。
4. 横向“引脚与外设”页左侧按类别配置 GPIO、UART1/2、Timer0/1/2、ADC、SPI、PCA 与系统外设，右侧显示四边引脚封装图。左键点击引脚选择或释放功能，右键设置名称、锁定或解除锁定；GPIO 电气模式和初始电平仍在左侧设置。锁定保护功能分配及外设换脚，名称和锁定随配置保存。
5. 独立“时钟树”页选择内部 RC 或实装外部晶振，源频率单位 MHz，可编辑也可下拉选择。九个推荐值来自 STC-ISP 6.97C 准确型号控件；最多六位小数，保存为整数 Hz。时钟及外设选择自动更新草稿，切换页签前提交当前输入，三路定时器的用途、分频和 UART 时钟来源同步到时钟树。
6. 文本输入停止 400 ms 后自动检查；无效输入保留并显示提示，也可点击“应用参数并检查”。“保存配置”只保存 `.mcuconfig`；“生成代码”同时保存当前有效配置、生成文件并接入主函数与构建列表，无代码预览页。
7. 下载页时钟由插件托管并只读，串口和传输波特率仍可编辑。RC 24 MHz、系统二分频时，ISP 目标 24 MHz，编译与 UART/Timer 使用 12 MHz。配套 SDCC 上电钩子在 main 前配置 CLK_DIV，保留其它位。

## 自动生成

输出位于 `src/generated/mcuconfig` 和 `include/generated/mcuconfig`：

- `gpio.c/.h`：所选 GPIO 的初始锁存器、电气模式和用户引脚名称宏。
- `timer.c/.h`：Timer0/1/2 的内部定时或外部计数、16 位自动重装和可选 CLKO，保持停止。
- `uart.c/.h`：UART1/2 路由、RX/TX 模式和波特率。UART1 可选 T1/T2、1T/12T；UART2 固定 T2、可选 1T/12T。共用 T2 必须同波特率、同分频。两个串口分别提供“生成 USARTx_printf”开关，默认关闭。
- `adc`、`spi`、`pca`、`exti`、`wakeup`、`lvd`、`iap`、`clock_output`、`wdt`：按实际启用生成各自 `.c/.h`，关闭后再次生成会移除生成器拥有的旧文件。
- `mcuconfig.c/.h`：统一资源检查与 EA 保护，协调上述模块；看门狗最后开启。
- `Delay.c/.h`：每次生成均提供 `void Delay_ms(uint16_t XMS)`，按当前时钟树的分频后 SYSCLK 重新计算软件延时，不占用定时器。

应用服务在 main 模板标记中加入头文件与 `sx_mcuconfig_init()` 调用，上电入口直接调用，不再插入失败空循环；需要运行中重配时由调用者处理返回值；在根 CMake 的专用块中登记所有生成源码。用户可以在初始化调用下一行添加业务代码；已有生成凭据且原始调用完整时，即使后续代码位于 init end 标记之前，重生成也原样保留整个初始化块。缺失或修改入口调用仍会提示修复，不自动覆盖。不要在运行中单独调用模块初始化；需要的 ISR、启动计时器和应用通信由用户编写。

51 引脚命名直接生成位别名：例如 P1.0 命名为 `LED`，`gpio.h` 输出 `#define LED P10`。`mcuconfig.h` 包含 `gpio.h`，生成后 main 可直接写 `LED = 1;`、`LED = 0;` 或 `LED = !LED;`。其它源文件包含 `generated/mcuconfig/gpio.h` 即可使用；已命名的 UART 引脚也按实际端口生成别名。名称区分大小写，须为不超过 32 字符的 C 标识符，不能重复或与 C 关键字、器件寄存器、生成器保留符号冲突。重命名、清空名称或释放引脚后再次生成会移除旧宏。旧版仅显示用的不合法名称仍可打开，在界面修正后才能生成；不要手改生成头文件。寄存器保留符号与配套 `stc15.h` 的来源摘要记录在 `Assets/stc15-register-symbols.json`。

首次同名文件、手改生成文件、只读、缺失接入点、复杂 CMake、脏编辑器或磁盘变化均拒绝覆盖。成功记录实际输出摘要；更改外设或时钟后需要重新生成。用户数据目录保留事务备份，中途失败自动回滚，重启打开工程恢复；有外部冲突时保留备份与待恢复标记。

完整字段、授权和恢复限制见[有限生成契约](../../docs/GRAPHICAL_CONFIGURATION_GENERATION.md)。该能力不等于设计草案的完整 `mcuConfigurationV1` 协议。MCP 直接调用插件生成动作只取得计划，不写工程。

## 串口 printf

在 profile 3.0.0 工程的“引脚与外设 → 通信 · UART1 / UART2”中，先选引脚组与波特率，再开启对应的“生成 USART1_printf / USART2_printf”，最后点击“生成代码”。函数定义和声明写入 `uart.c/.h`；`mcuconfig.h` 自动引入 `uart.h`，main 的已有生成接入点即可使用：

```c
USART1_printf("value=%d, hex=%04X\r\n", value, (unsigned int)mask);
USART2_printf("%s: %lu\r\n", "count", (unsigned long)count);
```

接口为 `int USARTx_printf(const char *format, ...)`。调用方式、参数提升和格式说明符沿用 SDCC 4.5.0 的 C `printf` 库，成功返回输出字符数，失败返回 `-1`，失败前可能已有部分字符发出。直接逐字符格式化发送，不使用定长字符串缓冲区，也不重定向全局 `putchar`；`\n` 原样发送，需要 CRLF 时显式使用 `\r\n`。当前 mcs51 默认库未开启浮点：`%f` 输出 `<NO FLOAT>`，`%e/%g` 不受支持，不宣称完整桌面 libc 格式集合。依据为随锁定工具链提供的 `include/stdio.h`、`lib/src/vprintf.c`、`lib/src/printf_large.c` 和 [SDCC 手册 3.14.2](https://sdcc.sourceforge.net/doc/sdccman.pdf)。本次不复制或修改工具链格式化库。

SDCC 原库还存在字符串宽度与精度组合的差异：`%8.3s` 对 `"abcdef"` 输出 `"  abc"`，宽度按截断前长度计算。单独的 `%8s`、`%.3s` 已按预期验证；需要精确表格对齐时避免组合这两个修饰。本插件保留与工程原有 `printf` 一致的库行为，未修改工具链实现。

这是主循环中的阻塞轮询输出。先完成 `sx_mcuconfig_init()`；对应 UART 中断保持关闭，应用不能同时操作 TX 寄存器或完成标志。轮询有与实际波特率对应的次数上限，故障会返回错误，不承诺精确毫秒超时；超时后保留未完成发送状态，再次调用先等待该字节完成，避免覆盖发送寄存器。两个函数共用格式化锁，仅短暂关中断取得锁，保持调用前 EA 状态；默认 SDCC 格式化库不可重入，因此 ISR 中也不能调用其它 `printf/sprintf` 函数。低波特率或长输出会占用主循环时间，启用看门狗的应用应自行安排打印长度和调度。

配置仅在 UART 的 `parameters` 中增加可选布尔项 `printfEnabled`，缺失视为关闭，不修改模板基础信息及摘要。开关关闭或 UART 停用后重新生成会移除对应函数和声明；未选择时不引入格式化实现。旧 profile 2.2.0 保持原有初始化功能。器件包版本和 IDE 产品版本保持不变。

## 软件毫秒延时

点击“生成代码”后，`main.c` 通过已有的 `mcuconfig.h` 接入点可直接调用 `Delay_ms(1000U);`。其它 C 文件包含 `generated/mcuconfig/Delay.h`。参数单位为毫秒，范围 0–65535；`Delay_ms(0)` 直接返回。不需要额外开关或初始化调用，Timer0/1/2 的用途保持不变。时钟树修改后再次生成会重算 `Delay.c`；只保存配置不会擅自改写源码，旧生成状态仍由已有时钟/构建检查拦截。

计算参考 STC-ISP/AiCube 6.97C 的 **STC15** 两层 C 倒数循环与 [IAP15L2K61S2 系列手册 5.2](https://www.stcmicro.com/datasheet/STC15F2K60S2-en.pdf)。生成的函数完全使用 C 语言，声明为 `void Delay_ms(uint16_t XMS);`，不包含内联汇编、裸函数、NOP 内建或手工调用约定。两层 `volatile uint8_t` 计数器保证等待循环不会被优化删除。

厂商示例的循环常量依赖编译器，不能直接套在 SDCC 上。配套 SDCC 4.5.0 mcs51 的默认、Os、O2 设置下，每次字节倒数及判断为 9 个 SYSCLK 周期；每毫秒循环为 `21 + 9 × (j + 256 × (i−1) + i)` 周期，插件选取最接近当前 `SYSCLK / 1000` 的 i/j。计数初值 0 表示无符号字节的 256 次回绕。调用及返回另有 20 周期，每跨越一次 XMS 低字节借位增加 2 周期。例如 12 MHz 的每轮为 12000 周期。极低 SYSCLK 下，最小 39 周期的循环已超过 1 ms，生成注释列出实际周期数，不承诺精确毫秒。

C 软件延时的实际时间受编译器、优化等级、中断和振荡器误差影响；O0 下循环更慢，只验证可编译并有限返回，不宣称 O0 的毫秒精度。函数供主循环阻塞等待，不关中断、不自动喂狗；运行中改时钟会使校准失效。不要在 ISR 中调用或用于精密脉冲。长延时与看门狗的配合由应用负责。验证覆盖真实 SDCC 编译链接、链接后机器码周期核对、系统分频和计数回绕，以及默认/Os/O2 的 0、255/256/257、65535 参数边界；未进行实板计时测量。

## 边界与验证

内部 IRC 5–28 MHz；外部频率须符合实际晶振与器件要求，不把推荐列表当硬件枚举。P5.5 可配置 GPIO，P5.4 需用户确认 ISP 已关闭复位用途。初始化不启用业务中断、不启动普通计数器、不进行数据传输；串口所需波特率计数器会启动，明确选择的看门狗会立即启动。不要将这些模块作为运行中无状态的重配置函数。

ADC 电源开启后、首次转换前，建议业务预留 10 ms 稳定等待并按电路验证；`adc.h` 给出等待常量，初始化不触发转换。PCA 提供三路捕获、比较、翻转和 8 位 PWM（高电平计数 0–256）；普通 T0/1 暂仅提供 16 位自动重装，串口暂为 8N1。其它工作模式未伪装成已实现。IAP 初始化保持擦写禁用，只生成与 SYSCLK 对应的等待位常量；IAP15 程序区可写，存储区域由用户另行规划。

完整硬件核验、资料冲突处理与初始化范围见 [外设核验表](../../docs/STC15-PERIPHERAL-CONFIGURATION.md)。

`tools/New-StcStdintPack.py` 基于已验证普通 STC 0.1.6 生成不可变 0.1.7；五组系列头文件包含 `<stdint.h>`，保留全部型号、寄存器、监控镜像和许可证。配套图形包也包含这些声明。已有工程的 device 副本不自动替换。

构建插件使用 `tools/Build-StcConfigurator.ps1`，数据源与 SHA-256 记录在 `Assets/provenance.json`。扩展外设验证使用 `tools/StudioX.StcConfiguratorValidation <包> <插件> <runtime> <新输出> --peripherals`；不带末尾参数则验证旧 0.1.3 包兼容路径。验证工具还包括 `tools/StudioX.StcConfiguratorValidation`、`tools/StudioX.StcValidation` 和桌面 `--preview-mcu-configuration`；统一维护声明 `sources,editor`。不自动编译用户工程、不启动硬件会话，软件编译不代表实板电气或时序验收。

可见离线试用：`MCU StudioX.exe --show-mcu-configuration <插件归档> <准确工程目录> <独立用户目录>`。此入口只打开明确选择的插件与工程；用户点击生成才写入源码。
